# Module 2 - 데이터 분석 (NumPy / pandas)

## 📅 2026-09-29 | 데이터 분석 개요 · NumPy
> 코드: [`numpy_basics.py`](./numpy_basics.py)

### 개념

**1. 데이터 분석이란**
- 데이터를 수집·정제·해석하여 숨겨진 패턴과 유용한 정보(인사이트)를 발견하고, 이를 바탕으로 미래의 발생 가능한 상황을 예측하고 최적의 의사결정을 내리는 일련의 과정
- 분석 과정
  - 데이터 수집: 분석에 필요한 데이터 확보
  - 데이터 전처리(preprocessing): 데이터를 분석에 적합한 형태로 만들어서 신뢰도를 높이는 작업
  - 데이터 탐색: 그래프나 통계적인 방법을 이용해 데이터의 특징과 패턴 파악
  - 모델링: 데이터 간의 관계를 파악하고, 새로운 데이터에 대해 결과를 예측하거나 설명할 수 있는 규칙(Model)을 만드는 과정
  - 분석 모델 평가

**2. NumPy(넘파이)**
- 정의: 수학적 계산을 위한 python 라이브러리
- 자료 구조: 다차원 배열(`ndarray`)
- 주요 특징
  - 대량의 숫자 데이터를 매우 빠르게 처리할 수 있음
  - 사칙연산, 통계(평균·합계·표준편차), 선형대수 등 수학 함수를 풍부하게 제공
- 임포트: `import numpy as np` (앞으로 `np`라는 이름으로 호출)

**3. python list와 numpy 배열의 차이**
- 존재 목적
  - python list: 정수, 실수, 문자열, 리스트 등 다양한 자료형을 하나의 리스트에 혼합해서 저장
  - numpy 배열: 단일 종류의 숫자 데이터 중심, 대규모 수치 데이터를 묶어서 빠르게 처리
- 요소별(Element-wise) 수학 연산: python list는 불가능, numpy 배열은 가능(최대 장점)
- 덧셈 연산
  - python list: 덧셈이 아니라 리스트의 연결(extension) → `[1, 2, 3, 4, 5, 6]`
  - numpy 배열: 같은 자리끼리 더함 → `[5 7 9]`
- 곱셈 연산
  - python list: 덧셈 반복의 효과 → `[1, 2, 3, 1, 2, 3, 1, 2, 3]`
  - numpy 배열: 각 원소에 곱함 → `[3 6 9]`
- 평균값
  - python list: `sum(리스트) / len(리스트)`로 직접 계산
  - numpy 배열: `배열.mean()` 전용 함수 제공

**4. 배열 생성**
- 기본 문법: `변수 = np.array(data)`
- 1차원 배열: data에 python 리스트 전달 (`np.array([1, 2, 3])`)
- 2차원 배열: data에 대괄호가 중첩된 리스트 전달 (`np.array([[1, 2, 3], [4, 5, 6]])`)
- 주의사항: 성분 원소 리스트의 원소 개수가 반드시 동일해야 함

**5. 배열의 차원과 모양(shape)**
- 1D array: `[7, 2, 9, 10]` → shape `(4,)`
- 2D array: 2행 3열 → shape `(2, 3)`
- 3D array: shape `(4, 3, 2)`

**6. 인덱싱**
- python 리스트: `변수[인덱스][인덱스]` → 한 단계씩 벗겨 들어가는 방식
- numpy 배열: 두 가지 방식 모두 사용 가능
  - `배열[0][0]`: python 리스트와 동일한 방식
  - `배열[0, 0]`: 구조(행, 열)를 이용한 방식

**7. 슬라이싱**
- 1차원 배열: `배열[start 인덱스 : stop 인덱스]`
  - start 인덱스부터 stop 인덱스 바로 전까지 값 추출 (`start <= x < stop`)
- 2차원 배열: `배열[행 start : 행 stop, 열 start : 열 stop]`
  - `배열[:, 4:9]` → 행 인덱스 전체, 열 인덱스 4부터 8까지

### 왜 이렇게 코딩했는가
- 리스트와 배열을 같은 데이터(`[1, 2, 3]`, `[4, 5, 6]`)로 만들어 덧셈·곱셈·평균을 나란히 실행해본 이유
  → 결과만 보고도 "리스트의 `+`는 연결, 배열의 `+`는 요소별 덧셈"이라는 차이를 한눈에 비교하기 위함
- 리스트의 곱셈 결과를 `output4 = []` + `for`문 + `append()`로 직접 구현해본 이유
  → numpy의 `arr_data1 * 3` 한 줄이 이 반복문 전체를 대체한다는 걸 직접 확인하기 위함
- 배열 인덱싱을 `arr_data[0][0]`과 `arr_data[0, 0]` 두 방식으로 모두 작성한 이유
  → 리스트 방식도 그대로 동작하지만, 앞으로 행·열 개념이 중요해지므로 `[행, 열]` 방식에 익숙해지기 위함
- 리스트 인덱싱에서 `list_data[0][0]`을 바로 쓰지 않고 `output1 = list_data[0]` → `output2 = output1[0]`처럼 단계별로 쪼갠 이유
  → 대괄호 두 개가 각각 무엇을 가리키는지 중간 결과를 눈으로 확인하기 위함
- 슬라이싱 실습 데이터를 `[range(0, 10), range(10, 20), range(20, 30), range(30, 40)]`로 만든 이유
  → 숫자가 규칙적이어서 어느 행·열이 잘려 나왔는지 결과만 보고 검증할 수 있기 때문

### 이해 포인트
- 리스트끼리 더하면 덧셈이 아니라 연결(extension)이고, 배열끼리 더해야 요소별 덧셈이 된다는 걸 확인함
  → 자료형에 따라 같은 `+` 기호가 전혀 다르게 동작한다는 걸 이해함
- 슬라이싱의 stop 인덱스는 포함되지 않는다는 걸 `arr_data[:, 4:9]`가 4~8열까지만 추출되는 것으로 확인함
  → 리스트 슬라이싱에서 배운 규칙(`start <= x < stop`)이 배열에서도 동일하게 적용된다는 걸 이해함
- 2차원 배열을 만들 때 성분 리스트의 원소 개수가 다르면 정상적인 2차원 배열이 되지 않는다는 걸 확인함

## 📅 2026-09-29 | pandas
> 코드: [`pandas_basics.py`](./pandas_basics.py), 데이터: [`ad_performance.csv`](./ad_performance.csv)

### 개념

**1. pandas(판다스)**
- 정의: 행(Row)과 열(Column)로 구성된 표 형식의 데이터(Tabular Data)를 효율적으로 다루기 위해 설계된 라이브러리
- 주요 특징: CSV, Excel 파일, DB 테이블 등 다양한 형태의 정형 데이터를 파이썬에서 쉽고 유연하게 불러오고, 정제하며, 분석할 수 있도록 지원
- 임포트: `import pandas as pd` (앞으로 `pd`라는 이름으로 호출)

**2. 자료 구조(클래스)**
- `Series`: 행과 1개의 열(컬럼)로 구성 → 1D 데이터
- `DataFrame`: 행과 열로 구성, 각 열은 Series로 구성 → 2D 데이터
- `Index`: 행이나 열을 식별하는 데 사용되는 정수 또는 문자열

**3. DataFrame 생성**
- `read_csv()` 함수를 이용한 csv 파일 처리: `df = pd.read_csv(file_path)`

**4. DataFrame 분해**
- DataFrame = 행 인덱스 + 컬럼 인덱스 + 값
- 행 인덱스: `df.index` (예: `RangeIndex(start=0, stop=5000, step=1)`)
- 컬럼 인덱스: `df.columns`
- 값: `df.values` → numpy 2차원 배열로 반환됨

**5. 인덱싱**
- 개념: 인덱스(index)를 이용하여 데이터프레임으로부터 특정한 데이터를 추출하는 것
- 특정 컬럼 인덱싱: `df["컬럼명"]` → 결과: Series 자료 구조 생성
- fancy 인덱싱: 여러 개의 컬럼을 동시에 추출 → `df[["컬럼명1", "컬럼명2"]]` → 결과: DataFrame 생성
- 특정 행과 컬럼 인덱싱: `df.loc[행 인덱스, "컬럼명"]`

**6. 새로운 컬럼 추가(파생 변수 생성)**
- 기본 문법: `df["새 컬럼명"] = 계산식`
- 컬럼끼리 연산하면 같은 행끼리 자동으로 계산됨 (numpy의 요소별 연산과 동일한 원리)
- CTR(Click-Through Rate, 클릭률) = 클릭수 / 노출수 * 100
- ROAS(Return On Ad Spend, 광고비 대비 매출액) = 매출액 / 광고비 * 100

**7. value_counts() 함수**
- 개념: 컬럼(범주형 데이터)의 항목별 개수(빈도수)를 알려주는 함수
- 사용법: `df["컬럼명"].value_counts()`
- 개수가 많은 항목부터 자동으로 정렬되어 반환됨

**8. 실습 데이터(`ad_performance.csv`) 구조**
- 가상의 이커머스 회사가 2025년 1월 1일 ~ 6월 30일까지 집행한 디지털 광고의 일별 성과 데이터 (5,000행)
- `Date`: 광고 성과가 기록된 날짜
- `Channel`: 광고가 집행된 마케팅 채널 또는 유입 경로
- `Age_Group` / `Gender`: 해당 광고가 타겟으로 한 고객의 연령대 그룹 / 성별
- `Impressions`: 광고가 잠재 고객에게 노출된 총 횟수
- `Clicks`: 노출된 광고를 고객이 클릭한 총 횟수
- `Cost`: 해당 광고를 집행하는 데 지출된 총 비용(원)
- `Conversions`: 광고를 통해 발생한 실제 목표 달성 횟수 (제품 구매, 회원 가입 등)
- `Revenue`: 발생한 전환으로부터 얻은 총 매출액(원)

### 왜 이렇게 코딩했는가
- `df.index`, `df.columns`, `df.values`를 각각 따로 출력해본 이유
  → "DataFrame = 행 인덱스 + 컬럼 인덱스 + 값"이라는 구조를 개념으로만 외우지 않고, 세 부분으로 분해된 실제 결과를 확인하기 위함
- `df["Channel"]`(대괄호 1개)과 `df[["Channel", "Clicks", "Revenue"]]`(대괄호 2개)를 이어서 실행해본 이유
  → 같은 인덱싱인데 반환되는 자료 구조가 Series와 DataFrame으로 달라진다는 걸 직접 비교하기 위함
- 파생 변수를 CTR → ROAS 순으로 하나씩 추가하고 그때마다 결과를 출력한 이유
  → 컬럼이 9개 → 10개 → 11개로 늘어나는 걸 단계별로 확인해서, 계산식이 의도대로 새 컬럼에 들어갔는지 검증하기 위함

### 이해 포인트
- `df["A"]`는 Series를, `df[["A"]]`는 DataFrame을 반환한다는 차이를 확인함
  → fancy 인덱싱에서 대괄호가 두 겹인 이유는 "컬럼명들의 리스트"를 전달하는 것이기 때문이라는 걸 이해함
- `df.values`의 결과가 numpy 2차원 배열이라는 걸 확인함
  → pandas가 내부적으로 numpy 위에서 동작한다는 걸 알게 되었고, numpy를 먼저 배우는 이유를 이해함
- `df["Clicks"] / df["Impressions"]`처럼 컬럼끼리 나누면 5,000행이 각각 계산된다는 걸 확인함
  → 반복문 없이 한 줄로 전체 행이 계산되는 것이 numpy에서 배운 요소별 연산과 같은 원리라는 걸 이해함
- SQL에서 `GROUP BY` + `COUNT(*)`로 작성하던 항목별 개수 집계가 pandas에서는 `value_counts()` 한 줄로 처리된다는 걸 확인함

### 개념
- 배열 생성·연산·인덱싱, DataFrame 인덱싱·파생 변수·빈도수 분석을 종합적으로 활용하는 복습 문제
- 함수(function)와 메서드(method)의 구분
  - 함수: `모듈.함수(데이터)` 형태로 데이터를 괄호 안에 전달 (예: `np.average(arr)`, `len(리스트)`)
  - 메서드: `객체.기능()` 형태로 객체 뒤에 점(`.`)을 찍고 호출 (예: `arr.mean()`, `리스트.append(값)`)
  - 점을 찍고 붙이면 메서드, 괄호에 데이터를 넣으면 함수

### 왜 이렇게 코딩했는가
- 3번(평균값)에서 `np.average(arr)` 대신 `arr.mean()`을 쓴 이유
  → 문제가 "넘파이 전용 메서드"를 요구했기 때문. `np.average()`는 넘파이 모듈의 함수이고,
    `.mean()`은 배열 객체가 가진 메서드라서 문제 조건에 맞는 것은 `.mean()`
- 1번(데이터 불러오기)에서 `print(df.head())`가 아니라 `display(df)`를 쓴 이유
  → 문제가 "display 함수로 전체 데이터 확인"을 요구했기 때문. `head()`는 앞 5행만 반환하므로 조건에 맞지 않음

### 막혔던 부분 / 이해 포인트
- 정답지와 다른 코드를 썼을 때 무조건 틀렸다고 보지 않고 문제 문구를 다시 확인하는 과정을 거침
  → 1번은 정답지(`print(df.head())`)보다 문제 조건에 맞는 코드를 작성했음을 확인함
- 변수명을 `output`으로 반복 사용하면 노트북에서 앞 셀의 결과가 덮어써진다는 걸 인식하고,
  각 결과의 의미가 드러나는 이름(`sum_result`, `multi_result` 등)으로 수정함

## 📅 2026-09-30 | 데이터 전처리 (누락 · 중복 · 이상치)
> 코드: [`missing_data.py`](./missing_data.py), [`groupby_basics.py`](./groupby_basics.py), [`outlier_basics.py`](./outlier_basics.py)

### 개념

**1. 데이터 전처리(preprocessing)**
- 수집된 데이터를 분석에 적합한 형태로 만들어서 신뢰도를 높이는 작업
- 주요 처리 대상: 누락 데이터, 중복 데이터, 이상치

**2. 누락 데이터(missing value)**
- 값이 누락된 데이터를 표현하는 용어: NaN, null, na
  - NaN: pandas의 read 함수(`read_csv` 등)로 파일을 DataFrame이나 Series로 변환할 때 누락 데이터를 표현하는 수단
  - null, na: 함수의 이름으로 사용
- 누락 데이터 개수 확인: `df.isnull().sum()`
  - `isnull()`: 누락 여부를 확인해서 bool 형식으로 전달하는 함수 → 불리언 DataFrame 생성
  - `sum()`: 배열 값의 총합을 구하는 메서드 → True를 1로 계산하여 컬럼별 누락 개수 반환

**3. 누락 데이터 삭제**
- `df.dropna(ignore_index=True)`
  - 행에 누락 데이터(NaN)가 1개만 있어도 해당 행 전체를 제거
  - `ignore_index=True`: 행 인덱스 자동 재설정
- `df.dropna(subset=["컬럼1", "컬럼2"], ignore_index=True)`
  - 지정한 컬럼에 누락이 있는 행만 제거

**4. 누락 데이터 대체**
- `df.fillna("없음")` 또는 `df.fillna(0)`: 누락된 자리에 적당한 값 삽입

**5. 중복 데이터 그룹화 — groupby()**
- 중복된 데이터를 그룹별로 분할하고, 각 그룹별 통계량을 확인할 때 사용
- 기본 문법: `df.groupby(by="컬럼명")["집계할 컬럼"].집계함수()`
  - `by`: 중복 여부를 확인하여 그룹별로 묶을 컬럼 지정
  - 집계 함수: `sum()`, `mean()` 등
- SQL의 `GROUP BY`와 같은 기능

**6. 여러 집계를 한 번에 — groupby().agg()**
- 각 그룹별로 다양한 집계 함수를 동시에 적용
- 기본 문법
```python
  df.groupby(by="컬럼명").agg(
      새로운_컬럼명=("원본 컬럼명", "집계 함수"),
      ...
  )
```

**7. 이상치(outlier)**
- 수집된 데이터 중에서 아주 작은 값이나 매우 큰 값
- 사분위수: 순서대로 정렬된 데이터를 4구간으로 균등하게 분할할 때 기준이 되는 수
- 백분위수: 순서대로 정렬된 데이터를 균등하게 100등분하는 경우 기준이 되는 수
- IQR(Interquartile range): 75% 지점의 값과 25% 지점의 값 차이 (Q3 − Q1)
- 정상 범위 최소값 = Q1 − (1.5 × IQR)
- 정상 범위 최대값 = Q3 + (1.5 × IQR)
- 이상치: 정상 범위 최소값과 최대값을 벗어난 값

**8. 분위수 구하기**
- `df.quantile(q)` 또는 `df["컬럼명"].quantile(q)`
- `q`: 원하는 백분위수 (Q1은 `0.25`, Q3은 `0.75`)

**9. 이상치 제거 5단계**
1. 전체 수치형 컬럼에 대한 Q1, Q3, IQR 계산
2. 각 컬럼별 정상 범위 최소값/최대값 계산
3. DataFrame 전체에 논리 연산자 적용 → 이상치 여부를 담은 불리언 DataFrame 생성
4. `any(axis=1)` → 어떤 컬럼에서든 이상치가 하나라도 있는 행을 True로 식별
5. `~`(논리 부정) + 불리언 인덱싱 → 이상치가 없는 행만 추출

**10. 이상치 대체**
- 정상 범위를 벗어난 값을 삭제하지 않고 경계값으로 일괄 변경
- `df.clip(lower=min_val, upper=max_val, axis=1)`

**11. 비교 연산자와 논리 연산자**
- 비교 연산자: `>`, `<`, `>=`, `<=`, `==`, `!=` → 결과는 True/False
- 논리 연산자: 두 가지 이상의 조건을 동시에 처리
  - 논리곱(AND): 양쪽 모두 참일 때 참
  - 논리합(OR): 양쪽 중 한쪽만 참이라도 참
  - 논리부정(NOT): 참과 거짓을 뒤집음
- DataFrame에 적용할 때는 `&`, `|`, `~` 기호를 사용 (`and`, `or`, `not`이 아님)

### 왜 이렇게 코딩했는가
- 누락 개수를 구할 때 `isnull()`과 `sum()`을 한 줄로 합치기 전에 각각 따로 실행해본 이유
  → `isnull()`의 결과가 True/False로 채워진 DataFrame이라는 걸 눈으로 확인해야,
    `sum()`이 왜 컬럼별 개수를 세어주는지(True=1) 이해할 수 있기 때문
- `dropna()`와 `dropna(subset=[...])`를 순서대로 둘 다 실행해본 이유
  → 전체 삭제는 401,682행 중 35,827행만 남아 91%가 사라졌고,
    특정 컬럼만 지정하니 401,081행이 유지됨. 두 결과를 비교해야 `subset`의 필요성이 체감되기 때문
- 이상치 제거를 한 줄로 합치지 않고 5단계로 나눠서 각 단계마다 출력한 이유
  → 불리언 DataFrame → `any(axis=1)` → `~` 부정 → `.values` → 불리언 인덱싱으로 이어지는 흐름에서
    각 단계의 결과 형태(DataFrame → Series → 넘파이 배열)가 어떻게 바뀌는지 확인하기 위함
- 데이터프레임마다 변수명을 `df_ns`, `df_ad`, `df_weather`로 구분한 이유
  → 노트북은 셀이 이어져 있어서 `df` 하나로 쓰면 위쪽 셀을 다시 실행했을 때
    아래쪽 분석이 다른 데이터로 계산되기 때문

### 이해 포인트
- `dropna()`가 91%를 삭제한 이유를 누락 개수 표에서 확인함
  → 세트 ISBN(339,811개), 권(333,415개)은 "여러 권짜리 시리즈"에만 존재하는 값이라 단행본은 비어 있는 게 정상임
  → 누락이라고 해서 전부 잘못된 데이터가 아니며, **분석에 필요한 컬럼이 무엇인지 먼저 정하고
    `subset`으로 범위를 좁혀야 한다**는 걸 이해함
- DataFrame에 조건을 걸 때 `and`, `or`, `not`이 아니라 `&`, `|`, `~`를 쓴다는 걸 확인함
  → 파이썬의 `and`/`or`는 값 하나를 판단하는 연산자이고, DataFrame은 수많은 행을 한꺼번에 비교해야 하므로
    각 행마다 따로 판단해주는 `&`, `|`, `~`를 사용함
- `any(axis=1)`의 `axis=1`이 "가로 방향(행 단위)으로 검사"를 뜻한다는 걸 결과로 확인함
  → 컬럼 4개 중 하나라도 True면 그 행이 True가 되어, 100,000행짜리 Series가 반환됨

## 📅 2026-10-01 | 데이터 탐색 (요약 통계량 · 상관 분석)
> 코드: [`data_exploration.py`](./data_exploration.py), [`exploration_practice.py`](./exploration_practice.py)

### 개념

**1. 데이터 탐색**
- 통계적인 방법으로 데이터의 특성을 파악하는 단계

**2. 요약(기술) 통계량 — `df.describe()`**
- 데이터 분포의 특징을 나타내는 통계량
- 데이터 분석 과정에서 데이터의 전체적인 특징과 분포를 빠르게 파악하기 위해 사용
- 수치형 컬럼에 대해 8가지 통계량을 반환
  - `count`: 데이터 개수 (NaN 값 제외)
  - `mean`: 평균값
  - `std`: 표준편차 (데이터가 퍼져있는 정도)
  - `min`: 최솟값
  - `25%`: 1사분위수 (하위 25% 지점의 값)
  - `50%`: 중앙값 (median, 2사분위수)
  - `75%`: 3사분위수 (하위 75% 지점의 값)
  - `max`: 최댓값

**3. 통계량을 구하는 두 가지 방법**
- 방법1: 요약 통계량 DataFrame을 인덱싱 → `df_stats.loc["통계량", "컬럼명"]`
- 방법2: 특정 컬럼에 전용 함수 적용 → `df["컬럼명"].함수()`

| 통계량 | 요약 통계량 인덱싱 | 전용 함수 |
|---|---|---|
| 평균값 | `df_stats.loc["mean", "col"]` | `df["col"].mean()` |
| 최솟값 | `df_stats.loc["min", "col"]` | `df["col"].min()` |
| 최댓값 | `df_stats.loc["max", "col"]` | `df["col"].max()` |
| 중앙값 | `df_stats.loc["50%", "col"]` | `df["col"].median()` 또는 `df["col"].quantile(q=0.5)` |
| 표준편차 | `df_stats.loc["std", "col"]` | `df["col"].std()` |
| 데이터 수 | `df_stats.loc["count", "col"]` | `df["col"].count()` 또는 `len(df["col"])` |

**4. 표준편차(standard deviation)**
- 데이터들이 평균값에서 평균적으로 얼마나 떨어져 있는가를 나타내는 지표
- 데이터의 '일관성' 또는 변동성을 보여줌
- 표준편차가 작다: 데이터들이 평균값 주변에 모여 있음 (성과가 꾸준하고 예측 가능)
- 표준편차가 크다: 데이터들이 평균값에서 멀리 흩어져 있음 (성과가 들쭉날쭉하고 예측하기 힘듦)

**5. 상관관계 분석(Correlation Analysis)**
- 두 변수 사이에 연관성의 존재 여부와 연관성의 강도를 측정하여 분석하는 방법
- 상관관계의 종류
  - 양(+)의 상관관계: 한 변수의 값이 증가할 때 다른 변수의 값도 증가
  - 음(−)의 상관관계: 한 변수의 값이 증가할 때 다른 변수의 값은 감소
  - 상관관계가 없음: 한 변수의 변화와 무관하게 다른 변수의 값이 변화
- 상관계수(피어슨 상관계수): 두 변수 간 선형 관계의 정도를 수량화, +1 ~ −1 범위
  - ±1에 가까울수록 강한 상관, 0에 가까울수록 무관계

**6. 상관 행렬 구현**
- `df.corr(numeric_only=True)`: 변수들 간의 상관 계수를 표현한 DataFrame 생성
- 특정 두 컬럼의 상관계수
  - 방법1: 상관 행렬 인덱싱 → `df_corr.loc["컬럼1", "컬럼2"]`
  - 방법2: 팬시 인덱싱 후 상관 분석 → `df[["컬럼1", "컬럼2"]].corr()`

### 왜 이렇게 코딩했는가
- 모든 통계량을 두 가지 방법으로 각각 구해본 이유
  → 요약 통계량에서 꺼내는 방식과 전용 함수를 쓰는 방식 중 어느 쪽이 편한지 비교하고,
    같은 값이 나오는지 서로 검산하기 위함
- 중앙값만 세 가지 방법(`loc["50%"]`, `quantile(q=0.5)`, `median()`)으로 구해본 이유
  → 중앙값은 "50% 지점의 분위수"이기도 해서, 분위수 함수와 중앙값 함수가 같은 결과를 내는지 확인하기 위함
- 출력할 때 `{값:.1f}`로 소수점 자리를 지정하거나 `int()`로 변환한 이유
  → 요약 통계량 DataFrame의 값은 모두 실수형이라 `100440.0`처럼 출력되는데,
    원본이 정수인 컬럼은 정수로 보여주는 것이 읽기 좋기 때문
- 데이터프레임 변수명을 `df_ad`, `df_weather`, `df_tips`로 구분한 이유
  → 노트북은 셀이 이어져 있어서 `df` 하나로 쓰면 앞 셀을 다시 실행했을 때 다른 데이터로 분석이 진행되기 때문

### 막혔던 부분 / 이해 포인트
- 상관 행렬을 구할 때 원본이 아니라 요약 통계량(`df_stats`)에 `corr()`을 적용하는 실수를 함
  → 온도와 습도의 상관계수가 `0.9999`로 나왔는데, 바로 아래 방법2에서는 `-0.4618`이 나와
    두 값의 부호까지 달랐음에도 넘어갈 뻔했음
  → 원인: `describe()`의 결과는 min → 25% → 50% → 75% → max 순으로 값이 커지는 8행짜리 표라서,
    어느 컬럼이든 같은 방향으로 증가함. 그래서 상관계수가 전부 1.0에 가깝게 나옴
  → `df_stats`는 "요약된 8개 숫자"일 뿐 원본 데이터가 아니므로, 상관 분석은 반드시 원본 `df`에 적용해야 함
- 같은 값을 두 가지 방법으로 구하는 것은 **두 결과가 일치하는지 눈으로 확인할 때만** 검산이 된다는 걸 알게 됨
  → 두 번 구해놓고 결과를 비교하지 않으면 검산의 의미가 사라짐
- `len()`으로 Cost 컬럼의 행 수를 구하면서 `len(df["Revenue"])`라고 다른 컬럼을 지정한 실수를 함
  → 모든 컬럼의 행 수가 5,000으로 같아서 숫자는 맞게 나왔지만, 누락 데이터가 있는 데이터였다면
    컬럼마다 `count()` 값이 달라져 틀린 결과가 나왔을 것임
- 상관계수를 실제로 해석해봄
  - ad_performance: Cost-Revenue 상관계수 `0.0098` → 광고비와 매출 사이에 사실상 관계가 없음
  - weather: hum-atm `-0.50`, temp-hum `-0.46` → 습도가 높을수록 기압과 기온이 낮아지는 경향
  → 상관계수는 숫자 하나로 결론을 내리는 지표라서, 그 숫자가 무엇으로 계산됐는지 확인하는 것이 중요함

- 그래프를 그리기 전에 `time` 컬럼의 빈도수를 먼저 확인한 이유
  → `color="time"`으로 색상을 나눌 예정이었으므로, 몇 개의 선이 그려질지(Dinner 176건, Lunch 68건)
    미리 파악하기 위함
- `warnings.filterwarnings("ignore")`를 설정한 이유
  → 시각화 라이브러리 경고 메시지가 출력에 섞여 결과를 읽기 어려워지는 것을 막기 위함
- 그래프를 화면에 띄우는 것에 그치지 않고 `write_html()`로 저장한 이유
  → plotly 그래프는 HTML 파일로 저장하면 인터랙티브 기능(툴팁, 확대/축소)이 그대로 유지되어,
    나중에 보고서나 발표 자료에 그대로 사용할 수 있기 때문

### 막혔던 부분 / 이해 포인트
- 직선 그래프에서 정렬이 필수라는 것을 이해함
  → 산점도는 점을 따로 찍으므로 순서가 상관없지만, 직선 그래프는 "앞 점과 뒤 점을 잇는" 방식이라
    데이터 순서가 곧 선의 모양이 됨
- `color` 파라미터는 단순히 색을 칠하는 옵션이 아니라, **그 컬럼의 항목 수만큼 선을 나눠 그리는** 기능임을 확인함
  → `color="time"`을 주니 Lunch 선과 Dinner 선이 따로 그려짐

## 📅 2026-10-02 | EDA 시각화 (막대 · 원 · 히스토그램 · 박스플롯 · 산점도 · 히트맵)
> 코드: [`eda_plotly.py`](./eda_plotly.py)

### 개념

**1. 막대 그래프**
- 개념: 범주형 컬럼에 대해 범주별 수치 데이터의 크기(총합, 평균 등)를 직사각형 막대로 표현하는 그래프
- 구현 방법
  - 수직 막대: `px.bar(data_frame, x, y)`
  - 수평 막대: `px.bar(data_frame, x, y, orientation="h")`
- 하이퍼파라미터
  - `x`, `y`
    - 수직형: x가 범주형 컬럼, y가 수치형 컬럼
    - 수평형: x가 수치형 컬럼, y가 범주형 컬럼
  - `orientation`: `"v"`(수직, 기본값), `"h"`(수평)
  - `category_orders`: 범주의 표시 순서를 직접 지정 (예: `{"day": ["Thur", "Fri", "Sat", "Sun"]}`)
  - `color`: 범주별 색상 구분

**2. 그래프용 데이터 만들기 — groupby 결과의 자료형 변환**
- `df.groupby(by="컬럼")["집계 컬럼"].mean()` → 결과는 **Series**
- plotly는 DataFrame을 받으므로 변환이 필요함
  - `Series.reset_index()`: 행 인덱스를 컬럼으로 바꾸고 번호 행 인덱스를 새로 추가 → **DataFrame** 생성
  - `df.rename(columns={"기존명": "새이름"})`: 컬럼 이름 변경

**3. 원 그래프**
- 개념: 범주형 컬럼에서 전체에 대한 각 범주의 비율을 시각적으로 나타내며, 부분과 전체의 관계를 파악하기 용이한 그래프
- 구현 방법: `px.pie(data_frame, names, values, hole)`
- 하이퍼파라미터
  - `names`: 범주형 컬럼 (원의 조각 이름)
  - `values`: 수치형 컬럼 (조각의 크기)
  - `hole`: 0~1 사이 값을 설정하여 도넛 모양으로 변경
- 비율 계산: `df["컬럼"].value_counts(normalize=True)` → 빈도수 대신 비율(합이 1) 반환, 컬럼명은 `proportion`

**4. 히스토그램(Histogram)**
- 개념: 수치형 데이터의 분포를 구간(bin)별로 나누어 구간별 누적 빈도를 직사각형 막대로 표현하는 그래프
- 구현 방법
  - 수직형: `px.histogram(data_frame, x, y=None, nbins, color)`
  - 수평형: `px.histogram(data_frame, x=None, y, color)`
- 하이퍼파라미터
  - `x`, `y`
    - 수직형: x가 수치형 컬럼, y=None (y축은 빈도수가 자동 계산됨)
    - 수평형: x=None, y가 수치형 컬럼
  - `nbins`: 빈(bin)의 개수 설정 (미지정 시 최적값 자동 계산)
  - `color`: 새로운 변수를 추가하여 색상으로 구분
  - `barmode`: `"overlay"`(겹쳐서 표시, `opacity`와 함께 사용) / `"group"`(나란히 분리해서 표시)
- `fig.update_traces(marker_line_color, marker_line_width)`: 모든 막대에 일괄적으로 경계선 지정

**5. 박스 플롯(Box plot)**
- 개념: 수치형 컬럼에 대해서 최소값(min), 1사분위수(Q1), 2사분위수(Q2, median), 3사분위수(Q3), 최대값(max)을 이용하여 데이터의 분포를 시각적으로 요약하고 이상치를 식별하는 데 유용한 그래프
- 구현 방법: `px.box(data_frame, x, y, color)`
- 하이퍼파라미터
  - 수직형: x가 범주형 컬럼, y가 수치형 컬럼
  - 수평형: x가 수치형 컬럼, y가 범주형 컬럼

**6. 산점도(Scatterplot)**
- 개념: 두 변수의 상관 관계를 직교 좌표계의 평면에 점으로 표현하는 그래프
- 구현 방법: `px.scatter(data_frame, x, y, color)`
- 하이퍼파라미터: `x`, `y`는 상관 관계를 분석할 두 수치형 컬럼

**7. heatmap**
- 개념: 변수들 간의 상관 계수 크기를 색상의 농도로 표현하여 변수 간의 관계를 한눈에 파악하는 그래프
- 구현 방법: `px.imshow(img, text_auto, color_continuous_scale)`
- 하이퍼파라미터
  - `img`: 상관 행렬(DataFrame) → `df.corr(numeric_only=True)`의 결과
  - `text_auto`: 상관계수 수치 형식을 표시 (예: `text_auto=".2f"`)
  - `color_continuous_scale`: 히트맵의 색상 테마 설정 (예: `"RdBu_r"`, `"Viridis"`)

**8. seaborn과 plotly 비교**
- seaborn 직선 그래프: `sns.lineplot(data, x, y, hue)` + `plt.show()`
- plotly의 `color` 매개변수가 seaborn에서는 `hue`에 해당함
- 같은 기능이라도 라이브러리마다 매개변수 이름이 다름

### 왜 이렇게 코딩했는가
- `groupby` 결과를 그대로 쓰지 않고 `reset_index()`로 DataFrame으로 변환한 이유
  → `groupby().mean()`의 결과는 Series라서 plotly의 `data_frame` 매개변수에 바로 넣을 수 없기 때문
- `rename()`으로 컬럼명을 `total_bill` → `avg_total_bill`로 바꾼 이유
  → 평균값이 담긴 컬럼인데 이름이 원본과 같으면 그래프 축 이름만 보고 무엇인지 알 수 없기 때문
- `category_orders`로 요일 순서를 직접 지정한 이유
  → 지정하지 않으면 알파벳순(Fri, Sat, Sun, Thur)으로 정렬되어 요일의 흐름이 깨지기 때문
- 히스토그램에서 `barmode="overlay"`와 `barmode="group"`을 모두 그려본 이유
  → 겹쳐서 보는 방식과 나눠서 보는 방식 중 어느 쪽이 그룹 간 비교에 유리한지 직접 확인하기 위함
- 같은 직선 그래프를 plotly와 seaborn으로 각각 그려본 이유
  → 두 라이브러리의 코드 구조와 매개변수 이름(`color` vs `hue`)이 어떻게 다른지 비교하기 위함

### 이해 포인트
- 히스토그램에서 `y`와 `color`의 역할을 구분하게 됨
  - `x`, `y`: **축에 올릴 값**을 지정하는 매개변수
  - `color`: 데이터를 **그룹으로 나눠 색을 다르게** 칠하는 매개변수
  → 히스토그램의 y축은 원래 빈도수가 자동으로 들어가는 자리이므로, 수직 히스토그램에서 `y`에 다른 컬럼을 지정하면
    빈도수 대신 그 값이 축에 올라가 의도와 다른 그래프가 됨
- 그래프 변수명을 `fig7` ~ `fig10`처럼 번호로만 짓다 보니, 수평 히스토그램을 작성할 때 수직 히스토그램의 변수명과 겹쳐
  앞서 만든 그래프 객체가 덮어써지는 상황이 생김
  → `.show()`로 바로 출력할 때는 문제가 없지만, 나중에 `write_html()`로 저장하려면 앞 그래프를 찾을 수 없게 됨
  → 번호보다 역할이 드러나는 이름(`fig_hist_v`, `fig_hist_h`)이 안전함
- 히트맵은 원본 데이터가 아니라 **상관 행렬(DataFrame)**을 입력으로 받는다는 걸 확인함
  → `px.imshow(img=df.corr(numeric_only=True))` 형태로, 상관 분석을 먼저 실행한 결과를 넘겨야 함
- tips 데이터의 상관 분석 결과를 해석해봄
  - `total_bill`-`tip`: `0.68` → 중간 이상의 양의 상관. 요금이 많을수록 팁도 많아지는 경향이 뚜렷함
  - `total_bill`-`size`: `0.60` → 일행이 많을수록 요금도 많아짐
  - `tip`-`size`: `0.49` → 일행 수와 팁은 요금만큼 강하지는 않음
  → 앞서 ad_performance 데이터는 상관계수가 전부 0 근처였는데, tips는 실제 데이터라 의미 있는 관계가 나타남
