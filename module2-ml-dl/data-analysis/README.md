# Module 2 - 데이터 분석 (NumPy / pandas)

## 📅 2026-09-29 | 데이터 분석 개요 · NumPy
> 코드: [`numpy_basics.py`](./numpy_basics.py)

### 개념

**1. 데이터 분석이란**
- 데이터를 수집·정제·해석하여 숨겨진 패턴과 유용한 정보(인사이트)를 발견하고, 이를 바탕으로 미래의 발생 가능한 상황을 예측하고 최적의 의사결정을 내리는 일련의 과정
- 분석 과정
  - 데이터 수집: 분석에 필요한 데이터 확보
  - 데이터 전처리(preprocessing): 데이터를 분석에 적합한 형태로 만들어서 신뢰도를 높이는 작업
  - 데이터 탐색: 그래프나 통계적인 방법을 이용해 데이터의 특징과 패턴 파악
  - 모델링: 데이터 간의 관계를 파악하고, 새로운 데이터에 대해 결과를 예측하거나 설명할 수 있는 규칙(Model)을 만드는 과정
  - 분석 모델 평가

**2. NumPy(넘파이)**
- 정의: 수학적 계산을 위한 python 라이브러리
- 자료 구조: 다차원 배열(`ndarray`)
- 주요 특징
  - 대량의 숫자 데이터를 매우 빠르게 처리할 수 있음
  - 사칙연산, 통계(평균·합계·표준편차), 선형대수 등 수학 함수를 풍부하게 제공
- 임포트: `import numpy as np` (앞으로 `np`라는 이름으로 호출)

**3. python list와 numpy 배열의 차이**
- 존재 목적
  - python list: 정수, 실수, 문자열, 리스트 등 다양한 자료형을 하나의 리스트에 혼합해서 저장
  - numpy 배열: 단일 종류의 숫자 데이터 중심, 대규모 수치 데이터를 묶어서 빠르게 처리
- 요소별(Element-wise) 수학 연산: python list는 불가능, numpy 배열은 가능(최대 장점)
- 덧셈 연산
  - python list: 덧셈이 아니라 리스트의 연결(extension) → `[1, 2, 3, 4, 5, 6]`
  - numpy 배열: 같은 자리끼리 더함 → `[5 7 9]`
- 곱셈 연산
  - python list: 덧셈 반복의 효과 → `[1, 2, 3, 1, 2, 3, 1, 2, 3]`
  - numpy 배열: 각 원소에 곱함 → `[3 6 9]`
- 평균값
  - python list: `sum(리스트) / len(리스트)`로 직접 계산
  - numpy 배열: `배열.mean()` 전용 함수 제공

**4. 배열 생성**
- 기본 문법: `변수 = np.array(data)`
- 1차원 배열: data에 python 리스트 전달 (`np.array([1, 2, 3])`)
- 2차원 배열: data에 대괄호가 중첩된 리스트 전달 (`np.array([[1, 2, 3], [4, 5, 6]])`)
- 주의사항: 성분 원소 리스트의 원소 개수가 반드시 동일해야 함

**5. 배열의 차원과 모양(shape)**
- 1D array: `[7, 2, 9, 10]` → shape `(4,)`
- 2D array: 2행 3열 → shape `(2, 3)`
- 3D array: shape `(4, 3, 2)`

**6. 인덱싱**
- python 리스트: `변수[인덱스][인덱스]` → 한 단계씩 벗겨 들어가는 방식
- numpy 배열: 두 가지 방식 모두 사용 가능
  - `배열[0][0]`: python 리스트와 동일한 방식
  - `배열[0, 0]`: 구조(행, 열)를 이용한 방식

**7. 슬라이싱**
- 1차원 배열: `배열[start 인덱스 : stop 인덱스]`
  - start 인덱스부터 stop 인덱스 바로 전까지 값 추출 (`start <= x < stop`)
- 2차원 배열: `배열[행 start : 행 stop, 열 start : 열 stop]`
  - `배열[:, 4:9]` → 행 인덱스 전체, 열 인덱스 4부터 8까지

### 왜 이렇게 코딩했는가
- 리스트와 배열을 같은 데이터(`[1, 2, 3]`, `[4, 5, 6]`)로 만들어 덧셈·곱셈·평균을 나란히 실행해본 이유
  → 결과만 보고도 "리스트의 `+`는 연결, 배열의 `+`는 요소별 덧셈"이라는 차이를 한눈에 비교하기 위함
- 리스트의 곱셈 결과를 `output4 = []` + `for`문 + `append()`로 직접 구현해본 이유
  → numpy의 `arr_data1 * 3` 한 줄이 이 반복문 전체를 대체한다는 걸 직접 확인하기 위함
- 배열 인덱싱을 `arr_data[0][0]`과 `arr_data[0, 0]` 두 방식으로 모두 작성한 이유
  → 리스트 방식도 그대로 동작하지만, 앞으로 행·열 개념이 중요해지므로 `[행, 열]` 방식에 익숙해지기 위함
- 리스트 인덱싱에서 `list_data[0][0]`을 바로 쓰지 않고 `output1 = list_data[0]` → `output2 = output1[0]`처럼 단계별로 쪼갠 이유
  → 대괄호 두 개가 각각 무엇을 가리키는지 중간 결과를 눈으로 확인하기 위함
- 슬라이싱 실습 데이터를 `[range(0, 10), range(10, 20), range(20, 30), range(30, 40)]`로 만든 이유
  → 숫자가 규칙적이어서 어느 행·열이 잘려 나왔는지 결과만 보고 검증할 수 있기 때문

### 이해 포인트
- 리스트끼리 더하면 덧셈이 아니라 연결(extension)이고, 배열끼리 더해야 요소별 덧셈이 된다는 걸 확인함
  → 자료형에 따라 같은 `+` 기호가 전혀 다르게 동작한다는 걸 이해함
- 슬라이싱의 stop 인덱스는 포함되지 않는다는 걸 `arr_data[:, 4:9]`가 4~8열까지만 추출되는 것으로 확인함
  → 리스트 슬라이싱에서 배운 규칙(`start <= x < stop`)이 배열에서도 동일하게 적용된다는 걸 이해함
- 2차원 배열을 만들 때 성분 리스트의 원소 개수가 다르면 정상적인 2차원 배열이 되지 않는다는 걸 확인함

## 📅 2026-09-29 | pandas
> 코드: [`pandas_basics.py`](./pandas_basics.py), 데이터: [`ad_performance.csv`](./ad_performance.csv)

### 개념

**1. pandas(판다스)**
- 정의: 행(Row)과 열(Column)로 구성된 표 형식의 데이터(Tabular Data)를 효율적으로 다루기 위해 설계된 라이브러리
- 주요 특징: CSV, Excel 파일, DB 테이블 등 다양한 형태의 정형 데이터를 파이썬에서 쉽고 유연하게 불러오고, 정제하며, 분석할 수 있도록 지원
- 임포트: `import pandas as pd` (앞으로 `pd`라는 이름으로 호출)

**2. 자료 구조(클래스)**
- `Series`: 행과 1개의 열(컬럼)로 구성 → 1D 데이터
- `DataFrame`: 행과 열로 구성, 각 열은 Series로 구성 → 2D 데이터
- `Index`: 행이나 열을 식별하는 데 사용되는 정수 또는 문자열

**3. DataFrame 생성**
- `read_csv()` 함수를 이용한 csv 파일 처리: `df = pd.read_csv(file_path)`

**4. DataFrame 분해**
- DataFrame = 행 인덱스 + 컬럼 인덱스 + 값
- 행 인덱스: `df.index` (예: `RangeIndex(start=0, stop=5000, step=1)`)
- 컬럼 인덱스: `df.columns`
- 값: `df.values` → numpy 2차원 배열로 반환됨

**5. 인덱싱**
- 개념: 인덱스(index)를 이용하여 데이터프레임으로부터 특정한 데이터를 추출하는 것
- 특정 컬럼 인덱싱: `df["컬럼명"]` → 결과: Series 자료 구조 생성
- fancy 인덱싱: 여러 개의 컬럼을 동시에 추출 → `df[["컬럼명1", "컬럼명2"]]` → 결과: DataFrame 생성
- 특정 행과 컬럼 인덱싱: `df.loc[행 인덱스, "컬럼명"]`

**6. 새로운 컬럼 추가(파생 변수 생성)**
- 기본 문법: `df["새 컬럼명"] = 계산식`
- 컬럼끼리 연산하면 같은 행끼리 자동으로 계산됨 (numpy의 요소별 연산과 동일한 원리)
- CTR(Click-Through Rate, 클릭률) = 클릭수 / 노출수 * 100
- ROAS(Return On Ad Spend, 광고비 대비 매출액) = 매출액 / 광고비 * 100

**7. value_counts() 함수**
- 개념: 컬럼(범주형 데이터)의 항목별 개수(빈도수)를 알려주는 함수
- 사용법: `df["컬럼명"].value_counts()`
- 개수가 많은 항목부터 자동으로 정렬되어 반환됨

**8. 실습 데이터(`ad_performance.csv`) 구조**
- 가상의 이커머스 회사가 2025년 1월 1일 ~ 6월 30일까지 집행한 디지털 광고의 일별 성과 데이터 (5,000행)
- `Date`: 광고 성과가 기록된 날짜
- `Channel`: 광고가 집행된 마케팅 채널 또는 유입 경로
- `Age_Group` / `Gender`: 해당 광고가 타겟으로 한 고객의 연령대 그룹 / 성별
- `Impressions`: 광고가 잠재 고객에게 노출된 총 횟수
- `Clicks`: 노출된 광고를 고객이 클릭한 총 횟수
- `Cost`: 해당 광고를 집행하는 데 지출된 총 비용(원)
- `Conversions`: 광고를 통해 발생한 실제 목표 달성 횟수 (제품 구매, 회원 가입 등)
- `Revenue`: 발생한 전환으로부터 얻은 총 매출액(원)

### 왜 이렇게 코딩했는가
- `df.index`, `df.columns`, `df.values`를 각각 따로 출력해본 이유
  → "DataFrame = 행 인덱스 + 컬럼 인덱스 + 값"이라는 구조를 개념으로만 외우지 않고, 세 부분으로 분해된 실제 결과를 확인하기 위함
- `df["Channel"]`(대괄호 1개)과 `df[["Channel", "Clicks", "Revenue"]]`(대괄호 2개)를 이어서 실행해본 이유
  → 같은 인덱싱인데 반환되는 자료 구조가 Series와 DataFrame으로 달라진다는 걸 직접 비교하기 위함
- 파생 변수를 CTR → ROAS 순으로 하나씩 추가하고 그때마다 결과를 출력한 이유
  → 컬럼이 9개 → 10개 → 11개로 늘어나는 걸 단계별로 확인해서, 계산식이 의도대로 새 컬럼에 들어갔는지 검증하기 위함

### 이해 포인트
- `df["A"]`는 Series를, `df[["A"]]`는 DataFrame을 반환한다는 차이를 확인함
  → fancy 인덱싱에서 대괄호가 두 겹인 이유는 "컬럼명들의 리스트"를 전달하는 것이기 때문이라는 걸 이해함
- `df.values`의 결과가 numpy 2차원 배열이라는 걸 확인함
  → pandas가 내부적으로 numpy 위에서 동작한다는 걸 알게 되었고, numpy를 먼저 배우는 이유를 이해함
- `df["Clicks"] / df["Impressions"]`처럼 컬럼끼리 나누면 5,000행이 각각 계산된다는 걸 확인함
  → 반복문 없이 한 줄로 전체 행이 계산되는 것이 numpy에서 배운 요소별 연산과 같은 원리라는 걸 이해함
- SQL에서 `GROUP BY` + `COUNT(*)`로 작성하던 항목별 개수 집계가 pandas에서는 `value_counts()` 한 줄로 처리된다는 걸 확인함
