# Module 2 - 머신러닝 (기본 개념 / 데이터 전처리)

## 📅 2026-10-06 | 머신러닝 기본 개념

### 개념

**1. 인공지능 · 머신러닝 · 딥러닝의 관계**
- 인공지능: 인간의 지적 능력을 컴퓨터를 통해 구현하는 기술
- 머신러닝: 컴퓨터가 데이터를 통해 스스로 학습하여 예측이나 판단을 제공하는 기술 (인공지능에 포함)
- 딥러닝: 깊은 인공신경망 알고리즘을 활용하는 머신러닝 기술 (머신러닝에 포함)
- 포함 관계: **인공지능 ⊃ 머신러닝 ⊃ 딥러닝**

**2. 데이터 분석 과정에서 머신러닝의 위치**
- 데이터 수집 → 데이터 전처리 → 데이터 탐색 → **모델링** → 분석 모델 평가
- 모델링: 수집·정제된 데이터를 기반으로 수학적·통계적 방법을 사용하여 데이터 간의 관계를 파악하고,
  새로운 데이터에 대해 결과를 예측하거나 설명할 수 있는 규칙을 만드는 과정
- 앞선 교재(데이터 분석)에서 1~3단계를 다뤘고, 이번 교재는 4단계 모델링을 다룸

**3. 머신러닝의 종류 (기준: 학습 방식)**
- 지도 학습(Supervised Learning): 데이터에 대한 '정답'이 주어진 상태에서 모델을 학습시키는 방법
  - 분류(Classification): 어떤 '범주'에 속할지를 예측 (예: 품종 분류, 종양 양성/악성)
  - 회귀(Regression): 숫자 값을 예측 (예: 수량, 가격 예측)
- 비지도 학습(Unsupervised Learning): 데이터에 대한 '정답'이 없는 상태에서 모델을 학습시키는 방법
  - 클러스터링(Clustering): 데이터를 비슷한 특성끼리 묶음

**4. 머신러닝 학습 - 데이터의 분할**
- 전체 데이터를 학습용(Train)과 평가용(Test)으로 나눔
- 비율: Train 6~8 : Test 4~2
- 컬럼의 구분
  - **X**: Feature, 독립변수 (예측에 사용하는 입력 데이터)
  - **y**: Label, 종속변수 (맞춰야 하는 정답)

**5. 모델 평가**
- 미지의 데이터로 결과(범주 또는 값)를 예측하고 성능을 측정
- 평가 척도: accuracy(정확도), recall(재현율), precision(정밀도), f1 score, MSE / RMSE

**6. Feature Engineering(특성 공학)**
- 개념: 분석가의 전문 지식과 통찰력을 데이터에 직접 주입하여, 머신러닝 모델이 더 좋은 예측을 하도록 만드는 과정
- 종류
  - 파생 변수 생성(Feature Creation): 기존 변수들을 조합하여 새롭고 더 강력한 의미를 가진 변수를 만드는 것
    (예: 광고비와 매출 변수로 ROAS 컬럼 생성)
  - 범주형 변수 변환(Encoding): 글자로 된 데이터를 모델이 이해할 수 있는 숫자로 변환
  - 연속형 변수 변환(Scaling): 숫자 데이터의 분포나 범위를 조정하여 모델의 성능을 높이는 작업

### 이해 포인트
- X = Feature = 독립변수 = 입력, y = Label = 종속변수 = 정답
  → "X는 문제, y는 답"으로 정리함. X는 여러 컬럼이라 대문자, y는 한 컬럼이라 소문자로 쓰는 것이 관례
- 지난 교재에서 배운 '전처리'와 이번 교재의 '전처리'가 목적이 다르다는 걸 알게 됨
  - 지난 교재: 누락·중복·이상치 처리 → **데이터를 신뢰할 수 있게** 만드는 작업
  - 이번 교재: 인코딩·스케일링 → **모델이 처리할 수 있는 형태로** 바꾸는 작업
- 파생 변수 생성의 예시로 교재가 ROAS를 들었는데, 지난주 광고 데이터에서 직접 만들었던 컬럼임
  → 그때는 '분석을 위한 컬럼 추가'였지만 머신러닝에서는 '모델 성능을 높이는 재료'가 된다는 점이 달랐음

## 📅 2026-10-06 | 데이터 전처리 - 인코딩 · 스케일링 · 구간화
> 코드: [`data_preprocessing.py`](./data_preprocessing.py)
> 데이터: [`iris_dataset.csv`](./iris_dataset.csv), [`ad_performance.csv`](./ad_performance.csv)

### 개념

**1. One-Hot Encoding**
- 개념: 범주형 컬럼의 각 값을 고유한 숫자 컬럼으로 만들어주는 방법
  - 범주형 컬럼의 문자열 고유값 n개 → 새로운 컬럼 n개 생성
  - 각 행마다 해당하는 컬럼에 1, 나머지 컬럼에 0을 할당
- 구현 방법
  - `pd.get_dummies(data=df, dtype=int)` → DataFrame 전체의 범주형 컬럼에 적용
  - `pd.get_dummies(data=df, columns=["col1", "col2"], dtype=int)` → 지정한 컬럼만 적용
- `dtype=int`를 지정하지 않으면 True/False로 생성됨

**2. Label Encoding**
- 개념: 각 컬럼의 범주형 문자열 데이터를 0부터 n-1까지의 연속적인 수치 데이터로 표현하는 것
- 구현 방법: `df.replace({"문자열1": 숫자1, "문자열2": 숫자2, ...})`

**3. Scaling**
- 개념: 특성(Feature)들의 값의 분포 특성(평균, 표준편차) 또는 범위를 [0, 1]로 동일하게 해주는 작업
- 필요성: 특성마다 다른 분포나 범위를 가지는 경우 머신러닝 모델이 제대로 학습되지 않을 가능성이 있음
- 종류

| 구분 | 변환 결과 | 공식 | 도구 |
|---|---|---|---|
| 표준화(Standardization) | 평균 0, 표준편차 1인 분포 | (x − μ) / σ | `StandardScaler` |
| 정규화(Normalization) | 범위 0 ~ 1 | (x − min) / (max − min) | `MinMaxScaler` |

- 구현 방법
  1. `from sklearn.preprocessing import MinMaxScaler` (또는 `StandardScaler`)
  2. 도구 생성: `scaler = MinMaxScaler()`
  3. 데이터 변환: `scaler.fit_transform(df)` → 넘파이 배열 반환
  4. 필요 시 `pd.DataFrame()`으로 다시 변환

**4. 머신러닝 알고리즘별 scaling 가이드**

| 알고리즘 분류 | 대표 모델 | 추천 전처리 | 핵심 이유 |
|---|---|---|---|
| 선형 & 규제 모델 | Linear/Logistic Regression, Ridge, Lasso | StandardScaler | L1/L2 규제 페널티 계산 시 필요 |
| SVM & 차원 축소 | SVM, PCA, LDA | StandardScaler | |
| 딥러닝(신경망) | MLP, CNN, RNN | StandardScaler 또는 (이상치 clip 후) MinMaxScaler | 스케일러 1개만 적용 |
| 거리 기반 모델 | K-Means | 이상치 clip 후 StandardScaler 또는 RobustScaler | K-Means는 이상치에 극도로 취약 |
| 트리 기반 모델 | Decision Tree, Random Forest, XGBoost, LightGBM | **스케일링 불필요(Skip)** | 스케일 변환이 성능에 전혀 영향 없음 |

**5. 구간화(Binning)**
- 개념: 연속형 수치 데이터를 특정 구간으로 나누어 범주형 데이터로 변환하는 작업
- 구현 방법: `pd.cut(x, bins, labels)`
  - `x`: data
  - `bins`: 구간의 경계값 리스트
  - `labels`: 각 구간에 붙일 범주의 라벨
- 주의: `bins`의 경계값 개수는 `labels` 개수보다 1개 많아야 함 (경계가 n+1개여야 구간이 n개 생김)

**6. query() 함수**
- 개념: 데이터프레임에서 특정 조건을 만족하는 행(row)만 추출(필터링)하는 함수
- 특징: 조건문을 문자열(string) 형태로 작성하기 때문에, 여러 조건을 조합할 때 코드가 복잡해지지 않고 직관적임
- 구현 방법: `df.query("조건문 문자열")`
- 비교 연산자: `>`, `<`, `>=`, `<=`, `==`, `!=`
- 논리 연산자: `&`(논리곱), `|`(논리합), `~`(논리부정)
- 조건문 안에서 문자열을 비교할 때는 바깥 따옴표와 다른 종류의 따옴표를 사용해야 함
  - 예: `df.query("Dept == 'IT'")`

### 왜 이렇게 코딩했는가
- 원-핫 인코딩 전에 `value_counts()`로 label 컬럼의 항목 개수를 먼저 확인한 이유
  → 고유값이 몇 개인지 알아야 인코딩 후 몇 개의 컬럼이 생길지 예상할 수 있기 때문 (3종 × 50개 → 컬럼 3개)
- 스케일링 실습 데이터를 나이(22~47)와 연봉(3000~8500)으로 만든 이유
  → 두 컬럼의 단위 차이가 100배 이상이라, 스케일링을 하지 않으면 모델이 연봉만 중요하게 볼 수 있다는 걸
    직접 확인하기 위함
- `fit_transform()`의 결과를 `pd.DataFrame()`으로 다시 변환한 이유
  → 반환값이 컬럼 이름 없는 넘파이 배열이라 어느 열이 나이이고 연봉인지 알 수 없기 때문.
    `index`와 `columns`를 지정해 원본과 비교할 수 있게 만듦
- 정규화와 표준화를 같은 데이터에 각각 적용해본 이유
  → 0~1 범위로 모이는 것과 0을 중심으로 음수·양수가 퍼지는 것의 차이를 결과로 비교하기 위함

### 이해 포인트
- 변수명을 `Standard_scaler`처럼 대문자로 시작하게 지었음
  → 파이썬에서 대문자로 시작하는 이름은 클래스에 쓰는 관례(`StandardScaler`, `MinMaxScaler`)이므로,
    변수는 소문자와 언더바(snake_case)로 짓는 것이 맞음
- `fit_transform()`의 반환값이 DataFrame이 아니라 **넘파이 배열**이라는 점
  → scikit-learn의 도구들은 pandas가 아니라 넘파이를 기본 입출력으로 사용함.
    지난 교재에서 `df.values`가 넘파이 배열이었던 것과 이어지는 내용
- 정규화 결과에서 최소값이 정확히 0, 최대값이 정확히 1이 되는 것을 확인함
  → 공식 (x − min) / (max − min)에 최소값을 넣으면 분자가 0, 최대값을 넣으면 분자와 분모가 같아지기 때문

## 📅 2026-10-07 | 선형 회귀 (LinearRegression) / 보스턴 집값 예측

> 코드: [`linear_regression.py`](./linear_regression.py)

### 개념

**1. 회귀(Regression)**
- 학습 데이터로 데이터의 특성과 상관 관계를 파악하고, 학습 데이터에 없는 미지의 데이터가 주어졌을 때 **연속적인 숫자 값**으로 예측하는 것
- 예: 공부 시간(x)과 시험 성적(y)의 관계를 알면 7시간 공부했을 때의 점수를 예측할 수 있음

**2. 선형 회귀(Linear Regression)**
- 입력과 출력의 관계를 **직선** 형태로 나타내고, 미지의 데이터도 `y = Wx + b` 값으로 예측하는 것
- `W`는 기울기(weight), `b`는 절편(bias)
- 데이터 사이를 지나는 직선은 무수히 많으므로, **데이터의 분포를 가장 잘 표현하는 직선 하나**를 찾는 과정이 곧 학습

**3. 다중 선형 회귀**
- 데이터의 특성(feature)을 여러 개 사용하는 선형 회귀
- `y = w₁x₁ + w₂x₂ + w₃x₃ + ... + wₚxₚ + b`
- 단순 선형 회귀(`y = wx + b`)에 비해 학습에 적용하는 특성이 많고 복잡함
- 보스턴 집값 데이터는 특성이 13개 → 기울기(`coef_`)도 13개, 절편(`intercept_`)은 1개

**4. 선형 회귀 모델의 성능 평가 방법**
- 오차(Error) 또는 손실(loss)이 작을수록 성능이 좋은 모델
- MAE(평균 절대값 오차): 예측 값과 실제 값 차이의 **절대 값**을 모두 더해 평균을 구함
- MSE(평균 제곱 오차): 예측 값과 실제 값 차이의 **제곱**을 모두 더해 평균을 구함
- RMSE(평균 제곱근 오차): MSE에 **루트**를 씌운 것 → 원래 데이터와 단위가 같아져 해석하기 쉬움

**5. sklearn을 이용한 머신러닝 기본 흐름**
- `train_test_split(X, y, test_size, random_state)` → 학습용 / 평가용 데이터 분리
- `StandardScaler()` → `fit_transform()`(학습용) / `transform()`(평가용)
- `LinearRegression()` → `fit(X_train, y_train)` 학습 → `predict(X_test)` 예측
- `root_mean_squared_error(y_test, pred_test)` → 평가

### 왜 이렇게 코딩했는가

- `drop(columns=["medv"])`로 X_data를 만든 이유
  → 정답 컬럼 하나만 제외하고 나머지 13개를 전부 특성으로 쓰기 위함 (컬럼을 일일이 나열하면 길고 빠뜨리기 쉬움)
- `random_state=0`을 지정한 이유
  → `train_test_split`은 데이터를 무작위로 섞어서 나누기 때문에, 값을 고정하지 않으면 실행할 때마다 결과가 달라짐. 같은 결과를 다시 만들어 내기 위함
- `X_train.index`와 `y_train.index`를 비교해 본 이유
  → X와 y가 **같은 순서로** 나뉘었는지 확인하기 위함. 두 인덱스가 다르면 문제와 정답이 어긋난 채로 학습하게 됨
- 학습용에는 `fit_transform()`, 평가용에는 `transform()`을 쓴 이유
  → 평가용 데이터는 "아직 보지 못한 데이터"여야 하는데, 평가용에 `fit`을 쓰면 평가용 데이터의 평균과 표준 편차를 미리 들여다보는 셈이 됨
- `coef_`를 `pd.Series`로 감싸 컬럼명과 묶은 이유
  → 숫자 13개만 출력하면 어떤 특성의 기울기인지 알 수 없어서, 컬럼명과 짝지어 영향력을 읽을 수 있게 하기 위함
- `root_mean_squared_error`를 별칭(`as rmse`) 없이 그대로 쓴 이유
  → 짧은 별칭을 붙이면 나중에 `rmse = rmse(...)`처럼 결과를 담을 때 함수가 숫자로 덮어써져서 그 다음 호출이 실패함
- 데이터프레임 변수명을 `df_house`로 지은 이유
  → 폴더 안의 다른 파일(`df_iris`, `df_sample` 등)과 같은 규칙으로 맞춰 어떤 데이터인지 바로 알 수 있게 하기 위함

### 이해 포인트

- **선형 회귀에 표준화가 성능을 위해 꼭 필요한 건 아니다**
  - 표준화를 하지 않고 그대로 학습시켜도 RMSE가 5.4573으로 **완전히 동일**함
  - `LinearRegression`은 규제(penalty)가 없어서 특성의 스케일을 바꿔도 예측 값이 수학적으로 같아지기 때문
  - 그럼에도 표준화를 하는 이유는 `coef_`끼리 **크기를 비교**할 수 있게 만들기 위함
    - 표준화 전: `crim` -0.1177, `zn` 0.044 → 단위(범죄율 vs 면적 비중)가 달라서 비교하는 의미가 없음
    - 표준화 후: `lstat` -3.590, `dis` -3.002, `rm` 2.610 → 전부 "표준편차 1만큼 변했을 때"로 단위가 통일되어 영향력 순위를 읽을 수 있음
  - 교재 19p의 "선형 & 규제 모델 → StandardScaler, L1/L2 규제 페널티 계산 시 필요"가 이 맥락. Ridge·Lasso를 배우면 그때는 성능 자체가 달라짐

- **`fit_transform`과 `transform`을 둘 다 `fit_transform`으로 쓰면 성능이 나빠진다**
  - 실제로 바꿔서 돌려보니 RMSE 5.4573 → 5.5316으로 나빠짐
  - 평가용 데이터의 평균과 표준 편차를 미리 사용하게 되어 "아직 보지 못한 데이터"라는 전제가 깨지기 때문

- **"RMSE가 최소인 직선"이라는 표현**
  - `LinearRegression`이 실제로 최소화하는 것은 **MSE**
  - 다만 RMSE는 MSE에 루트만 씌운 것이라 **최솟값이 되는 지점이 같아서** 결과적으로 같은 직선이 나옴

- **`coef_`의 부호를 해석하는 방법**
  - 값이 음수면 그 특성이 커질수록 집값이 내려간다는 뜻
  - `lstat`(급여가 낮은 직업 종사자 비율) -3.590, `dis`(고용 시설까지의 거리) -3.002 → 둘 다 클수록 집값이 내려감
  - `rm`(집의 평균 방 수) 2.610 → 방이 많을수록 집값이 올라감
  - `indus` -0.040 → 거의 영향을 주지 않는 특성

- **예측값에 비현실적인 숫자가 섞여 나온다**
  - 예측값 중 0.228, 4.75, 4.92가 있는데 실제 `y_test`의 최솟값은 5.6
  - 선형 회귀는 직선을 무한히 연장해서 예측하기 때문에 0에 가까운 값이나 음수도 그대로 출력함
  - 모델은 "집값은 0보다 커야 한다"는 상식을 알지 못한다는 점을 확인함

## 📅 2026-10-08 | 모델 정규화(L1 / L2) · 로지스틱 회귀 / 타이타닉 생존 예측

> 코드: [`logistic_regression.py`](./logistic_regression.py)

### 개념

**1. 모델 정규화(Regularization)**
- 모델이 과대적합되지 않도록 복잡한 모델을 단순하게 만드는 것
- 데이터의 특성(feature)에는 손대지 않고 복잡도를 줄이려면, **가중치(W)를 0으로 만들거나 0에 가까운 작은 숫자로** 만들면 됨
- 하이퍼파라미터 `α`로 규제의 강도를 조절함

**2. L1 규제 (Lasso 모델)**
- 모든 가중치 W를 **같은 크기**로 감소시킴 (`w1-k`, `w2-k`, ..., `wn-k`)
- 효과: 크기가 작은 가중치들이 0이 되어 **중요도가 낮은 특성을 제거**할 수 있음
- `from sklearn.linear_model import Lasso`

**3. L2 규제 (Ridge 모델)**
- 모든 가중치 W를 **같은 비율**로 감소시킴 (`w1` 0.9 → 0.45, `w2` 0.2 → 0.1)
- 효과: 크기가 큰 가중치일수록 더 크게 감소해서 전체 가중치를 0에 가깝게 만듦
- `from sklearn.linear_model import Ridge`

**4. 로지스틱 회귀(Logistic Regression)**
- 선형 회귀 모델을 이용한 분류 알고리즘 → **"이름은 회귀, 목적은 분류"**
- 선형 회귀의 결과값(양수/음수)으로 바로 분류하지 않고, **시그모이드 함수**를 거쳐 0과 1 사이의 확률로 변환함
- 양수/음수로만 판단하면 "A 클래스다"만 알 수 있지만, 시그모이드를 쓰면 "**A 클래스일 확률이 95%다**"를 알 수 있음
- 장점: 매우 빠른 학습 속도 / 단점: 직선 형태의 경계만 가능해서 비선형 데이터에 한계

**5. 시그모이드(Sigmoid) 함수**
- `σ(z) = 1 / (1 + e⁻ᶻ)`
- -∞ ~ +∞ 사이의 입력 값을 0에서 1 사이로 압축하는 S자형 곡선 함수
- 입력 -∞ → 확률 0 / 입력 0 → 확률 0.5 / 입력 +∞ → 확률 1
- **결정 경계**: 시그모이드 값이 0.5가 되는 지점
- A 클래스일 확률이 P면, B 클래스일 확률은 1-P

**6. 모델의 매개 변수와 속성 변수**
- `max_iter`: 학습(선형 회귀 직선의 기울기 조정) 횟수
- `coef_`: 최적의 선형 회귀 직선(`w1·x1 + w2·x2 + ... + b`)의 기울기

**7. 분류 모델의 평가**
- `accuracy_score(y_test, pred_test)` → 정확도
- `stratify=y_data`: 원본 정답의 비율을 학습용 / 평가용에 그대로 유지하며 분할

**8. `pd.concat()` 함수**
- 데이터프레임들을 병합함 (기본값 `axis=0` → 공통된 컬럼을 기준으로 y축 방향 병합)
- `ignore_index=True`: 원본 인덱스를 버리고 0부터 다시 부여

## 📅 2026-10-12 | SVM (SVC) / 결정 트리 · 붓꽃 품종 분류

> 코드: [`svm_classification.py`](./svm_classification.py)
> 코드: [`iris_eda.py`](./iris_eda.py)
> 코드: [`decision_tree.py`](./decision_tree.py)

### 개념

**1. SVM (Support Vector Machine)**
- 클래스 간의 **안전한 거리(마진, Margin)를 최대화**하여 모델의 성능을 높이는 분류 알고리즘
- 서포트 벡터(Support Vector): 결정 경계와 가장 가까운 위치의 데이터
- 마진(Margin): 결정 경계와 서포트 벡터 사이의 거리
- 목표: 데이터를 두 클래스로 분리하면서도 마진이 최대가 되는 결정 경계 탐색
- 장점: 소규모 데이터(수십~수백 개)에서도 일반화 능력이 탁월함 / 특성 수가 샘플 수보다 많아도 안정적
- 단점: 데이터가 커지면 학습 속도가 기하급수적으로 느려짐
- `SVC`(분류) / `SVR`(회귀)로 나뉨

**2. 결정 트리 (Decision Tree)**
- 특정 특성의 **임계값(Threshold)을 기준으로 데이터를 축에 수직인 경계로 반복 분할**하여, 영역 내의 불순도를 최소화하는 비선형 알고리즘
- "AI가 하는 스무고개" — IF-THEN 규칙을 반복 적용함
- 질문을 거듭할수록 데이터 그룹의 불순도가 낮아지며 한 가지 품종으로 나뉨

**3. 불순도 (Impurity)**
- 서로 다른 데이터가 섞여 있는 정도. 다양한 개체가 섞여 있을수록 높아짐
- 최악의 불순도: 한 그룹에 여러 클래스가 정확히 반반씩 섞여 어느 쪽인지 예측할 수 없는 상태
- 불순도 0(순도 100%): 한 영역에 한 클래스만 완벽하게 모여 있는 상태
- 불순도 함수: **지니 지수(Gini)** / **엔트로피 지수(Entropy)**
  - 지니 불순도: `criterion="gini"`가 기본값, 계산 속도가 빠름
  - 엔트로피: `criterion="entropy"`, 정보이론의 혼잡도 개념

**4. 트리의 구성 요소**
- 루트 노드(Root Node): 최상단 분할 노드
- 리프 노드(Leaf Node): 최종 클래스 또는 예측값이 결정되는 최하단 노드
- 노드 정보: Threshold(분할 조건), gini/entropy(불순도), samples(샘플 수), value(클래스별 샘플 수)
- depth: 트리의 깊이

**5. 클래스 확률 추정**
- 샘플이 어떤 리프 노드에 도달하면, 그 리프 노드에 있는 **학습용 데이터의 클래스 비율**로 확률을 추정함
- `P(Y=k|X) = N(L,k) / N(L)`
- `predict()`는 확률이 가장 높은 클래스를 출력

**6. CART 알고리즘 (Classification and Regression Trees)**
- Scikit-Learn이 결정 트리를 훈련할 때 쓰는 대표 알고리즘
- **이진 트리(Binary Tree)만 생성** — 리프를 제외한 모든 노드는 항상 2개로 분할됨
- 분할 기준: 하나의 피처 k와 임계값으로 가장 순수한 두 개의 서브셋으로 나눔
- 정지 기준: `max_depth`에 도달하거나, 더 이상 불순도를 줄일 수 있는 분할이 없을 때

**7. 결정 트리의 해석 가능성 (Explainability)**
- 모델의 예측 근거와 판단 과정을 시각적으로 확인할 수 있음
- "AI가 그냥 setosa라고 했어요"가 아니라 **"꽃잎의 너비가 0.8cm 이하라서 setosa입니다"** 라고 논리적으로 설명 가능
- `plot_tree(decision_tree, feature_names, class_names, filled=True)`로 시각화

- SVM에서 전처리 완료 데이터(`titanic_cleaned.csv`)를 불러와 쓴 이유
  → 지난주에 전처리 결과를 파일로 저장해둬서, 같은 데이터로 모델만 바꿔 비교할 수 있게 하기 위함
- SVM에는 표준화를 하고 결정 트리에는 하지 않은 이유
  → SVM은 마진(거리)을 계산하므로 값의 범위가 큰 특성이 거리를 독차지함. 반면 트리는 "값이 임계값보다 큰가"만 보기 때문에 단위가 바뀌어도 순서가 그대로라 분할이 달라지지 않음
- `replace()` 뒤에 `.astype(int)`를 붙인 이유
  → `replace()`로 숫자를 넣어도 컬럼의 자료형이 `object`로 남기 때문 (아래 참고)
- `DecisionTreeClassifier`에 `random_state=0`을 준 이유
  → 트리는 불순도가 같은 분할이 여러 개일 때 그중 하나를 무작위로 고르므로, 값을 고정하지 않으면 실행할 때마다 구조가 달라질 수 있음
- `plot_tree`에 `class_names`와 `filled=True`를 넣은 이유
  → 클래스 이름을 넣으면 `value=[38, 0, 0]` 대신 품종 이름이 표시되고, `filled=True`는 클래스별로 색을 칠해 어느 쪽으로 기울었는지 한눈에 보이게 하기 위함
- 그래프 변수명을 `fig_sepal_len_all` / `fig_sepal_len_label`처럼 지은 이유
  → `fig1`~`fig9`로 두면 어떤 그래프인지 알 수 없고, 나중에 특정 그래프만 수정할 때 찾기 어려움

### 막혔던 부분 / 이해 포인트

- **`replace()`로 숫자를 넣어도 자료형은 `object`로 남는다**
  - `df.replace({"setosa": "0", ...})`처럼 따옴표를 붙이면 `dtype`이 `str`이 되고, `predict()` 결과도 `['0' '1' '2']`처럼 문자열로 나옴
  - 따옴표 없이 `{"setosa": 0, ...}`로 넣어도 `dtype`은 `object`
  - 분류 모델은 라벨이 문자든 숫자든 학습이 되기 때문에 **에러가 나지 않아 넘어가기 쉬움**
  - 다만 문자열 라벨이면 `mean()`도 안 되고 `corr()`에서도 제외되므로, `.astype(int)`로 확실히 숫자로 바꿔두기로 함

- **SVM과 로지스틱 회귀의 정확도가 소수점까지 같았다**
  - 둘 다 0.8587786259541985
  - 우연인지 확인하려고 예측값을 직접 비교해보니 **262명 중 4명을 서로 다르게 예측**하고 있었음
  - 한 모델이 틀린 사람을 다른 모델이 맞히고, 그 반대도 있어서 점수가 상쇄된 것
  - → **"정확도가 같다"가 "같은 모델이다"를 뜻하지 않는다.** 서로 다른 샘플에서 강점이 있다는 뜻이고, 이것이 여러 모델을 합치는 앙상블의 출발점

- **트리 기반 모델에 스케일링이 필요 없는 이유를 확인함**
  - 표준화한 경우와 안 한 경우의 예측이 **100% 일치**함
  - 트리는 "petal width가 0.8 이하인가?"처럼 **값의 순서만** 따지는데, 표준화는 순서를 바꾸지 않기 때문
  - 교재 19p 표의 "트리 기반 모델 → 스케일링 불필요(Skip), 스케일 변환이 성능에 전혀 영향 없음"을 직접 확인함
  - 거리를 재는 SVM과 정반대라서, **모델이 무엇을 계산하는지 알면 전처리가 필요한지도 알 수 있음**

- **`random_state`가 없어도 결과가 흔들리지 않을 수 있다**
  - `random_state` 없이 15번 반복 학습했는데 정확도(0.9667), 깊이(4), 리프 수(8)가 모두 동일했음
  - iris는 데이터가 작고 품종이 뚜렷하게 갈려서 매번 같은 분할이 최선으로 나오기 때문
  - 하지만 불순도가 같은 분할이 여러 개 생기면 무작위로 고르므로, 데이터가 커지면 달라질 수 있음 → 재현을 위해 넣어두는 습관이 필요

- **학습용 정확도가 1.0이 나오면 과적합을 의심해야 한다**
  - `max_depth` 제한 없이 학습하면 학습용 정확도가 **1.0000**, 평가용은 0.9667
  - 트리는 제한을 두지 않으면 **모든 리프의 불순도가 0이 될 때까지 계속 분할**하기 때문에 학습 데이터를 통째로 외워버림
  - 다만 `max_depth=3`으로 줄이면 학습용 0.9667 / 평가용 0.9333으로 **평가용도 같이 떨어져서**, 제한이 항상 좋은 것은 아니라는 것도 확인함

## 📅 2026-10-13 | 결정 트리의 과대적합 / 앙상블 · 랜덤 포레스트

> 코드: [`decision_tree_practice.py`](./decision_tree_practice.py)
> 코드: [`random_forest.py`](./random_forest.py)

### 개념

**1. 단일 결정 트리의 장단점**
- 장점
  - 최고의 설명력: 판단 근거를 시각적으로 보여주는 '화이트박스' 모델
  - 비선형성: 복잡한 비선형 관계도 직관적으로 학습 가능
- 단점
  - **과대적합(Overfitting)**: 데이터의 아주 미세한 노이즈까지 학습하려는 성향이 강함. 트리가 깊어질수록 훈련 데이터는 100% 맞추지만 새 데이터가 들어오면 성능이 급격히 떨어짐
  - 성능 한계: 단일 모델로는 높은 정확도를 얻기 어려움

**2. 과대적합 방지를 위한 규제 매개변수**
- `max_depth`: 트리의 최대 깊이 제어 (가장 직관적인 규제 방법)
- `min_samples_split`: 노드를 분할하기 위한 최소 샘플 수
- `min_samples_leaf`: 리프 노드가 가져야 할 최소 샘플 수
- `max_leaf_nodes`: 생성될 수 있는 리프 노드의 최대 개수
- `max_features`: 각 노드 분할 시 고려할 최대 피처 수
- **`max_`로 시작하는 매개변수를 줄이거나, `min_`으로 시작하는 매개변수를 늘리면 규제가 강화됨**

**3. 트리 기반 회귀 (Decision Tree Regression)**
- 클래스 레이블 대신 **연속적인 숫자값을 예측**
- 각 리프 노드에 속한 학습용 데이터들의 **평균(Mean)**을 그 영역의 최종 예측값으로 사용
- 분할 기준: **MSE를 최소화**하는 피처와 임계값을 탐색 (분류는 지니/엔트로피)
- `DecisionTreeRegressor`

**4. 결정 트리의 불안정성 (Instability)**
- **축 수직 분할의 한계**: 트리는 공간을 '축에 수직'으로만 분할함. 정답 경계선이 완만한 대각선이라면 수많은 '계단 모양'으로 잘라야 하고, 이 매끄럽지 못한 경계면이 예측 오차를 만듦
- **높은 분산(High Variance)**: 훈련 데이터의 아주 미세한 변화(샘플 추가/삭제)에도 트리 전체 구조가 완전히 재구성될 수 있음
- 해결 방안: 여러 트리를 결합하는 **앙상블** 기법 활용

**5. 앙상블 학습 (Ensemble Learning)**
- 여러 개의 단일 결정 트리 모델을 연결하여 더 강력한 모델을 만드는 기법
- 종류: Bagging / Boosting / Stacking

**6. 앙상블의 결과 집계 방식**
- 분류 — 투표 기반(다수결)
  - **직접 투표(Hard Voting)**: 각 모델이 예측한 클래스 레이블의 다수결로 최종 클래스 결정
  - **소프트 투표(Soft Voting)**: 각 모델이 출력하는 클래스별 예측 확률의 평균을 구해 가장 높은 확률의 클래스 선택. 예측 확신도를 반영하므로 일반적으로 Hard Voting보다 우수함
- 회귀 — 평균 기반
  - 연속형 값은 다수결이 불가능하므로 각 모델의 예측값 **평균**을 최종 예측값으로 결정

**7. 베깅(Bagging)과 페이스팅(Pasting)**
- **베깅(Bagging, Bootstrap Aggregating)**: 학습용 데이터에서 **복원 추출**로 중복을 허용하여 서브 데이터를 생성하고, 각 서브 데이터로 모델을 개별 훈련한 후 결과를 집계
- **페이스팅(Pasting)**: 학습용 데이터에서 **비복원 추출**로 중복 없이 서브 데이터 생성

**8. 랜덤 패치와 랜덤 서브스페이스**
- 특성 무작위 추출(Feature Sampling): '행'뿐만 아니라 '특성(열)'까지 무작위로 추출해 모델 간 다채로움(Diversity) 확보
- **랜덤 패치**: 샘플과 특성을 모두 무작위 추출 (`bootstrap=True` & `max_features < 1.0`)
- **랜덤 서브스페이스**: 샘플은 전체를 쓰고 특성만 무작위 추출 (`bootstrap=False` & `max_features < 1.0`)
- 장점: 고차원 데이터에서 일부 강한 특성에 모델이 편향되는 현상을 예방

**9. 랜덤 포레스트 (Random Forest)**
- 결정 트리를 기본 모델(Base Estimator)로 사용하는 **랜덤 패치 기반의 대표적 베깅 앙상블**
- 트리의 무작위성: 노드를 분할할 때 전체 특성을 검토하지 않고, **무작위로 선택된 특성의 부분집합(√n_features) 중에서** 최선의 분할 특성을 선택
- `RandomForestClassifier` / `RandomForestRegressor`
- `n_estimators` 기본값은 100 (트리 100개)
- `feature_importances_`로 특성별 중요도 확인 가능

### 왜 이렇게 코딩했는가

- 회귀에서 `stratify`를 쓰지 않은 이유
  → `stratify`는 정답의 항목별 비율을 유지하는 옵션이라 분류에서만 쓸 수 있음. 집값처럼 연속된 숫자는 항목이 거의 모든 행마다 달라져서 적용할 수 없음
- `plot_tree`에 `max_depth=3`을 준 이유
  → 학습된 트리의 깊이가 당뇨병 37, 집값 18이라 전부 그리면 글자가 보이지 않고 출력에도 오래 걸림. 상위 3단계만 보면 어떤 특성으로 먼저 나누는지는 충분히 확인됨
- 학습용 성능도 함께 측정한 이유
  → 평가용 성능만 보면 과대적합인지 알 수 없음. 두 값을 나란히 봐야 모델이 데이터를 외운 것인지 일반화한 것인지 판단할 수 있음
- 랜덤 포레스트와 결정 트리에 **같은 `random_state`와 분할 비율**을 쓴 이유
  → 두 모델의 성능 차이가 알고리즘 때문인지 데이터 분할 때문인지 구분하려면 분할 조건이 같아야 함
- 변수명을 `dt_clf` / `dt_reg`, `rf_clf` / `rf_reg`로 나눈 이유
  → 한 파일에 분류와 회귀가 함께 있어서 `dt`, `rf`만으로는 구분되지 않음
- `feature_importances_`를 출력한 이유
  → 랜덤 포레스트는 트리를 100개 만들어 개별 트리를 그려볼 수 없으므로, 어떤 특성이 기여했는지는 중요도로 확인해야 함

  ```
    which is too few. The minimum number of groups for any class
    cannot be less than 2.
    Classes with too few members are: [5.6, 6.3, 7.4, 7.5, 8.1, ...]
  ```
  - 원인: `stratify`는 정답의 **항목별 비율**을 학습용과 평가용에 똑같이 유지하는 옵션인데, 비율을 맞추려면 각 항목이 최소 2개는 있어야 양쪽에 하나씩 나눠 넣을 수 있음
  - 집값(`medv`)은 506개 행에 고유값이 **229개**이고, 그중 **100개는 데이터에 단 한 번만 등장**함. 5.6이라는 값이 한 명뿐이면 학습용에 넣을지 평가용에 넣을지 비율을 맞출 방법이 없음
  - 반면 당뇨병(`Diabetes_binary`)은 고유값이 0과 1 **두 개뿐**이고 각각 35,346개씩 있어서 비율대로 나눌 수 있음
  - → **정답이 연속형 숫자면(회귀) 못 쓰고, 정해진 항목으로 나뉘면(분류) 쓸 수 있다**

- **그렇다면 분류에서 `stratify`는 실제로 얼마나 차이를 만들까**
  - 당뇨병 데이터(원본 비율 50:50)를 `random_state`만 바꿔가며 나눠봄
    - seed=0 → `stratify` 없음 0.5097 / 적용 0.5000
    - seed=1 → `stratify` 없음 0.4949 / 적용 0.5000
    - seed=2 → `stratify` 없음 0.4932 / 적용 0.5000
  - `stratify`를 쓰면 **항상 정확히 50:50**, 안 쓰면 매번 ±1%p씩 흔들림
  - 이 데이터는 원래 균형이 맞아서 차이가 작지만, 한쪽이 5%뿐인 불균형 데이터라면 운이 나쁠 때 **평가용에 그 클래스가 거의 안 들어갈 수도** 있음
  - 노트북에서 회귀 쪽은 `#stratify=y_data`로 주석 처리해 남겨뒀는데, 지우지 않고 남겨두니 **"여기선 왜 안 썼는지"가 코드에 그대로 보여서** 앞으로도 이렇게 하기로 함

## 📅 2026-10-14 | 모델 정규화(Lasso) / 부스팅·XGBoost / 스태킹

> 코드: [`regularization.py`](./regularization.py)
> 코드: [`boosting_stacking.py`](./boosting_stacking.py)
> 코드: [`diabetes_eda.py`](./diabetes_eda.py)

### 개념

**1. 부스팅(Boosting)의 핵심 메커니즘**
- **순차적 학습(Sequential Learning)**: 이전 모델의 오류를 다음 모델이 보완하는 체인 형태의 앙상블
- 첫 번째 트리는 평균값으로 예측하고, 실제값과의 차이인 **잔차(Residual)**를 다음 트리가 학습함
- 베깅(랜덤 포레스트)은 트리를 동시에 만들어 평균을 내지만, 부스팅은 앞 트리가 틀린 것을 뒤 트리가 고쳐나감

**2. 부스팅을 '조각상 다듬기'로 이해하기**
- 초기값: 대략적인 큰 덩어리를 잡음(첫 번째 트리 예측: 평균값으로 오차 계산)
- 1단계: 튀어나온 큰 오차 부분을 깎아냄(두 번째 트리 예측 × 학습률)
- 2단계: 아직 덜 깎이거나 잘못 깎인 미세한 오차를 조금 더 깎아냄
- 이를 수백 번 반복하여 점점 정밀한 조각(완성된 모델)을 만들어냄

**3. XGBoost (Extreme Gradient Boosting)**
- 별도 설치가 필요함: `pip install xgboost`
- `XGBClassifier`(분류) / `XGBRegressor`(회귀)
- sklearn과 사용법이 같아 `fit` → `predict` → 평가 흐름을 그대로 쓸 수 있음

**4. 스태킹 (Stacking / Stacked Generalization)**
- 학습용 데이터에 대한 개별 모델들의 **예측 결과를 새로운 특성(Feature)으로 만들어** 메타 모델을 학습시키는 앙상블 기법
- 학습 2단계 구조
  - 1단계(Base Models): 서로 다른 알고리즘으로 개별 모델 학습 및 예측 수행
  - 2단계(Meta Model): 1단계 모델들의 예측값을 입력 데이터(X)로 삼아 최종 메타 모델 훈련
  - 정리: [기반 모델들의 train] → [출력값 + 정답 결합] → [메타 모델의 train]
- 예측 2단계 구조: [기반 모델들의 predict] → [출력값 결합] → [메타 모델의 predict]
- `StackingClassifier` / `StackingRegressor`에 `estimators`와 `final_estimator`를 전달
- 메타 모델은 분류에 `LogisticRegression`, 회귀에 `LinearRegression`을 주로 사용

**5. 모델 선택 기준 (교재 114p)**
- 1단계: 비즈니스 제약 확인 — 설명 가능성이 필수인가? 추세 예측인가?
- 2단계: 후보 모델 일괄 실험 — 선형/로지스틱, SVM, 단일 트리, 랜덤포레스트, 부스팅, 스태킹
- 3단계: 정량 지표 평가 & 선택 — **분류: F1-score / 회귀: RMSE**

**6. 모델 정규화 복습 (교재 42~46p)**
- L1 규제(Lasso): 모든 가중치를 **같은 크기**로 감소 → 작은 가중치가 0이 되어 중요도 낮은 특성이 제거됨
- L2 규제(Ridge): 모든 가중치를 **같은 비율**로 감소 → 0에 가까워질 뿐 0이 되지는 않음
- 하이퍼파라미터 `alpha`로 규제의 강도를 조절

### 왜 이렇게 코딩했는가

- 규제 모델 앞에 표준화를 넣은 이유
  → 규제는 가중치의 크기에 벌점을 매기는데, 특성마다 단위가 다르면 벌점이 불공평하게 매겨짐. 지난주 "선형 회귀는 표준화해도 성능이 같다"가 여기서 뒤집힘
- `lasso.coef_`를 컬럼명과 묶어 0이 된 특성을 따로 출력한 이유
  → 숫자 배열만 보면 `-0.`이 몇 개인지만 알 수 있고, **어떤 특성이** 제거되었는지는 알 수 없음
- 분류와 회귀 모두에 같은 데이터·같은 `random_state`를 쓴 이유
  → 세 모델(RandomForest / XGBoost / Stacking)의 차이가 알고리즘 때문인지 데이터 분할 때문인지 구분하기 위함
- 스태킹의 메타 모델로 분류에는 `LogisticRegression`, 회귀에는 `LinearRegression`을 쓴 이유
  → 메타 모델은 1단계 예측값 3개를 입력으로 받는 단순한 문제를 풀기 때문에, 복잡한 모델보다 단순한 선형 모델이 적합함
- `LogisticRegression(max_iter=1000)`으로 반복 횟수를 늘린 이유
  → 기본값 100으로는 수렴하지 않아 경고가 발생할 수 있음
- EDA에서 `value_counts()` 결과에 `reset_index()`와 `replace({0.0: "0"})`를 적용한 이유
  → `value_counts()`는 Series를 반환해서 `px.bar`의 `data_frame`에 바로 넣을 수 없고, 0.0/1.0은 숫자라 x축이 연속형으로 그려짐. 문자열로 바꿔야 범주로 인식됨

### 막혔던 부분 / 이해 포인트

- **L1 규제가 실제로 특성 8개를 0으로 만들었다**
  - `lasso.coef_` 13개 중 8개가 정확히 0 → `crim`, `zn`, `indus`, `chas`, `nox`, `age`, `dis`, `rad`
  - 살아남은 5개: `rm` 2.529(방 개수), `lstat` -3.606, `ptratio` -1.701, `tax` -0.228, `b` 0.132
  - 지난주 선형 회귀에서 영향력 1·2위였던 `lstat`과 `rm`이 그대로 살아남음
  - 교재 43p의 "크기가 작은 가중치들을 0으로 만들어 중요도가 낮은 특성을 제거"가 숫자로 확인됨

- **그런데 규제를 걸었더니 성능이 오히려 나빠졌다**
  - 선형 회귀 RMSE 5.4573 → Lasso(기본 `alpha=1.0`) RMSE **5.9573**
  - `alpha`를 바꿔가며 돌려보니
    - `alpha=1.0` → 5.9573 (0이 된 특성 8개)
    - `alpha=0.5` → 5.9159 (5개)
    - `alpha=0.1` → 5.5833 (0개)
    - `alpha=0.01` → 5.4660 (0개, 선형 회귀와 거의 같음)
  - 학습용 성능까지 보면 이유가 드러남
    - 선형 회귀: 학습용 4.4318 / 평가용 5.4573 (차이 1.03)
    - Lasso: 학습용 5.0386 / 평가용 5.9573 (차이 0.92)
  - 규제가 과적합 차이는 줄였지만(1.03 → 0.92) **학습용 성능까지 함께 떨어뜨림**
  - → 보스턴 데이터는 506개에 특성 13개라 애초에 과적합이 심하지 않았고, 이런 경우 **규제는 이득이 아니라 손해**가 됨. 어제 결정 트리처럼 학습용 0.9952 / 평가용 0.6545인 상황이어야 규제가 효과를 봄

- **Ridge는 아무리 강하게 걸어도 계수가 0이 되지 않는다**
  - `Ridge(alpha=1)` → 0인 특성 0개 / `alpha=10` → 0개 / `alpha=100` → 0개
  - 같은 강도의 `Lasso(alpha=1.0)`은 8개를 0으로 만듦
  - L1은 **같은 크기**로 빼서 0에 도달하지만, L2는 **같은 비율**로 줄이기 때문에 반으로 줄이기를 반복해도 0이 되지 않음
  - → 특성을 **골라내고 싶으면 Lasso**, 전체를 **고르게 줄이고 싶으면 Ridge**

- **가장 복잡한 모델인 스태킹이 1등이 아니었다**
  - 집값 회귀(RMSE, 낮을수록 좋음): 랜덤 포레스트 **4.0720** < 스태킹 4.1951 < XGBoost 4.2298
  - 당뇨병 분류(정확도, 높을수록 좋음): XGBoost **0.7498** > 스태킹 0.7478 > 랜덤 포레스트 0.7402
  - 두 경우 모두 모델 3개를 모아 메타 모델까지 얹은 스태킹이 2등
  - 스태킹은 1단계 모델들이 **서로 다른 종류의 실수**를 할 때 이득을 보는데, 여기서는 세 모델이 모두 트리 기반이라 비슷하게 틀렸을 가능성이 큼
  - → **모델을 복잡하게 만든다고 항상 좋아지는 게 아니고, 실제로 돌려서 비교해봐야 안다**

- **데이터에 따라 1등 모델이 달랐다**
  - 집값(506개, 특성 13개)은 랜덤 포레스트가, 당뇨병(70,692개, 특성 21개)은 XGBoost가 1등
  - 교재 114p가 "후보 모델 **일괄 실험**"을 2단계로 넣어둔 이유를 알 것 같음. 어떤 모델이 좋은지는 데이터를 보기 전에 정할 수 없음
