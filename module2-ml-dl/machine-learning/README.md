# Module 2 - 머신러닝 (기본 개념 / 데이터 전처리)

## 📅 2026-10-06 | 머신러닝 기본 개념

### 개념

**1. 인공지능 · 머신러닝 · 딥러닝의 관계**
- 인공지능: 인간의 지적 능력을 컴퓨터를 통해 구현하는 기술
- 머신러닝: 컴퓨터가 데이터를 통해 스스로 학습하여 예측이나 판단을 제공하는 기술 (인공지능에 포함)
- 딥러닝: 깊은 인공신경망 알고리즘을 활용하는 머신러닝 기술 (머신러닝에 포함)
- 포함 관계: **인공지능 ⊃ 머신러닝 ⊃ 딥러닝**

**2. 데이터 분석 과정에서 머신러닝의 위치**
- 데이터 수집 → 데이터 전처리 → 데이터 탐색 → **모델링** → 분석 모델 평가
- 모델링: 수집·정제된 데이터를 기반으로 수학적·통계적 방법을 사용하여 데이터 간의 관계를 파악하고,
  새로운 데이터에 대해 결과를 예측하거나 설명할 수 있는 규칙을 만드는 과정
- 앞선 교재(데이터 분석)에서 1~3단계를 다뤘고, 이번 교재는 4단계 모델링을 다룸

**3. 머신러닝의 종류 (기준: 학습 방식)**
- 지도 학습(Supervised Learning): 데이터에 대한 '정답'이 주어진 상태에서 모델을 학습시키는 방법
  - 분류(Classification): 어떤 '범주'에 속할지를 예측 (예: 품종 분류, 종양 양성/악성)
  - 회귀(Regression): 숫자 값을 예측 (예: 수량, 가격 예측)
- 비지도 학습(Unsupervised Learning): 데이터에 대한 '정답'이 없는 상태에서 모델을 학습시키는 방법
  - 클러스터링(Clustering): 데이터를 비슷한 특성끼리 묶음

**4. 머신러닝 학습 - 데이터의 분할**
- 전체 데이터를 학습용(Train)과 평가용(Test)으로 나눔
- 비율: Train 6~8 : Test 4~2
- 컬럼의 구분
  - **X**: Feature, 독립변수 (예측에 사용하는 입력 데이터)
  - **y**: Label, 종속변수 (맞춰야 하는 정답)

**5. 모델 평가**
- 미지의 데이터로 결과(범주 또는 값)를 예측하고 성능을 측정
- 평가 척도: accuracy(정확도), recall(재현율), precision(정밀도), f1 score, MSE / RMSE

**6. Feature Engineering(특성 공학)**
- 개념: 분석가의 전문 지식과 통찰력을 데이터에 직접 주입하여, 머신러닝 모델이 더 좋은 예측을 하도록 만드는 과정
- 종류
  - 파생 변수 생성(Feature Creation): 기존 변수들을 조합하여 새롭고 더 강력한 의미를 가진 변수를 만드는 것
    (예: 광고비와 매출 변수로 ROAS 컬럼 생성)
  - 범주형 변수 변환(Encoding): 글자로 된 데이터를 모델이 이해할 수 있는 숫자로 변환
  - 연속형 변수 변환(Scaling): 숫자 데이터의 분포나 범위를 조정하여 모델의 성능을 높이는 작업

### 이해 포인트
- X = Feature = 독립변수 = 입력, y = Label = 종속변수 = 정답
  → "X는 문제, y는 답"으로 정리함. X는 여러 컬럼이라 대문자, y는 한 컬럼이라 소문자로 쓰는 것이 관례
- 지난 교재에서 배운 '전처리'와 이번 교재의 '전처리'가 목적이 다르다는 걸 알게 됨
  - 지난 교재: 누락·중복·이상치 처리 → **데이터를 신뢰할 수 있게** 만드는 작업
  - 이번 교재: 인코딩·스케일링 → **모델이 처리할 수 있는 형태로** 바꾸는 작업
- 파생 변수 생성의 예시로 교재가 ROAS를 들었는데, 지난주 광고 데이터에서 직접 만들었던 컬럼임
  → 그때는 '분석을 위한 컬럼 추가'였지만 머신러닝에서는 '모델 성능을 높이는 재료'가 된다는 점이 달랐음

## 📅 2026-10-06 | 데이터 전처리 - 인코딩 · 스케일링 · 구간화
> 코드: [`data_preprocessing.py`](./data_preprocessing.py)
> 데이터: [`iris_dataset.csv`](./iris_dataset.csv), [`ad_performance.csv`](./ad_performance.csv)

### 개념

**1. One-Hot Encoding**
- 개념: 범주형 컬럼의 각 값을 고유한 숫자 컬럼으로 만들어주는 방법
  - 범주형 컬럼의 문자열 고유값 n개 → 새로운 컬럼 n개 생성
  - 각 행마다 해당하는 컬럼에 1, 나머지 컬럼에 0을 할당
- 구현 방법
  - `pd.get_dummies(data=df, dtype=int)` → DataFrame 전체의 범주형 컬럼에 적용
  - `pd.get_dummies(data=df, columns=["col1", "col2"], dtype=int)` → 지정한 컬럼만 적용
- `dtype=int`를 지정하지 않으면 True/False로 생성됨

**2. Label Encoding**
- 개념: 각 컬럼의 범주형 문자열 데이터를 0부터 n-1까지의 연속적인 수치 데이터로 표현하는 것
- 구현 방법: `df.replace({"문자열1": 숫자1, "문자열2": 숫자2, ...})`

**3. Scaling**
- 개념: 특성(Feature)들의 값의 분포 특성(평균, 표준편차) 또는 범위를 [0, 1]로 동일하게 해주는 작업
- 필요성: 특성마다 다른 분포나 범위를 가지는 경우 머신러닝 모델이 제대로 학습되지 않을 가능성이 있음
- 종류

| 구분 | 변환 결과 | 공식 | 도구 |
|---|---|---|---|
| 표준화(Standardization) | 평균 0, 표준편차 1인 분포 | (x − μ) / σ | `StandardScaler` |
| 정규화(Normalization) | 범위 0 ~ 1 | (x − min) / (max − min) | `MinMaxScaler` |

- 구현 방법
  1. `from sklearn.preprocessing import MinMaxScaler` (또는 `StandardScaler`)
  2. 도구 생성: `scaler = MinMaxScaler()`
  3. 데이터 변환: `scaler.fit_transform(df)` → 넘파이 배열 반환
  4. 필요 시 `pd.DataFrame()`으로 다시 변환

**4. 머신러닝 알고리즘별 scaling 가이드**

| 알고리즘 분류 | 대표 모델 | 추천 전처리 | 핵심 이유 |
|---|---|---|---|
| 선형 & 규제 모델 | Linear/Logistic Regression, Ridge, Lasso | StandardScaler | L1/L2 규제 페널티 계산 시 필요 |
| SVM & 차원 축소 | SVM, PCA, LDA | StandardScaler | |
| 딥러닝(신경망) | MLP, CNN, RNN | StandardScaler 또는 (이상치 clip 후) MinMaxScaler | 스케일러 1개만 적용 |
| 거리 기반 모델 | K-Means | 이상치 clip 후 StandardScaler 또는 RobustScaler | K-Means는 이상치에 극도로 취약 |
| 트리 기반 모델 | Decision Tree, Random Forest, XGBoost, LightGBM | **스케일링 불필요(Skip)** | 스케일 변환이 성능에 전혀 영향 없음 |

**5. 구간화(Binning)**
- 개념: 연속형 수치 데이터를 특정 구간으로 나누어 범주형 데이터로 변환하는 작업
- 구현 방법: `pd.cut(x, bins, labels)`
  - `x`: data
  - `bins`: 구간의 경계값 리스트
  - `labels`: 각 구간에 붙일 범주의 라벨
- 주의: `bins`의 경계값 개수는 `labels` 개수보다 1개 많아야 함 (경계가 n+1개여야 구간이 n개 생김)

**6. query() 함수**
- 개념: 데이터프레임에서 특정 조건을 만족하는 행(row)만 추출(필터링)하는 함수
- 특징: 조건문을 문자열(string) 형태로 작성하기 때문에, 여러 조건을 조합할 때 코드가 복잡해지지 않고 직관적임
- 구현 방법: `df.query("조건문 문자열")`
- 비교 연산자: `>`, `<`, `>=`, `<=`, `==`, `!=`
- 논리 연산자: `&`(논리곱), `|`(논리합), `~`(논리부정)
- 조건문 안에서 문자열을 비교할 때는 바깥 따옴표와 다른 종류의 따옴표를 사용해야 함
  - 예: `df.query("Dept == 'IT'")`

### 왜 이렇게 코딩했는가
- 원-핫 인코딩 전에 `value_counts()`로 label 컬럼의 항목 개수를 먼저 확인한 이유
  → 고유값이 몇 개인지 알아야 인코딩 후 몇 개의 컬럼이 생길지 예상할 수 있기 때문 (3종 × 50개 → 컬럼 3개)
- 스케일링 실습 데이터를 나이(22~47)와 연봉(3000~8500)으로 만든 이유
  → 두 컬럼의 단위 차이가 100배 이상이라, 스케일링을 하지 않으면 모델이 연봉만 중요하게 볼 수 있다는 걸
    직접 확인하기 위함
- `fit_transform()`의 결과를 `pd.DataFrame()`으로 다시 변환한 이유
  → 반환값이 컬럼 이름 없는 넘파이 배열이라 어느 열이 나이이고 연봉인지 알 수 없기 때문.
    `index`와 `columns`를 지정해 원본과 비교할 수 있게 만듦
- 정규화와 표준화를 같은 데이터에 각각 적용해본 이유
  → 0~1 범위로 모이는 것과 0을 중심으로 음수·양수가 퍼지는 것의 차이를 결과로 비교하기 위함

### 이해 포인트
- 변수명을 `Standard_scaler`처럼 대문자로 시작하게 지었음
  → 파이썬에서 대문자로 시작하는 이름은 클래스에 쓰는 관례(`StandardScaler`, `MinMaxScaler`)이므로,
    변수는 소문자와 언더바(snake_case)로 짓는 것이 맞음
- `fit_transform()`의 반환값이 DataFrame이 아니라 **넘파이 배열**이라는 점
  → scikit-learn의 도구들은 pandas가 아니라 넘파이를 기본 입출력으로 사용함.
    지난 교재에서 `df.values`가 넘파이 배열이었던 것과 이어지는 내용
- 정규화 결과에서 최소값이 정확히 0, 최대값이 정확히 1이 되는 것을 확인함
  → 공식 (x − min) / (max − min)에 최소값을 넣으면 분자가 0, 최대값을 넣으면 분자와 분모가 같아지기 때문

## 📅 2026-10-07 | 선형 회귀 (LinearRegression) / 보스턴 집값 예측

> 코드: [`linear_regression.py`](./linear_regression.py)

### 개념

**1. 회귀(Regression)**
- 학습 데이터로 데이터의 특성과 상관 관계를 파악하고, 학습 데이터에 없는 미지의 데이터가 주어졌을 때 **연속적인 숫자 값**으로 예측하는 것
- 예: 공부 시간(x)과 시험 성적(y)의 관계를 알면 7시간 공부했을 때의 점수를 예측할 수 있음

**2. 선형 회귀(Linear Regression)**
- 입력과 출력의 관계를 **직선** 형태로 나타내고, 미지의 데이터도 `y = Wx + b` 값으로 예측하는 것
- `W`는 기울기(weight), `b`는 절편(bias)
- 데이터 사이를 지나는 직선은 무수히 많으므로, **데이터의 분포를 가장 잘 표현하는 직선 하나**를 찾는 과정이 곧 학습

**3. 다중 선형 회귀**
- 데이터의 특성(feature)을 여러 개 사용하는 선형 회귀
- `y = w₁x₁ + w₂x₂ + w₃x₃ + ... + wₚxₚ + b`
- 단순 선형 회귀(`y = wx + b`)에 비해 학습에 적용하는 특성이 많고 복잡함
- 보스턴 집값 데이터는 특성이 13개 → 기울기(`coef_`)도 13개, 절편(`intercept_`)은 1개

**4. 선형 회귀 모델의 성능 평가 방법**
- 오차(Error) 또는 손실(loss)이 작을수록 성능이 좋은 모델
- MAE(평균 절대값 오차): 예측 값과 실제 값 차이의 **절대 값**을 모두 더해 평균을 구함
- MSE(평균 제곱 오차): 예측 값과 실제 값 차이의 **제곱**을 모두 더해 평균을 구함
- RMSE(평균 제곱근 오차): MSE에 **루트**를 씌운 것 → 원래 데이터와 단위가 같아져 해석하기 쉬움

**5. sklearn을 이용한 머신러닝 기본 흐름**
- `train_test_split(X, y, test_size, random_state)` → 학습용 / 평가용 데이터 분리
- `StandardScaler()` → `fit_transform()`(학습용) / `transform()`(평가용)
- `LinearRegression()` → `fit(X_train, y_train)` 학습 → `predict(X_test)` 예측
- `root_mean_squared_error(y_test, pred_test)` → 평가

### 왜 이렇게 코딩했는가

- `drop(columns=["medv"])`로 X_data를 만든 이유
  → 정답 컬럼 하나만 제외하고 나머지 13개를 전부 특성으로 쓰기 위함 (컬럼을 일일이 나열하면 길고 빠뜨리기 쉬움)
- `random_state=0`을 지정한 이유
  → `train_test_split`은 데이터를 무작위로 섞어서 나누기 때문에, 값을 고정하지 않으면 실행할 때마다 결과가 달라짐. 같은 결과를 다시 만들어 내기 위함
- `X_train.index`와 `y_train.index`를 비교해 본 이유
  → X와 y가 **같은 순서로** 나뉘었는지 확인하기 위함. 두 인덱스가 다르면 문제와 정답이 어긋난 채로 학습하게 됨
- 학습용에는 `fit_transform()`, 평가용에는 `transform()`을 쓴 이유
  → 평가용 데이터는 "아직 보지 못한 데이터"여야 하는데, 평가용에 `fit`을 쓰면 평가용 데이터의 평균과 표준 편차를 미리 들여다보는 셈이 됨
- `coef_`를 `pd.Series`로 감싸 컬럼명과 묶은 이유
  → 숫자 13개만 출력하면 어떤 특성의 기울기인지 알 수 없어서, 컬럼명과 짝지어 영향력을 읽을 수 있게 하기 위함
- `root_mean_squared_error`를 별칭(`as rmse`) 없이 그대로 쓴 이유
  → 짧은 별칭을 붙이면 나중에 `rmse = rmse(...)`처럼 결과를 담을 때 함수가 숫자로 덮어써져서 그 다음 호출이 실패함
- 데이터프레임 변수명을 `df_house`로 지은 이유
  → 폴더 안의 다른 파일(`df_iris`, `df_sample` 등)과 같은 규칙으로 맞춰 어떤 데이터인지 바로 알 수 있게 하기 위함

### 이해 포인트

- **선형 회귀에 표준화가 성능을 위해 꼭 필요한 건 아니다**
  - 표준화를 하지 않고 그대로 학습시켜도 RMSE가 5.4573으로 **완전히 동일**함
  - `LinearRegression`은 규제(penalty)가 없어서 특성의 스케일을 바꿔도 예측 값이 수학적으로 같아지기 때문
  - 그럼에도 표준화를 하는 이유는 `coef_`끼리 **크기를 비교**할 수 있게 만들기 위함
    - 표준화 전: `crim` -0.1177, `zn` 0.044 → 단위(범죄율 vs 면적 비중)가 달라서 비교하는 의미가 없음
    - 표준화 후: `lstat` -3.590, `dis` -3.002, `rm` 2.610 → 전부 "표준편차 1만큼 변했을 때"로 단위가 통일되어 영향력 순위를 읽을 수 있음
  - 교재 19p의 "선형 & 규제 모델 → StandardScaler, L1/L2 규제 페널티 계산 시 필요"가 이 맥락. Ridge·Lasso를 배우면 그때는 성능 자체가 달라짐

- **`fit_transform`과 `transform`을 둘 다 `fit_transform`으로 쓰면 성능이 나빠진다**
  - 실제로 바꿔서 돌려보니 RMSE 5.4573 → 5.5316으로 나빠짐
  - 평가용 데이터의 평균과 표준 편차를 미리 사용하게 되어 "아직 보지 못한 데이터"라는 전제가 깨지기 때문

- **"RMSE가 최소인 직선"이라는 표현**
  - `LinearRegression`이 실제로 최소화하는 것은 **MSE**
  - 다만 RMSE는 MSE에 루트만 씌운 것이라 **최솟값이 되는 지점이 같아서** 결과적으로 같은 직선이 나옴

- **`coef_`의 부호를 해석하는 방법**
  - 값이 음수면 그 특성이 커질수록 집값이 내려간다는 뜻
  - `lstat`(급여가 낮은 직업 종사자 비율) -3.590, `dis`(고용 시설까지의 거리) -3.002 → 둘 다 클수록 집값이 내려감
  - `rm`(집의 평균 방 수) 2.610 → 방이 많을수록 집값이 올라감
  - `indus` -0.040 → 거의 영향을 주지 않는 특성

- **예측값에 비현실적인 숫자가 섞여 나온다**
  - 예측값 중 0.228, 4.75, 4.92가 있는데 실제 `y_test`의 최솟값은 5.6
  - 선형 회귀는 직선을 무한히 연장해서 예측하기 때문에 0에 가까운 값이나 음수도 그대로 출력함
  - 모델은 "집값은 0보다 커야 한다"는 상식을 알지 못한다는 점을 확인함

## 📅 2026-10-08 | 모델 정규화(L1 / L2) · 로지스틱 회귀 / 타이타닉 생존 예측

> 코드: [`logistic_regression.py`](./logistic_regression.py)

### 개념

**1. 모델 정규화(Regularization)**
- 모델이 과대적합되지 않도록 복잡한 모델을 단순하게 만드는 것
- 데이터의 특성(feature)에는 손대지 않고 복잡도를 줄이려면, **가중치(W)를 0으로 만들거나 0에 가까운 작은 숫자로** 만들면 됨
- 하이퍼파라미터 `α`로 규제의 강도를 조절함

**2. L1 규제 (Lasso 모델)**
- 모든 가중치 W를 **같은 크기**로 감소시킴 (`w1-k`, `w2-k`, ..., `wn-k`)
- 효과: 크기가 작은 가중치들이 0이 되어 **중요도가 낮은 특성을 제거**할 수 있음
- `from sklearn.linear_model import Lasso`

**3. L2 규제 (Ridge 모델)**
- 모든 가중치 W를 **같은 비율**로 감소시킴 (`w1` 0.9 → 0.45, `w2` 0.2 → 0.1)
- 효과: 크기가 큰 가중치일수록 더 크게 감소해서 전체 가중치를 0에 가깝게 만듦
- `from sklearn.linear_model import Ridge`

**4. 로지스틱 회귀(Logistic Regression)**
- 선형 회귀 모델을 이용한 분류 알고리즘 → **"이름은 회귀, 목적은 분류"**
- 선형 회귀의 결과값(양수/음수)으로 바로 분류하지 않고, **시그모이드 함수**를 거쳐 0과 1 사이의 확률로 변환함
- 양수/음수로만 판단하면 "A 클래스다"만 알 수 있지만, 시그모이드를 쓰면 "**A 클래스일 확률이 95%다**"를 알 수 있음
- 장점: 매우 빠른 학습 속도 / 단점: 직선 형태의 경계만 가능해서 비선형 데이터에 한계

**5. 시그모이드(Sigmoid) 함수**
- `σ(z) = 1 / (1 + e⁻ᶻ)`
- -∞ ~ +∞ 사이의 입력 값을 0에서 1 사이로 압축하는 S자형 곡선 함수
- 입력 -∞ → 확률 0 / 입력 0 → 확률 0.5 / 입력 +∞ → 확률 1
- **결정 경계**: 시그모이드 값이 0.5가 되는 지점
- A 클래스일 확률이 P면, B 클래스일 확률은 1-P

**6. 모델의 매개 변수와 속성 변수**
- `max_iter`: 학습(선형 회귀 직선의 기울기 조정) 횟수
- `coef_`: 최적의 선형 회귀 직선(`w1·x1 + w2·x2 + ... + b`)의 기울기

**7. 분류 모델의 평가**
- `accuracy_score(y_test, pred_test)` → 정확도
- `stratify=y_data`: 원본 정답의 비율을 학습용 / 평가용에 그대로 유지하며 분할

**8. `pd.concat()` 함수**
- 데이터프레임들을 병합함 (기본값 `axis=0` → 공통된 컬럼을 기준으로 y축 방향 병합)
- `ignore_index=True`: 원본 인덱스를 버리고 0부터 다시 부여

## 📅 2026-10-12 | SVM (SVC) / 결정 트리 · 붓꽃 품종 분류

> 코드: [`svm_classification.py`](./svm_classification.py)
> 코드: [`iris_eda.py`](./iris_eda.py)
> 코드: [`decision_tree.py`](./decision_tree.py)

### 개념

**1. SVM (Support Vector Machine)**
- 클래스 간의 **안전한 거리(마진, Margin)를 최대화**하여 모델의 성능을 높이는 분류 알고리즘
- 서포트 벡터(Support Vector): 결정 경계와 가장 가까운 위치의 데이터
- 마진(Margin): 결정 경계와 서포트 벡터 사이의 거리
- 목표: 데이터를 두 클래스로 분리하면서도 마진이 최대가 되는 결정 경계 탐색
- 장점: 소규모 데이터(수십~수백 개)에서도 일반화 능력이 탁월함 / 특성 수가 샘플 수보다 많아도 안정적
- 단점: 데이터가 커지면 학습 속도가 기하급수적으로 느려짐
- `SVC`(분류) / `SVR`(회귀)로 나뉨

**2. 결정 트리 (Decision Tree)**
- 특정 특성의 **임계값(Threshold)을 기준으로 데이터를 축에 수직인 경계로 반복 분할**하여, 영역 내의 불순도를 최소화하는 비선형 알고리즘
- "AI가 하는 스무고개" — IF-THEN 규칙을 반복 적용함
- 질문을 거듭할수록 데이터 그룹의 불순도가 낮아지며 한 가지 품종으로 나뉨

**3. 불순도 (Impurity)**
- 서로 다른 데이터가 섞여 있는 정도. 다양한 개체가 섞여 있을수록 높아짐
- 최악의 불순도: 한 그룹에 여러 클래스가 정확히 반반씩 섞여 어느 쪽인지 예측할 수 없는 상태
- 불순도 0(순도 100%): 한 영역에 한 클래스만 완벽하게 모여 있는 상태
- 불순도 함수: **지니 지수(Gini)** / **엔트로피 지수(Entropy)**
  - 지니 불순도: `criterion="gini"`가 기본값, 계산 속도가 빠름
  - 엔트로피: `criterion="entropy"`, 정보이론의 혼잡도 개념

**4. 트리의 구성 요소**
- 루트 노드(Root Node): 최상단 분할 노드
- 리프 노드(Leaf Node): 최종 클래스 또는 예측값이 결정되는 최하단 노드
- 노드 정보: Threshold(분할 조건), gini/entropy(불순도), samples(샘플 수), value(클래스별 샘플 수)
- depth: 트리의 깊이

**5. 클래스 확률 추정**
- 샘플이 어떤 리프 노드에 도달하면, 그 리프 노드에 있는 **학습용 데이터의 클래스 비율**로 확률을 추정함
- `P(Y=k|X) = N(L,k) / N(L)`
- `predict()`는 확률이 가장 높은 클래스를 출력

**6. CART 알고리즘 (Classification and Regression Trees)**
- Scikit-Learn이 결정 트리를 훈련할 때 쓰는 대표 알고리즘
- **이진 트리(Binary Tree)만 생성** — 리프를 제외한 모든 노드는 항상 2개로 분할됨
- 분할 기준: 하나의 피처 k와 임계값으로 가장 순수한 두 개의 서브셋으로 나눔
- 정지 기준: `max_depth`에 도달하거나, 더 이상 불순도를 줄일 수 있는 분할이 없을 때

**7. 결정 트리의 해석 가능성 (Explainability)**
- 모델의 예측 근거와 판단 과정을 시각적으로 확인할 수 있음
- "AI가 그냥 setosa라고 했어요"가 아니라 **"꽃잎의 너비가 0.8cm 이하라서 setosa입니다"** 라고 논리적으로 설명 가능
- `plot_tree(decision_tree, feature_names, class_names, filled=True)`로 시각화

- SVM에서 전처리 완료 데이터(`titanic_cleaned.csv`)를 불러와 쓴 이유
  → 지난주에 전처리 결과를 파일로 저장해둬서, 같은 데이터로 모델만 바꿔 비교할 수 있게 하기 위함
- SVM에는 표준화를 하고 결정 트리에는 하지 않은 이유
  → SVM은 마진(거리)을 계산하므로 값의 범위가 큰 특성이 거리를 독차지함. 반면 트리는 "값이 임계값보다 큰가"만 보기 때문에 단위가 바뀌어도 순서가 그대로라 분할이 달라지지 않음
- `replace()` 뒤에 `.astype(int)`를 붙인 이유
  → `replace()`로 숫자를 넣어도 컬럼의 자료형이 `object`로 남기 때문 (아래 참고)
- `DecisionTreeClassifier`에 `random_state=0`을 준 이유
  → 트리는 불순도가 같은 분할이 여러 개일 때 그중 하나를 무작위로 고르므로, 값을 고정하지 않으면 실행할 때마다 구조가 달라질 수 있음
- `plot_tree`에 `class_names`와 `filled=True`를 넣은 이유
  → 클래스 이름을 넣으면 `value=[38, 0, 0]` 대신 품종 이름이 표시되고, `filled=True`는 클래스별로 색을 칠해 어느 쪽으로 기울었는지 한눈에 보이게 하기 위함
- 그래프 변수명을 `fig_sepal_len_all` / `fig_sepal_len_label`처럼 지은 이유
  → `fig1`~`fig9`로 두면 어떤 그래프인지 알 수 없고, 나중에 특정 그래프만 수정할 때 찾기 어려움

### 막혔던 부분 / 이해 포인트

- **`replace()`로 숫자를 넣어도 자료형은 `object`로 남는다**
  - `df.replace({"setosa": "0", ...})`처럼 따옴표를 붙이면 `dtype`이 `str`이 되고, `predict()` 결과도 `['0' '1' '2']`처럼 문자열로 나옴
  - 따옴표 없이 `{"setosa": 0, ...}`로 넣어도 `dtype`은 `object`
  - 분류 모델은 라벨이 문자든 숫자든 학습이 되기 때문에 **에러가 나지 않아 넘어가기 쉬움**
  - 다만 문자열 라벨이면 `mean()`도 안 되고 `corr()`에서도 제외되므로, `.astype(int)`로 확실히 숫자로 바꿔두기로 함

- **SVM과 로지스틱 회귀의 정확도가 소수점까지 같았다**
  - 둘 다 0.8587786259541985
  - 우연인지 확인하려고 예측값을 직접 비교해보니 **262명 중 4명을 서로 다르게 예측**하고 있었음
  - 한 모델이 틀린 사람을 다른 모델이 맞히고, 그 반대도 있어서 점수가 상쇄된 것
  - → **"정확도가 같다"가 "같은 모델이다"를 뜻하지 않는다.** 서로 다른 샘플에서 강점이 있다는 뜻이고, 이것이 여러 모델을 합치는 앙상블의 출발점

- **트리 기반 모델에 스케일링이 필요 없는 이유를 확인함**
  - 표준화한 경우와 안 한 경우의 예측이 **100% 일치**함
  - 트리는 "petal width가 0.8 이하인가?"처럼 **값의 순서만** 따지는데, 표준화는 순서를 바꾸지 않기 때문
  - 교재 19p 표의 "트리 기반 모델 → 스케일링 불필요(Skip), 스케일 변환이 성능에 전혀 영향 없음"을 직접 확인함
  - 거리를 재는 SVM과 정반대라서, **모델이 무엇을 계산하는지 알면 전처리가 필요한지도 알 수 있음**

- **`random_state`가 없어도 결과가 흔들리지 않을 수 있다**
  - `random_state` 없이 15번 반복 학습했는데 정확도(0.9667), 깊이(4), 리프 수(8)가 모두 동일했음
  - iris는 데이터가 작고 품종이 뚜렷하게 갈려서 매번 같은 분할이 최선으로 나오기 때문
  - 하지만 불순도가 같은 분할이 여러 개 생기면 무작위로 고르므로, 데이터가 커지면 달라질 수 있음 → 재현을 위해 넣어두는 습관이 필요

- **학습용 정확도가 1.0이 나오면 과적합을 의심해야 한다**
  - `max_depth` 제한 없이 학습하면 학습용 정확도가 **1.0000**, 평가용은 0.9667
  - 트리는 제한을 두지 않으면 **모든 리프의 불순도가 0이 될 때까지 계속 분할**하기 때문에 학습 데이터를 통째로 외워버림
  - 다만 `max_depth=3`으로 줄이면 학습용 0.9667 / 평가용 0.9333으로 **평가용도 같이 떨어져서**, 제한이 항상 좋은 것은 아니라는 것도 확인함

## 📅 2026-10-13 | 결정 트리의 과대적합 / 앙상블 · 랜덤 포레스트

> 코드: [`decision_tree_practice.py`](./decision_tree_practice.py)
> 코드: [`random_forest.py`](./random_forest.py)

### 개념

**1. 단일 결정 트리의 장단점**
- 장점
  - 최고의 설명력: 판단 근거를 시각적으로 보여주는 '화이트박스' 모델
  - 비선형성: 복잡한 비선형 관계도 직관적으로 학습 가능
- 단점
  - **과대적합(Overfitting)**: 데이터의 아주 미세한 노이즈까지 학습하려는 성향이 강함. 트리가 깊어질수록 훈련 데이터는 100% 맞추지만 새 데이터가 들어오면 성능이 급격히 떨어짐
  - 성능 한계: 단일 모델로는 높은 정확도를 얻기 어려움

**2. 과대적합 방지를 위한 규제 매개변수**
- `max_depth`: 트리의 최대 깊이 제어 (가장 직관적인 규제 방법)
- `min_samples_split`: 노드를 분할하기 위한 최소 샘플 수
- `min_samples_leaf`: 리프 노드가 가져야 할 최소 샘플 수
- `max_leaf_nodes`: 생성될 수 있는 리프 노드의 최대 개수
- `max_features`: 각 노드 분할 시 고려할 최대 피처 수
- **`max_`로 시작하는 매개변수를 줄이거나, `min_`으로 시작하는 매개변수를 늘리면 규제가 강화됨**

**3. 트리 기반 회귀 (Decision Tree Regression)**
- 클래스 레이블 대신 **연속적인 숫자값을 예측**
- 각 리프 노드에 속한 학습용 데이터들의 **평균(Mean)**을 그 영역의 최종 예측값으로 사용
- 분할 기준: **MSE를 최소화**하는 피처와 임계값을 탐색 (분류는 지니/엔트로피)
- `DecisionTreeRegressor`

**4. 결정 트리의 불안정성 (Instability)**
- **축 수직 분할의 한계**: 트리는 공간을 '축에 수직'으로만 분할함. 정답 경계선이 완만한 대각선이라면 수많은 '계단 모양'으로 잘라야 하고, 이 매끄럽지 못한 경계면이 예측 오차를 만듦
- **높은 분산(High Variance)**: 훈련 데이터의 아주 미세한 변화(샘플 추가/삭제)에도 트리 전체 구조가 완전히 재구성될 수 있음
- 해결 방안: 여러 트리를 결합하는 **앙상블** 기법 활용

**5. 앙상블 학습 (Ensemble Learning)**
- 여러 개의 단일 결정 트리 모델을 연결하여 더 강력한 모델을 만드는 기법
- 종류: Bagging / Boosting / Stacking

**6. 앙상블의 결과 집계 방식**
- 분류 — 투표 기반(다수결)
  - **직접 투표(Hard Voting)**: 각 모델이 예측한 클래스 레이블의 다수결로 최종 클래스 결정
  - **소프트 투표(Soft Voting)**: 각 모델이 출력하는 클래스별 예측 확률의 평균을 구해 가장 높은 확률의 클래스 선택. 예측 확신도를 반영하므로 일반적으로 Hard Voting보다 우수함
- 회귀 — 평균 기반
  - 연속형 값은 다수결이 불가능하므로 각 모델의 예측값 **평균**을 최종 예측값으로 결정

**7. 베깅(Bagging)과 페이스팅(Pasting)**
- **베깅(Bagging, Bootstrap Aggregating)**: 학습용 데이터에서 **복원 추출**로 중복을 허용하여 서브 데이터를 생성하고, 각 서브 데이터로 모델을 개별 훈련한 후 결과를 집계
- **페이스팅(Pasting)**: 학습용 데이터에서 **비복원 추출**로 중복 없이 서브 데이터 생성

**8. 랜덤 패치와 랜덤 서브스페이스**
- 특성 무작위 추출(Feature Sampling): '행'뿐만 아니라 '특성(열)'까지 무작위로 추출해 모델 간 다채로움(Diversity) 확보
- **랜덤 패치**: 샘플과 특성을 모두 무작위 추출 (`bootstrap=True` & `max_features < 1.0`)
- **랜덤 서브스페이스**: 샘플은 전체를 쓰고 특성만 무작위 추출 (`bootstrap=False` & `max_features < 1.0`)
- 장점: 고차원 데이터에서 일부 강한 특성에 모델이 편향되는 현상을 예방

**9. 랜덤 포레스트 (Random Forest)**
- 결정 트리를 기본 모델(Base Estimator)로 사용하는 **랜덤 패치 기반의 대표적 베깅 앙상블**
- 트리의 무작위성: 노드를 분할할 때 전체 특성을 검토하지 않고, **무작위로 선택된 특성의 부분집합(√n_features) 중에서** 최선의 분할 특성을 선택
- `RandomForestClassifier` / `RandomForestRegressor`
- `n_estimators` 기본값은 100 (트리 100개)
- `feature_importances_`로 특성별 중요도 확인 가능

### 왜 이렇게 코딩했는가

- 회귀에서 `stratify`를 쓰지 않은 이유
  → `stratify`는 정답의 항목별 비율을 유지하는 옵션이라 분류에서만 쓸 수 있음. 집값처럼 연속된 숫자는 항목이 거의 모든 행마다 달라져서 적용할 수 없음
- `plot_tree`에 `max_depth=3`을 준 이유
  → 학습된 트리의 깊이가 당뇨병 37, 집값 18이라 전부 그리면 글자가 보이지 않고 출력에도 오래 걸림. 상위 3단계만 보면 어떤 특성으로 먼저 나누는지는 충분히 확인됨
- 학습용 성능도 함께 측정한 이유
  → 평가용 성능만 보면 과대적합인지 알 수 없음. 두 값을 나란히 봐야 모델이 데이터를 외운 것인지 일반화한 것인지 판단할 수 있음
- 랜덤 포레스트와 결정 트리에 **같은 `random_state`와 분할 비율**을 쓴 이유
  → 두 모델의 성능 차이가 알고리즘 때문인지 데이터 분할 때문인지 구분하려면 분할 조건이 같아야 함
- 변수명을 `dt_clf` / `dt_reg`, `rf_clf` / `rf_reg`로 나눈 이유
  → 한 파일에 분류와 회귀가 함께 있어서 `dt`, `rf`만으로는 구분되지 않음
- `feature_importances_`를 출력한 이유
  → 랜덤 포레스트는 트리를 100개 만들어 개별 트리를 그려볼 수 없으므로, 어떤 특성이 기여했는지는 중요도로 확인해야 함

  ```
    which is too few. The minimum number of groups for any class
    cannot be less than 2.
    Classes with too few members are: [5.6, 6.3, 7.4, 7.5, 8.1, ...]
  ```
  - 원인: `stratify`는 정답의 **항목별 비율**을 학습용과 평가용에 똑같이 유지하는 옵션인데, 비율을 맞추려면 각 항목이 최소 2개는 있어야 양쪽에 하나씩 나눠 넣을 수 있음
  - 집값(`medv`)은 506개 행에 고유값이 **229개**이고, 그중 **100개는 데이터에 단 한 번만 등장**함. 5.6이라는 값이 한 명뿐이면 학습용에 넣을지 평가용에 넣을지 비율을 맞출 방법이 없음
  - 반면 당뇨병(`Diabetes_binary`)은 고유값이 0과 1 **두 개뿐**이고 각각 35,346개씩 있어서 비율대로 나눌 수 있음
  - → **정답이 연속형 숫자면(회귀) 못 쓰고, 정해진 항목으로 나뉘면(분류) 쓸 수 있다**

- **그렇다면 분류에서 `stratify`는 실제로 얼마나 차이를 만들까**
  - 당뇨병 데이터(원본 비율 50:50)를 `random_state`만 바꿔가며 나눠봄
    - seed=0 → `stratify` 없음 0.5097 / 적용 0.5000
    - seed=1 → `stratify` 없음 0.4949 / 적용 0.5000
    - seed=2 → `stratify` 없음 0.4932 / 적용 0.5000
  - `stratify`를 쓰면 **항상 정확히 50:50**, 안 쓰면 매번 ±1%p씩 흔들림
  - 이 데이터는 원래 균형이 맞아서 차이가 작지만, 한쪽이 5%뿐인 불균형 데이터라면 운이 나쁠 때 **평가용에 그 클래스가 거의 안 들어갈 수도** 있음
  - 노트북에서 회귀 쪽은 `#stratify=y_data`로 주석 처리해 남겨뒀는데, 지우지 않고 남겨두니 **"여기선 왜 안 썼는지"가 코드에 그대로 보여서** 앞으로도 이렇게 하기로 함

## 📅 2026-10-14 | 모델 정규화(Lasso) / 부스팅·XGBoost / 스태킹

> 코드: [`regularization.py`](./regularization.py)
> 코드: [`boosting_stacking.py`](./boosting_stacking.py)
> 코드: [`diabetes_eda.py`](./diabetes_eda.py)

### 개념

**1. 부스팅(Boosting)의 핵심 메커니즘**
- **순차적 학습(Sequential Learning)**: 이전 모델의 오류를 다음 모델이 보완하는 체인 형태의 앙상블
- 첫 번째 트리는 평균값으로 예측하고, 실제값과의 차이인 **잔차(Residual)**를 다음 트리가 학습함
- 베깅(랜덤 포레스트)은 트리를 동시에 만들어 평균을 내지만, 부스팅은 앞 트리가 틀린 것을 뒤 트리가 고쳐나감

**2. 부스팅을 '조각상 다듬기'로 이해하기**
- 초기값: 대략적인 큰 덩어리를 잡음(첫 번째 트리 예측: 평균값으로 오차 계산)
- 1단계: 튀어나온 큰 오차 부분을 깎아냄(두 번째 트리 예측 × 학습률)
- 2단계: 아직 덜 깎이거나 잘못 깎인 미세한 오차를 조금 더 깎아냄
- 이를 수백 번 반복하여 점점 정밀한 조각(완성된 모델)을 만들어냄

**3. XGBoost (Extreme Gradient Boosting)**
- 별도 설치가 필요함: `pip install xgboost`
- `XGBClassifier`(분류) / `XGBRegressor`(회귀)
- sklearn과 사용법이 같아 `fit` → `predict` → 평가 흐름을 그대로 쓸 수 있음

**4. 스태킹 (Stacking / Stacked Generalization)**
- 학습용 데이터에 대한 개별 모델들의 **예측 결과를 새로운 특성(Feature)으로 만들어** 메타 모델을 학습시키는 앙상블 기법
- 학습 2단계 구조
  - 1단계(Base Models): 서로 다른 알고리즘으로 개별 모델 학습 및 예측 수행
  - 2단계(Meta Model): 1단계 모델들의 예측값을 입력 데이터(X)로 삼아 최종 메타 모델 훈련
  - 정리: [기반 모델들의 train] → [출력값 + 정답 결합] → [메타 모델의 train]
- 예측 2단계 구조: [기반 모델들의 predict] → [출력값 결합] → [메타 모델의 predict]
- `StackingClassifier` / `StackingRegressor`에 `estimators`와 `final_estimator`를 전달
- 메타 모델은 분류에 `LogisticRegression`, 회귀에 `LinearRegression`을 주로 사용

**5. 모델 선택 기준 (교재 114p)**
- 1단계: 비즈니스 제약 확인 — 설명 가능성이 필수인가? 추세 예측인가?
- 2단계: 후보 모델 일괄 실험 — 선형/로지스틱, SVM, 단일 트리, 랜덤포레스트, 부스팅, 스태킹
- 3단계: 정량 지표 평가 & 선택 — **분류: F1-score / 회귀: RMSE**

**6. 모델 정규화 복습 (교재 42~46p)**
- L1 규제(Lasso): 모든 가중치를 **같은 크기**로 감소 → 작은 가중치가 0이 되어 중요도 낮은 특성이 제거됨
- L2 규제(Ridge): 모든 가중치를 **같은 비율**로 감소 → 0에 가까워질 뿐 0이 되지는 않음
- 하이퍼파라미터 `alpha`로 규제의 강도를 조절

### 왜 이렇게 코딩했는가

- 규제 모델 앞에 표준화를 넣은 이유
  → 규제는 가중치의 크기에 벌점을 매기는데, 특성마다 단위가 다르면 벌점이 불공평하게 매겨짐. 지난주 "선형 회귀는 표준화해도 성능이 같다"가 여기서 뒤집힘
- `lasso.coef_`를 컬럼명과 묶어 0이 된 특성을 따로 출력한 이유
  → 숫자 배열만 보면 `-0.`이 몇 개인지만 알 수 있고, **어떤 특성이** 제거되었는지는 알 수 없음
- 분류와 회귀 모두에 같은 데이터·같은 `random_state`를 쓴 이유
  → 세 모델(RandomForest / XGBoost / Stacking)의 차이가 알고리즘 때문인지 데이터 분할 때문인지 구분하기 위함
- 스태킹의 메타 모델로 분류에는 `LogisticRegression`, 회귀에는 `LinearRegression`을 쓴 이유
  → 메타 모델은 1단계 예측값 3개를 입력으로 받는 단순한 문제를 풀기 때문에, 복잡한 모델보다 단순한 선형 모델이 적합함
- `LogisticRegression(max_iter=1000)`으로 반복 횟수를 늘린 이유
  → 기본값 100으로는 수렴하지 않아 경고가 발생할 수 있음
- EDA에서 `value_counts()` 결과에 `reset_index()`와 `replace({0.0: "0"})`를 적용한 이유
  → `value_counts()`는 Series를 반환해서 `px.bar`의 `data_frame`에 바로 넣을 수 없고, 0.0/1.0은 숫자라 x축이 연속형으로 그려짐. 문자열로 바꿔야 범주로 인식됨

### 막혔던 부분 / 이해 포인트

- **L1 규제가 실제로 특성 8개를 0으로 만들었다**
  - `lasso.coef_` 13개 중 8개가 정확히 0 → `crim`, `zn`, `indus`, `chas`, `nox`, `age`, `dis`, `rad`
  - 살아남은 5개: `rm` 2.529(방 개수), `lstat` -3.606, `ptratio` -1.701, `tax` -0.228, `b` 0.132
  - 지난주 선형 회귀에서 영향력 1·2위였던 `lstat`과 `rm`이 그대로 살아남음
  - 교재 43p의 "크기가 작은 가중치들을 0으로 만들어 중요도가 낮은 특성을 제거"가 숫자로 확인됨

- **그런데 규제를 걸었더니 성능이 오히려 나빠졌다**
  - 선형 회귀 RMSE 5.4573 → Lasso(기본 `alpha=1.0`) RMSE **5.9573**
  - `alpha`를 바꿔가며 돌려보니
    - `alpha=1.0` → 5.9573 (0이 된 특성 8개)
    - `alpha=0.5` → 5.9159 (5개)
    - `alpha=0.1` → 5.5833 (0개)
    - `alpha=0.01` → 5.4660 (0개, 선형 회귀와 거의 같음)
  - 학습용 성능까지 보면 이유가 드러남
    - 선형 회귀: 학습용 4.4318 / 평가용 5.4573 (차이 1.03)
    - Lasso: 학습용 5.0386 / 평가용 5.9573 (차이 0.92)
  - 규제가 과적합 차이는 줄였지만(1.03 → 0.92) **학습용 성능까지 함께 떨어뜨림**
  - → 보스턴 데이터는 506개에 특성 13개라 애초에 과적합이 심하지 않았고, 이런 경우 **규제는 이득이 아니라 손해**가 됨. 어제 결정 트리처럼 학습용 0.9952 / 평가용 0.6545인 상황이어야 규제가 효과를 봄

- **Ridge는 아무리 강하게 걸어도 계수가 0이 되지 않는다**
  - `Ridge(alpha=1)` → 0인 특성 0개 / `alpha=10` → 0개 / `alpha=100` → 0개
  - 같은 강도의 `Lasso(alpha=1.0)`은 8개를 0으로 만듦
  - L1은 **같은 크기**로 빼서 0에 도달하지만, L2는 **같은 비율**로 줄이기 때문에 반으로 줄이기를 반복해도 0이 되지 않음
  - → 특성을 **골라내고 싶으면 Lasso**, 전체를 **고르게 줄이고 싶으면 Ridge**

- **가장 복잡한 모델인 스태킹이 1등이 아니었다**
  - 집값 회귀(RMSE, 낮을수록 좋음): 랜덤 포레스트 **4.0720** < 스태킹 4.1951 < XGBoost 4.2298
  - 당뇨병 분류(정확도, 높을수록 좋음): XGBoost **0.7498** > 스태킹 0.7478 > 랜덤 포레스트 0.7402
  - 두 경우 모두 모델 3개를 모아 메타 모델까지 얹은 스태킹이 2등
  - 스태킹은 1단계 모델들이 **서로 다른 종류의 실수**를 할 때 이득을 보는데, 여기서는 세 모델이 모두 트리 기반이라 비슷하게 틀렸을 가능성이 큼
  - → **모델을 복잡하게 만든다고 항상 좋아지는 게 아니고, 실제로 돌려서 비교해봐야 안다**

- **데이터에 따라 1등 모델이 달랐다**
  - 집값(506개, 특성 13개)은 랜덤 포레스트가, 당뇨병(70,692개, 특성 21개)은 XGBoost가 1등
  - 교재 114p가 "후보 모델 **일괄 실험**"을 2단계로 넣어둔 이유를 알 것 같음. 어떤 모델이 좋은지는 데이터를 보기 전에 정할 수 없음

## 📅 2026-10-15 | 고객 이탈 예측(Telco) 전처리·EDA / Ridge 모델

> 코드: [`telco_churn.py`](./telco_churn.py)
> 코드: [`regularization.py`](./regularization.py)

### 개념

**1. Telco Customer Churn 데이터**
- 가상의 통신사가 지난달에 이탈한 고객의 정보를 담은 데이터셋 (Kaggle)
- 7,043개의 행(고객) / 21개의 열(특성), 누락 데이터 포함
- 타겟 변수: `Churn` (고객의 이탈 여부, Yes / No)
- 분석의 핵심 목표: **"어떤 특성을 가진 고객이 떠날 가능성이 높은가?"** 를 파악해 선제적인 방어 마케팅을 설계하는 것
- 컬럼은 크게 세 가지로 나뉨
  - 고객 인구통계: `gender`, `SeniorCitizen`, `Partner`, `Dependents`
  - 가입 서비스: `PhoneService`, `InternetService`, `OnlineSecurity`, `TechSupport` 등
  - 계약 및 결제: `tenure`(가입 개월 수), `Contract`, `PaymentMethod`, `MonthlyCharges`, `TotalCharges`

**2. `df.info()` — 전처리 전에 자료형부터 확인**
- 각 컬럼의 행 수, 누락이 아닌 값의 개수(Non-Null Count), 자료형(Dtype)을 한 번에 보여줌
- 숫자여야 할 컬럼이 문자열(`str`)로 읽혔는지 확인하는 용도로 쓸 수 있음

**3. `pd.to_numeric(컬럼, errors="coerce")`**
- 문자열 컬럼을 숫자형으로 변환하는 함수
- `errors="coerce"`: 숫자로 바꿀 수 없는 값(공백, 문자 등)을 에러 대신 **누락(NaN)으로 처리**
- 누락으로 바꿔두면 `dropna()`나 `fillna()`로 이어서 처리할 수 있음

**4. `df.select_dtypes(include=[...])`**
- 자료형을 기준으로 컬럼을 골라내는 DataFrame 전용 함수
- `.columns.tolist()`와 이어 쓰면 범주형 컬럼의 이름 리스트를 한 줄로 얻을 수 있음
- `df.select_dtypes(include=["str"]).columns.tolist()`

**5. `map()` vs `replace()` — 라벨 인코딩**
- `map({"No": 0, "Yes": 1})`: Series 전용. 딕셔너리에 없는 값은 NaN이 됨
- `replace({...})`: 지정한 값만 바꾸고 나머지는 그대로 둠
- 정답 컬럼처럼 **값의 종류가 정해져 있을 때는 `map()`이 안전함** (빠진 값이 있으면 NaN으로 드러나기 때문)

**6. `groupby([...]).size().reset_index(name="컬럼명")`**
- 두 개 이상의 기준 컬럼으로 묶어 각 조합의 **행 수**를 세는 방법
- `size()`는 Series를 반환하므로 `reset_index(name=...)`로 DataFrame으로 바꿔야 `px.bar`에 넣을 수 있음

**7. L2 규제(Ridge) 복습**
- 모든 가중치를 **같은 비율**로 감소시킴 → 0에 가까워지지만 0이 되지는 않음
- L1(Lasso)은 같은 크기로 빼기 때문에 0에 도달해 특성이 제거됨

### 왜 이렇게 코딩했는가

- `df.info()`를 전처리의 첫 단계로 넣은 이유
  → `TotalCharges`가 금액인데 `str`로 읽힌 것을 발견하기 위함. 데이터를 눈으로만 보면 숫자처럼 보여서 놓치기 쉬움
- 공백 행을 바로 지우지 않고 `query("TotalCharges == ' '")`로 먼저 확인한 이유
  → 몇 개가 어느 위치에 있는지 알아야 "지워도 되는 양인지" 판단할 수 있음 (11개 / 7,043개)
- `errors="coerce"`를 쓴 이유
  → 이 옵션이 없으면 공백을 만나는 순간 에러가 나서 변환 자체가 멈춤. 누락으로 바꿔두면 기존에 쓰던 `dropna()`로 이어서 처리할 수 있음
- `customerID`를 삭제한 이유
  → 고객을 식별하는 고유 번호라 예측에 아무 정보도 주지 않음. 오히려 모든 행이 다른 값이라 모델이 잘못 학습할 수 있음
- 범주형 컬럼을 `select_dtypes()`로 자동 추출한 이유
  → 범주형 컬럼이 15개라 일일이 적으면 길고 빠뜨리기 쉬움. 컬럼이 바뀌어도 코드를 고치지 않아도 됨
- `train_test_split`에 `stratify`를 적용한 이유
  → 이탈 고객이 26.6%인 불균형 데이터라, 무작위로 나누면 평가용의 이탈 비율이 달라질 수 있음
- 모델 학습 전에 표준화를 넣은 이유

**3. `pd.to_numeric(컬럼, errors="coerce")`**
- 문자열 컬럼을 숫자형으로 변환하는 함수
- `errors="coerce"`: 숫자로 바꿀 수 없는 값(공백, 문자 등)을 에러 대신 **누락(NaN)으로 처리**
- 누락으로 바꿔두면 `dropna()`나 `fillna()`로 이어서 처리할 수 있음

**4. `df.select_dtypes(include=[...])`**
- 자료형을 기준으로 컬럼을 골라내는 DataFrame 전용 함수
- `.columns.tolist()`와 이어 쓰면 범주형 컬럼의 이름 리스트를 한 줄로 얻을 수 있음
- `df.select_dtypes(include=["str"]).columns.tolist()`

**5. `map()` vs `replace()` — 라벨 인코딩**
- `map({"No": 0, "Yes": 1})`: Series 전용. 딕셔너리에 없는 값은 NaN이 됨
- `replace({...})`: 지정한 값만 바꾸고 나머지는 그대로 둠
- 정답 컬럼처럼 **값의 종류가 정해져 있을 때는 `map()`이 안전함** (빠진 값이 있으면 NaN으로 드러나기 때문)

**6. `groupby([...]).size().reset_index(name="컬럼명")`**
- 두 개 이상의 기준 컬럼으로 묶어 각 조합의 **행 수**를 세는 방법
- `size()`는 Series를 반환하므로 `reset_index(name=...)`로 DataFrame으로 바꿔야 `px.bar`에 넣을 수 있음

**7. L2 규제(Ridge) 복습**
- 모든 가중치를 **같은 비율**로 감소시킴 → 0에 가까워지지만 0이 되지는 않음
- L1(Lasso)은 같은 크기로 빼기 때문에 0에 도달해 특성이 제거됨

**8. 모델별 표준화 필요 여부 정리**
- 로지스틱 회귀 / SVM: 값의 범위가 결과에 영향을 주므로 **표준화한 데이터**를 사용
- 결정 트리: "값이 임계값보다 큰가"만 따지므로 **원본 데이터**를 그대로 사용

## 📅 2026-10-16 | 차원 축소 (PCA) / 손글씨 데이터

> 코드: [`dimensionality_reduction.py`](./dimensionality_reduction.py)

### 개념

**1. 차원의 저주(Curse of Dimensionality)**
- 데이터의 차원(특성 수)이 증가할수록 공간의 부피가 급격히 커져서, 데이터 밀도가 극도로 **희박(Sparse)** 해지는 현상
- 주요 문제점
  - 과대적합 위험 극대화: 샘플 수에 비해 차원이 많아지면 모델이 잡음까지 학습함
  - 거리 측정의 무의미화: 고차원에서는 거의 모든 샘플 간 거리가 비슷해져서, 유클리드 거리 기반 알고리즘(SVM, K-Means 등)의 성능이 떨어짐
- 해결 방안
  - 학습용 데이터 밀도 올리기 → 차원이 늘어난 만큼 엄청난 양의 데이터가 필요해서 현실적으로 불가능
  - **차원 축소(Dimensionality Reduction)**

**2. PCA(Principal Component Analysis, 주성분 분석)**
- 데이터가 가장 넓게 퍼져서 원래 형태를 가장 잘 나타내는 **각도(축)** 를 찾아내고, 그 축으로 데이터를 투영해 차원을 줄이는 알고리즘
- 첫 번째 주성분(PC1): 데이터의 분산이 가장 넓게 퍼지는 축
- 두 번째 주성분(PC2): PC1과 **직교**하면서 분산이 가장 넓게 퍼지는 축

**3. 주성분 개수를 정하는 두 가지 방법**
- 시각화가 목적이면 2개(2차원)
- 모델 학습이 목적이면 원본 정보의 80~90% 이상을 유지하는 개수 `d`를 선택

**4. `PCA`의 `n_components`는 정수와 실수를 다르게 해석한다**
- 정수(`n_components=2`) → "주성분을 **2개** 만들어라"
- 0과 1 사이 실수(`n_components=0.95`) → "원본 정보의 **95%를 유지**하는 데 필요한 개수를 알아서 계산해라"

### 왜 이렇게 코딩했는가

- `load_digits()`로 손글씨 데이터를 쓴 이유
  → 8×8 픽셀 이미지라서 특성이 64개. 고차원이 무엇인지 체감하기 좋고, 각 픽셀이 하나의 차원이라는 게 직관적임
- `np.unique(ar=y_digits, return_counts=True)`로 빈도수를 확인한 이유
  → 0~9까지 숫자가 고르게 들어있는지 먼저 확인하기 위함 (174~183개로 균형 잡힌 데이터임을 확인)
- `fit_transform()` 하나만 쓰고 `transform()`은 쓰지 않은 이유
  → 학습용과 평가용으로 나누기 전, 전체 데이터의 차원을 줄여 구조를 살펴보는 단계이기 때문. 실제 모델 학습에 쓸 때는 스케일러와 똑같이 학습용에 `fit_transform()`, 평가용에 `transform()`을 적용해야 함
- 2차원 변환과 95% 유지 변환을 **모델 두 개로 따로** 만든 이유
  → 목적이 다름. `pca_2d`는 눈으로 보기 위한 것이고, `pca_95`는 정보 손실을 최소화하면서 차원만 줄이기 위한 것

### 이해 포인트

- **2차원으로 줄이면 원본 정보의 28.5%만 남는다**
  - `explained_variance_ratio_`로 확인해보니 PC1이 14.89%, PC2가 13.62% → 합쳐서 **28.51%**
  - 즉 64차원을 2차원으로 줄이면 정보의 **71.5%가 사라짐**
  - 그래서 2차원 축소는 "눈으로 보기 위한 것"이지 모델에 넣기 위한 것이 아님
  - 교재가 "시각화 목표: 2개"와 "80~90% 이상 유지"를 **따로** 적어둔 이유가 이것

- **이 데이터에서 80% / 90% / 95%를 유지하려면 몇 개가 필요한가**
  - 80% → 13개 / 90% → 21개 / 95% → **29개**
  - 64차원을 29차원으로 줄이면서 정보는 95.48% 유지 → 차원은 55% 줄었는데 정보는 4.5%만 잃음
  - 차원 축소의 가치가 여기서 드러남

- **`PCA(random_state=0)`가 이 경우에는 아무 효과가 없다**
  - `random_state`를 0, 42로 바꾸거나 아예 빼고 돌려도 결과가 **완전히 동일**함
  - sklearn이 데이터 크기를 보고 solver를 자동 선택하는데, 이 데이터(1797×64)에서는 `covariance_eigh`가 선택됨. 이 solver에는 무작위성이 아예 없음
  - `random_state`는 solver가 `randomized`일 때만 의미가 있음
  - 붙여서 해로울 건 없지만, **무작위성이 있는 곳에만 `random_state`가 효과를 낸다**는 걸 알고 쓰는 것과 습관적으로 붙이는 것은 다름

## 📅 2026-10-16 | AutoML (AutoGluon) / 고객 이탈 예측

> 코드: [`automl_autogluon.py`](./automl_autogluon.py)

### 개념

**1. AutoML(Automated Machine Learning)**
- 머신러닝 모델을 구축할 때 필요한 반복적이고 복잡한 과정(전처리, 모델 선택, 성능 고도화)을 **자동화**하는 기술
- 필요성: 모델 개발 시간을 단축해서 데이터 분석가가 '비즈니스 가치 창출'에 더 집중하게 함

**2. AutoGluon**
- Amazon이 개발한 파이썬 기반 오픈 소스 AutoML 라이브러리
- 설치: `pip install -U "autogluon.tabular[all]>=1.6.0"`
- 전통적 방식과의 차이
  - 모델 탐색: 모델별 개별 코드 작성 → **한 줄로 수십 개 모델 동시 학습·비교**
  - 데이터 전처리: 인코딩·누락·스케일링 직접 구현 → **기초 전처리 자동화** (단, 도메인 파생 변수 생성과 노이즈 정제는 제외)
  - 성능 고도화: `GridSearchCV` 수동 최적화 → **하이퍼파라미터 최적화와 다층 스태킹 앙상블 자동화**

**3. AutoGluon 3-Step 워크플로우**
- `TabularPredictor` 클래스: 모델 생성 (`label`, `eval_metric`, `path` 지정)
- `fit()` 함수: 학습 및 최적화, best 모델 생성
- `evaluate()` 함수: best 모델 성능 평가(예측 + 평가를 한 번에)

**4. `fit()`의 주요 매개변수**
- `presets="best_quality"`: 성능 우선 설정
- `num_gpus=0`: CPU만 사용
- `dynamic_stacking=False`: 사전 탐색(DyStack) 끄기 → 자원 절약
- `num_stack_levels=1`: 스태킹을 1단계까지만
- `time_limit=300`: 학습 시간을 300초로 제한

**5. 학습된 모델의 저장과 재사용**
- `path`로 지정한 경로에 학습이 끝난 모델이 저장됨
- `TabularPredictor.load(경로)`로 불러오면 **다시 학습하지 않고** 바로 예측·평가 가능

### 왜 이렇게 코딩했는가

- `X_data`와 `y_data`로 나누지 않고 DataFrame을 통째로 분할한 이유
  → AutoGluon은 sklearn과 입력 방식이 다름. `label="Churn"`으로 정답 컬럼 이름만 알려주면 되므로 X/y를 미리 쪼개면 오히려 쓸 수 없음
- `stratify=df2["Churn"]`를 지정한 이유
  → 이탈 고객이 26.6%뿐인 불균형 데이터라, 무작위로 나누면 학습용과 평가용의 이탈 비율이 달라질 수 있음
- 학습용과 평가용의 정답 비율을 **둘 다** 출력한 이유
  → `stratify`가 제대로 적용됐는지는 한쪽만 봐서는 알 수 없음. 두 비율이 같아야 확인이 되는 것 (학습용 0.734222 / 평가용 0.734186으로 거의 일치)
- `eval_metric="accuracy"`로 지정한 이유
  → 교재 예시를 따름. 다만 불균형 데이터에서는 이 선택이 결과를 크게 바꾼다는 걸 아래에서 확인함
- `dynamic_stacking=False`, `time_limit=300`을 준 이유
  → 설정하지 않으면 학습이 무한정 길어질 수 있음. 수업 시간 안에 끝내기 위해 자원과 시간을 제한함

### 막혔던 부분 / 이해 포인트

- **AutoML이 로지스틱 회귀 한 줄보다 못한 결과를 냈다**
  - 같은 데이터, 같은 분할(`test_size=0.2`, `random_state=0`, `stratify`)로 비교한 결과
    - 베이스라인(전부 "이탈 안 함"으로 찍기) → 정확도 0.7342
    - 결정 트리 → 0.7193
    - 랜덤 포레스트 → 0.7903
    - **AutoGluon (5분, 모델 15개, 3단계 스태킹) → 0.8003**
    - **로지스틱 회귀 (한 줄) → 0.8081**
  - f1-score도 로지스틱 0.6053 vs AutoGluon 0.5504로 로지스틱이 앞섬
  - AutoML은 **"자동으로 돌려주는 도구"이지 "항상 최고 성능을 내는 도구"가 아니다**

- **`leaderboard()`의 점수와 실제 평가 점수가 다른 이유**
  - leaderboard의 1등(`WeightedEnsemble_L3`) 검증 점수는 0.8126인데, 평가용 데이터 실제 점수는 0.8003
  - leaderboard의 `score_val`은 **학습용 데이터 안에서 나눈 검증 데이터**로 매긴 점수
  - 그 점수를 기준으로 모델을 고르다 보면, 검증 데이터에 맞춰진 모델이 뽑힐 수 있음
  - 결국 **최종 판단은 평가용 데이터로 해야 한다**는 원칙이 AutoML에서도 똑같이 적용됨

- **불균형 데이터에서 `eval_metric="accuracy"`의 함정**
  - AutoGluon의 recall이 0.4599 → 실제 이탈한 374명 중 **172명만 찾아내고 202명을 놓침**
  - 정확도를 기준으로 최적화하면, 전체의 73.4%를 차지하는 "이탈 안 함"을 잘 맞히는 쪽이 유리해짐
  - 어제 SVM이 1,407명 전원을 0으로 예측하고도 정확도 0.7342가 나왔던 것과 같은 원리
  - 이탈 고객을 찾는 것이 목적이라면 `eval_metric`을 `f1`이나 `recall`로 바꿔야 함
  - 교재 114p "모델 선택 기준"에서 **분류는 F1-score**로 보라고 한 이유가 이것

## 📅 2026-10-16 | 비지도 학습 (K-Means) / 붓꽃 군집화

> 코드: [`clustering_kmeans.py`](./clustering_kmeans.py)

### 개념

**1. 군집화(Clustering)**
- 유사한 속성들을 갖는 데이터를 묶어 전체 데이터를 몇 개의 군집(그룹)으로 나누는 것
- 군집화 기준
  - 군집 간 분산(inter-cluster variance): **최대화** → 집단 간의 이질성 최대
  - 군집 내 분산(inner-cluster variance): **최소화** → 집단 내의 유사성 최대

**2. 분류(Classification)와 군집화(Clustering)의 차이**
- 분류: 사전에 정의된 범주가 있는(**labeled**) 데이터를 학습한 후 미지의 데이터에 대해 범주를 예측 → 지도 학습
- 군집화: 사전에 정의된 범주가 없는(**unlabeled**) 데이터로부터 최적의 군집을 찾는 것 → 비지도 학습

**3. K-Means 알고리즘**
- 군집화에서 가장 일반적인 알고리즘으로, 임의의 K개만큼 클러스터를 묶는 방식
- 데이터들 사이의 **유클리디안 거리**를 측정하여 군집화
- 원리
  - 초기 중심점 설정
  - 각 데이터를 가장 가까운 중심점에 할당 → 초기 클러스터 생성
  - 클러스터에 할당된 데이터 간 거리의 평균을 계산 → 중심점 다시 지정(중심점 이동)
  - 이동된 중심점 기준으로 다시 할당 → 새 클러스터 생성
  - **중심점의 변경과 이동이 없으면 종료**

**4. 최적의 클러스터 개수 설정: 엘보우(elbow) method**
- 클러스터 내 오차제곱합(SSE)이 최소가 되도록 클러스터의 중심을 설정하는 방법
- 클러스터의 개수를 1에서 n으로 증가시키며 SSE의 변화를 관찰
- SSE의 변화가 가장 크게 감소하는 구간 → 최적의 개수

**5. 사용법**
- `from sklearn.cluster import KMeans`
- `model = KMeans(n_clusters=k, random_state)`
- `model.fit_predict(data)` → 학습과 군집화 결과 확인을 한 번에

### 왜 이렇게 코딩했는가

- `fit()`과 `predict()`를 따로 쓰지 않고 `fit_predict()`를 쓴 이유
  → 군집화에는 평가용 데이터가 따로 없음. 전체 데이터를 학습하면서 동시에 각 행이 어느 군집에 속하는지 번호를 돌려받으면 되므로 한 번에 처리함
- `data`에 정답 컬럼(`label`)을 넣지 않은 이유
  → 비지도 학습이므로 정답을 모르는 상태에서 군집을 찾는 것이 목적. 정답을 넣으면 그건 군집화가 아니라 분류가 됨
- 4개 특성 중 꽃잎의 길이·너비 **2개만** 뽑은 이유
  → 2차원이어야 산점도로 그려서 군집 결과를 눈으로 확인할 수 있음. 또한 붓꽃 EDA에서 꽃받침보다 꽃잎이 품종을 더 잘 구분한다는 걸 이미 확인했기 때문
- 군집화 전에 산점도를 먼저 그린 이유
  → 데이터가 실제로 몇 덩어리로 보이는지 눈으로 먼저 확인하기 위함. 사람 눈에 2덩어리로 보이는지 3덩어리로 보이는지가 `n_clusters` 선택의 출발점이 됨

### 이해 포인트

- **`fit_predict()`의 결과 숫자는 "품종 번호"가 아니라 "군집 번호"다**
  - 출력이 `[1 1 1 ... 0 0 0]`으로 나오지만 1 = setosa, 0 = virginica 같은 의미가 아님
  - 군집에 붙는 번호는 임의로 매겨진 것이라, `random_state`를 바꾸면 0과 1이 뒤바뀔 수도 있음
  - 군집화는 **"이 데이터들이 같은 무리"** 라고만 말해줄 뿐, 그 무리가 무엇인지는 사람이 해석해야 함

- **2개 군집으로 나눴을 때 98번 행 하나만 다른 무리로 갔다**
  - 출력 중간에 `1`이 하나 섞여 있는데, 확인해보니 98번 행
  - 실제 품종은 **versicolor**인데 setosa 쪽 군집으로 분류됨
  - 꽃잎 길이 3.0 / 너비 1.1로, versicolor 중에서 가장 작은 값
  - 군집별 중심점이 (1.492, 0.263)과 (4.925, 1.682)이므로, 이 행은 두 중심점의 중간 지점에 애매하게 놓여 있음
  - **군집화는 정답을 모른 채 거리만 보기 때문에, 경계에 걸친 데이터는 이렇게 넘어갈 수 있다**는 걸 보여주는 사례

- **왜 품종이 3개인데 `n_clusters=2`부터 해봤을까**
  - 산점도를 보면 setosa는 확실히 떨어져 있지만 versicolor와 virginica는 붙어 있음
  - 그래서 사람 눈에는 2덩어리로도, 3덩어리로도 보임
  - 실제로 SSE를 계산해보니 k=1에서 550.90 → k=2에서 86.39로 급감하고, k=3에서 31.37로 또 한 번 꺾임
  - **엘보우가 두 군데 나타나는 경우**라서, 숫자만으로는 2와 3 중 하나를 고르기 어려움
  - 이럴 때는 도메인 지식(붓꽃 품종은 3개)이 판단의 근거가 됨

## 📅 2026-10-19 | 모델 성능 개선 (과대적합 규제 · 교차검증 · GridSearchCV)

> 코드: [model_tuning.py](./model_tuning.py)

### 개념
- 과대적합(Overfitting)
  - 모델이 너무 복잡해서 학습 데이터의 노이즈까지 외워버린 상태
  - 결정 트리에서는 트리가 너무 깊어져서 학습 데이터 하나하나에 맞춘 조건이 생기는 것
  - 판별: 학습용 정확도는 높은데 평가용 정확도가 크게 낮으면 과대적합
- 과대적합 방지: 사전 가지치기
  - 모델 생성 시점에 트리가 자랄 수 있는 범위를 미리 제한
  - 중요한 분기만 남기고 불필요한 세부 조건은 반영하지 않음
  - 대표 규제 매개변수
    - `max_depth`: 트리의 최대 깊이 제한 (가장 직관적인 규제)
    - `min_samples_split`: 노드를 분할하기 위해 필요한 최소 샘플 수
    - `min_samples_leaf`: 리프 노드가 가져야 하는 최소 샘플 수
- 학습용 · 검증용 · 평가용 데이터의 역할
  - 학습용(train): 모델이 학습하는 데이터
  - 검증용(validation): 하이퍼파라미터를 고르기 위해 성능을 비교하는 데이터
  - 평가용(test): 모든 선택이 끝난 뒤 최종 성능을 딱 한 번 확인하는 데이터
  - 평가용 점수를 보면서 하이퍼파라미터를 고르면 평가용 데이터에 맞춰지는 셈이라 최종 점수를 믿을 수 없게 됨
- K-fold 교차검증(Cross-Validation)
  - 한 번 나눈 검증 점수가 운 좋게 잘 나온 건지, 진짜 실력인지 판별하는 표준 기법
  - 진행 순서
    1. 학습용 데이터를 k개의 그룹(fold)으로 나눈다
    2. k-1개의 그룹으로 학습한다
    3. 남은 1개 그룹으로 검증한다
    4. 검증 그룹을 바꿔가며 2~3번을 k번 반복한다
    5. k개 점수의 평균을 최종 검증 점수로 사용한다
  - k는 보통 5 또는 10, 클수록 학습 횟수가 늘어나 시간이 오래 걸림
  - 분류 모델에서 `cv=5`처럼 숫자를 주면 정답 비율을 유지하는 StratifiedKFold가 자동 적용됨
- 실무에서의 검증 방식
  - 일반 머신러닝: K-fold 교차검증
  - 딥러닝: Hold-out 검증
    - 전체 데이터를 학습용 · 검증용 · 평가용으로 한 번만 무작위 분할
    - 딥러닝은 한 번 학습하는 비용이 커서 k번 반복하기 부담스러움
    - 데이터가 충분히 크면 한 번만 나눠도 각 데이터가 전체 분포를 잘 대변함
- GridSearchCV
  - 하이퍼파라미터 후보의 모든 조합을 교차검증으로 평가해서 가장 좋은 조합을 찾아주는 도구
  - 주요 매개변수
    - `estimator`: 튜닝할 모델
    - `param_grid`: 탐색할 하이퍼파라미터 후보 (dict)
    - `scoring`: 비교 기준 지표 (예: `"accuracy"`)
    - `cv`: 교차검증 fold 수
  - 주요 결과 속성
    - `best_params_`: 가장 좋았던 하이퍼파라미터 조합
    - `best_score_`: 그 조합의 교차검증 평균 점수 (평가용 점수가 아님)
    - `best_estimator_`: 가장 좋은 조합으로 학습용 데이터 전체에 다시 학습한 모델

### 왜 이렇게 코딩했는가
- 당뇨병 데이터(70,692행, 정답 비율 50:50)를 `stratify=y_data`로 80:20 분할
  - 학습용 정답 비율 0.500009 : 0.499991로 원본 비율이 유지된 것을 `value_counts(normalize=True)`로 확인
- 결정 트리에 `max_depth=9`를 직접 지정해서 규제 효과 확인
  - `get_depth()`로 실제 트리 깊이가 9로 제한된 것을 확인
  - `plot_tree(..., max_depth=3)`으로 위쪽 3단계만 시각화 (깊이 9 전체는 너무 커서 알아볼 수 없음)
- GridSearchCV로 하이퍼파라미터 자동 탐색
```python
    params = {
        "max_depth": [3, 4, 5, 6, 7, 8, 9, 10],
        "min_samples_leaf": [2, 3, 4, 5]
    }
    grid_dt = GridSearchCV(estimator=dt, param_grid=params, scoring="accuracy", cv=5)
    grid_dt.fit(X_train, y_train)
    best_dt = grid_dt.best_estimator_
```
  - 후보 조합 8 × 4 = 32개, 각각 5-fold로 학습하므로 총 160번 학습
  - `fit()`에는 학습용 데이터만 넣음 → 평가용 데이터는 탐색 과정에 전혀 쓰이지 않음
- 결과 비교
  - 규제 없는 결정 트리(10/13): 0.6545
  - `max_depth=9` 직접 지정: 평가용 0.7432
  - GridSearchCV 최적 조합 `max_depth=7, min_samples_leaf=5`: 교차검증 0.7419 / 평가용 0.7411
  - 규제만으로 정확도가 약 0.09 상승 → 과대적합이 성능을 크게 떨어뜨리고 있었음을 확인

### 이해 포인트
- GridSearchCV 결과(0.7411)가 직접 지정한 depth 9(0.7432)보다 낮게 나옴
  - 차이 0.002는 의미 있는 차이라기보다 데이터 분할에 따른 오차 수준
  - depth 9는 평가용 점수를 보고 골랐다면 평가용 데이터를 튜닝에 쓴 셈이라 공정한 비교가 아님
  - GridSearchCV는 평가용을 한 번도 보지 않고 고른 결과라 더 믿을 수 있는 숫자
- `best_score_`와 평가용 점수의 차이
  - `best_score_`(0.7419)는 학습용 데이터 안에서 나눈 검증 fold들의 평균
  - 평가용 점수(0.7411)는 처음 보는 데이터에 대한 결과
  - 두 값이 비슷하다는 건 교차검증이 실제 성능을 잘 예측했다는 뜻
- Train/Test 분할 자체가 나쁜 게 아니라, 평가용 점수 하나만 보고 모델을 고르는 게 문제
  - 교차검증은 학습용 안에서, 평가용은 마지막에 한 번만

## 📅 2026-10-20 | 모델 성능 고도화 (RandomizedSearchCV) / 당뇨병 데이터

> 코드: [`model_tuning.py`](./model_tuning.py)

### 개념

**1. RandomizedSearchCV**
- GridSearchCV와 같은 목적(최적의 하이퍼파라미터 탐색)이지만, **모든 조합을 다 돌지 않는다**
- 탐색 범위 안에서 `n_iter`로 정한 횟수만큼 **무작위로 뽑아서** 학습·검증
- `param_grid` 대신 `param_distributions`에 탐색 범위를 전달
- 무작위로 뽑으므로 `random_state`를 지정해야 같은 결과가 재현됨

**2. GridSearchCV와 RandomizedSearchCV의 선택 기준**
- 탐색할 조합이 적으면 GridSearchCV → 전부 다 보므로 최적값을 놓치지 않음
- 조합이 많아 시간이 감당되지 않으면 RandomizedSearchCV → 일부만 보지만 훨씬 빠름
- 오늘 실습에서 RandomForest 전체 조합은 10 × 6 × 4 = **240가지**였는데, `n_iter=30`으로 **30가지만** 탐색함

**3. `classification_report`로 평가 지표 바꾸기**
- `accuracy_score`는 정확도 하나만 돌려줌
- `classification_report(y_test, pred)`는 **precision, recall, f1-score, support**를 클래스별로 한 번에 보여줌
- 불균형 데이터에서는 정확도 하나만으로 판단할 수 없으므로 이쪽이 기본이 됨

**4. 고도화된 모델을 스태킹의 재료로 쓰기**
- 1단계 Base Models에 `DecisionTreeClassifier()` 같은 기본 모델 대신 **탐색으로 찾아낸 best 모델**(`best_dt`, `best_rf`, `best_xgb`)을 넣음
- 2단계 메타 모델은 `LogisticRegression(max_iter=1000)`

### 왜 이렇게 코딩했는가

- RandomForest에 `n_estimators`를 탐색 대상에 넣은 이유
  → 결정 트리는 `max_depth`와 `min_samples_leaf`만 조절하면 되지만, 랜덤 포레스트는 **트리를 몇 개 만들 것인가**가 하나 더 있음. 100개와 1000개는 성능도 시간도 다름
- RandomizedSearchCV에서 `n_estimators` 범위를 1000까지 넓힌 이유
  → 어차피 전부 돌지 않고 30개만 뽑으므로, 범위를 넓게 잡아도 시간이 늘지 않음. **GridSearchCV였다면 범위를 넓히는 순간 조합이 폭발하지만 RandomizedSearchCV는 그렇지 않다**는 점을 이용함
- `scoring="f1"`을 준 이유
  → 7주차에 AutoGluon을 `eval_metric="accuracy"`로 돌렸다가 recall이 0.4599에 그쳤던 경험 때문. 정확도 대신 f1을 기준으로 탐색하면 소수 클래스를 더 신경 쓴 모델이 뽑힌다
- 스태킹의 Base Models에 고도화된 모델을 넣은 이유
  → 기본 모델을 넣으면 "덜 다듬어진 재료"로 요리하는 셈. 각각 최적화를 끝낸 모델을 모아야 스태킹의 의미가 살아남
- `accuracy_score` 대신 `classification_report`로 바꾼 이유
  → 모델 4개를 비교하는데 정확도만 보면 전부 0.74~0.75로 비슷해서 차이가 안 보임. recall과 f1까지 봐야 어느 모델이 당뇨 환자를 더 잘 찾아내는지 구분됨

### 막혔던 부분 / 이해 포인트

- **모델마다 `scoring`이 달라서 `best_score_`를 나란히 비교하면 안 된다**
  - DecisionTree 0.7419와 RandomForest 0.7511은 `scoring="accuracy"` 기준
  - RandomizedSearchCV 0.7617과 XGBoost 0.7642는 `scoring="f1"` 기준
  - 앞의 둘과 뒤의 둘은 **단위가 다른 숫자**라서, 0.7642가 0.7511보다 높다고 모델이 더 좋다고 말할 수 없음
  - 비교는 `classification_report`에 찍힌 같은 지표끼리 해야 함

- **`scoring`을 바꾸면 최적 파라미터가 항상 달라지는 것은 아니다**
  - DecisionTree를 `accuracy`와 `f1`으로 각각 돌려서 비교해봄
    - `scoring="accuracy"` → max_depth=7, min_samples_leaf=5 / best_score_ 0.7419
    - `scoring="f1"` → max_depth=7, min_samples_leaf=5 / best_score_ 0.7498
  - **최적 파라미터는 완전히 동일**했고, 평가용 성능도 0.7411로 같았음
  - 달라진 것은 `best_score_` 숫자뿐 → 같은 모델을 다른 자로 잰 것
  - 이유는 당뇨병 데이터가 **균형 데이터**(파일명의 `5050split`, 평가용 7070명 vs 7069명)이기 때문. 정확도와 f1이 거의 같은 방향을 가리킴
  - Telco 같은 불균형 데이터(이탈 26.6%)였다면 결과가 달랐을 것

- **XGBoost는 자기에게 없는 매개변수를 받아도 에러를 내지 않는다**
  - 처음에 `params`에 `min_samples_leaf`를 넣었는데 에러 없이 탐색이 끝남
  - 출력된 best 모델에도 `min_samples_leaf=2`가 찍혀 있었음
  - 그런데 `min_samples_leaf`는 **sklearn 트리의 매개변수**이고, XGBoost에서 같은 역할을 하는 것은 `min_child_weight`
  - XGBoost는 sklearn 형식을 흉내 내는 껍데기(wrapper)라서, 모르는 이름이 와도 **보관만 하고 학습에는 쓰지 않음**
  - 문제는 탐색량. 4 × 3 × 3 × 4 = **144조합**(720회 학습)을 돌았는데, 아무 효과 없는 값 4개를 빼면 4 × 3 × 3 = **36조합**(180회 학습)이면 충분했음 → **4배를 헛돌린 것**
  - 에러가 나지 않는다고 매개변수가 동작하는 것은 아니라는 걸 확인함

## 📅 2026-10-20 | 분류 평가 지표 (Confusion Matrix·정밀도·재현율·F1)

> 코드: [`model_tuning.py`](./model_tuning.py)

### 개념

**1. Confusion Matrix(혼동 행렬, 오차 행렬)**
- 분류 모델의 예측 성능을 측정하기 위해 **실제 정답과 모델의 예측값을 비교**해 표현한 2×2 행렬
- TP(True Positive): 양성인데 양성이라고 맞힘
- FN(False Negative): 양성인데 음성이라고 틀림 → **놓침**
- FP(False Positive): 음성인데 양성이라고 틀림 → **헛걱정**
- TN(True Negative): 음성인데 음성이라고 맞힘
- 앞 글자 T/F는 **맞혔는지 틀렸는지**, 뒤 글자 P/N은 **모델이 뭐라고 예측했는지**

**2. 정확도(Accuracy)**
- `(TP + TN) / (TP + TN + FP + FN)` → 전체 중에 정확히 맞힌 비율
- **한계**: 데이터가 불균형하면 수학적 왜곡이 생김
  - 암 환자가 100명 중 5명인 데이터에서 아무 연산 없이 "전부 정상"이라고만 찍어도 정확도가 95%

**3. 재현율(Recall)**
- `TP / (TP + FN)` → **실제 정답이 양성인 것들 중** 모델이 양성이라고 맞힌 비율
- 분모가 **실제 양성 전체**(가로 한 줄)
- 위의 암 예시에서 전부 정상이라고 찍으면 재현율은 0/5 = **0.0**
- 놓치면 안 되는 상황(질병 진단, 고객 이탈)에서 중요

**4. 정밀도(Precision)**
- `TP / (TP + FP)` → **모델이 양성이라고 예측한 것들 중** 실제로 양성인 비율
- 분모가 **양성이라고 예측한 전체**(세로 한 줄)
- 틀린 경보가 비용이 되는 상황(스팸 분류)에서 중요

**5. F1-Score**
- 정밀도와 재현율의 **조화평균**
- `F1 = 2 × (Precision × Recall) / (Precision + Recall)`
- 산술평균을 쓰지 않는 이유
  - 정밀도 1.0, 재현율 0.0인 엉터리 모델의 **산술평균은 0.5**로 그럴듯해 보임
  - **조화평균은 (2 × 1.0 × 0.0) / (1.0 + 0.0) = 0.0**
  - 어느 한쪽이 0이면 최종 점수도 0으로 떨어뜨려 불균형의 왜곡을 차단함

**6. 학습된 모델 저장과 재사용 (joblib)**
- `joblib.dump(모델, "파일명.pkl")` → 학습이 끝난 모델을 파일로 저장
- `joblib.load("파일명.pkl")` → 저장된 모델을 **학습이 완료된 상태 그대로** 불러옴
- `.pkl`은 pickle 형식으로, 파이썬 객체를 그대로 파일에 담는 방식
- 불러온 모델은 바로 `predict()`를 쓸 수 있음 (다시 `fit()`을 호출할 필요 없음)

### 왜 이렇게 코딩했는가

- `classification_report` 하나로 바꾼 이유
  → precision, recall, f1-score를 각각 임포트해서 따로 계산할 수도 있지만, 네 지표를 클래스별로 한 번에 보여주므로 비교가 훨씬 빠름
- 출력에서 `support`를 함께 본 이유
  → 각 클래스에 데이터가 몇 개인지 알아야 지표를 해석할 수 있음. 7070명 / 7069명으로 거의 같다는 걸 보고 이 데이터가 균형 데이터임을 확인함
- 모델을 파일로 저장한 이유
  → RandomizedSearchCV로 800개 트리를 탐색하는 데 오래 걸렸는데, 노트북을 껐다 켜면 그 결과가 사라짐. 저장해두면 **탐색을 다시 돌리지 않고** 예측만 바로 할 수 있음
- 불러온 모델로 성능을 다시 측정한 이유
  → 저장과 불러오기 과정에서 모델이 손상되지 않았는지 확인하기 위함. 저장 전과 **똑같은 숫자**가 나와야 제대로 저장된 것

### 이해 포인트

- **재현율과 정밀도는 분모가 가로냐 세로냐의 차이다**
  - 공식만 보면 `TP/(TP+FN)`과 `TP/(TP+FP)`라 헷갈림
  - 혼동 행렬에서 **재현율은 가로 한 줄**(실제 정답이 양성인 행), **정밀도는 세로 한 줄**(양성이라 예측한 열)을 분모로 삼는다고 보니 구분됨
  - "실제 중에 맞힌 비율"이 재현율, "예측 중에 맞힌 비율"이 정밀도

- **지난주 SVM 사건이 교재 5p의 예시와 똑같은 구조였다**
  - 교재: 암 환자 5%인 데이터에서 전부 정상이라고 찍으면 정확도 95%, 재현율 0.0
  - 7주차에 Telco에서 SVM이 1,407명 전원을 0으로 예측하고 정확도 0.7342, recall 0.0000이 나왔던 것과 같은 일
  - 그때는 "이상한데?" 정도로 넘어갔는데, 오늘 **정확도의 수학적 한계**로 설명되는 현상이라는 걸 알게 됨

- **f1-score 차이가 작아 보여도 사람 수로 환산하면 차이가 크다**
  - 평가용 당뇨 환자(클래스 1)는 7,069명
  - recall로 환산해보니
    - DecisionTree recall 0.75 → 약 1,767명을 놓침
    - RandomForest recall 0.78 → 약 1,555명을 놓침
    - XGBoost recall 0.79 → 약 1,484명을 놓침
  - 소수점 두 자리 차이가 **283명**의 차이였음
  - 지표를 비율로만 보지 말고 **사람 수로 바꿔서 보면 체감이 달라진다**는 걸 알게 됨

- **저장한 모델 파일이 생각보다 훨씬 크다**
  - `best_rf_random.pkl`은 `n_estimators=800`, `max_depth=10`짜리 랜덤 포레스트
  - 트리 100개일 때 약 9.5MB, 200개일 때 약 18.8MB → 800개면 **약 75MB**
  - 랜덤 포레스트는 트리 하나하나의 분기 조건을 전부 저장하므로, 트리 개수에 **비례해서** 파일이 커짐
  - GitHub는 50MB가 넘으면 경고하고 100MB를 넘으면 업로드를 막으므로, `.gitignore`에 `*.pkl`을 추가해 제외함
  - 모델 파일은 **코드가 아니라 결과물**이라 저장소에 올릴 필요가 없다는 것도 함께 정리함

- **AutoGluon에서 했던 것과 같은 일이었다**
  - 7주차에 AutoGluon을 쓸 때 `path="autogluon_churn_model"`로 저장하고 `TabularPredictor.load(model_path)`로 불러왔었음
  - 그때는 AutoGluon이 알아서 해주는 기능이라고만 생각했는데, sklearn 모델도 `joblib`으로 똑같이 할 수 있다는 걸 알게 됨
  - 차이점은 AutoGluon은 **폴더**에 여러 모델을 저장하고, joblib은 **파일 하나**에 모델 하나를 저장한다는 것

## 📅 2026-10-21 | 로지스틱 회귀 고도화와 특성 중요도 / Telco 고객 이탈

> 코드: [`telco_churn.py`](./telco_churn.py)

### 개념

**1. 로지스틱 회귀의 특성 중요도**
- 결정 트리 계열은 `feature_importances_`가 있지만, 로지스틱 회귀에는 없음
- 대신 `coef_`(기울기, 가중치)의 **절댓값**을 특성 중요도로 사용함
- 절댓값을 쓰는 이유: 부호는 방향(이탈을 높이는지 낮추는지)이고, 크기가 영향력이므로 영향력만 보려면 부호를 떼야 함
- `lr.coef_[0]` → 이진 분류는 직선이 하나뿐이라 `[0]`으로 꺼냄

**2. 로지스틱 회귀의 하이퍼파라미터 `C`**
- 규제의 강도를 조절하는 값
- **`C`가 작을수록 규제가 강함** → Ridge·Lasso의 `alpha`와 **반대 방향**
- `C=0.01`은 강한 규제, `C=100`은 거의 규제 없음

**3. `max_iter`**
- 최적의 직선을 찾기 위해 반복 계산하는 최대 횟수
- 횟수 안에 답을 못 찾으면 중간에 멈추고 경고를 띄움

### 왜 이렇게 코딩했는가

- `scoring="f1"`을 준 이유
  → 이탈 고객이 26.6%뿐인 불균형 데이터. 정확도로 탐색하면 다수인 "잔류"만 잘 맞히는 모델이 뽑힘
- 탐색이 고른 `C=100` 대신 `C=1`(기본값)로 모델을 하나 더 만들어 비교한 이유
  → 탐색 결과를 그대로 믿지 않고, **기본값과 실제로 차이가 나는지** 확인하기 위함
- Top5만 뽑아 시각화한 이유
  → One-Hot Encoding 후 특성이 45개라 전부 그리면 읽을 수 없음

### 막혔던 부분 / 이해 포인트

- **스케일링을 하지 않은 상태의 계수는 중요도 비교에 쓸 수 없다**
  - 오늘 뽑은 Top5는 `Contract_Two year`, `Contract_Month-to-month`, `InternetService_DSL`... 전부 One-Hot으로 만들어진 0/1 컬럼이었음
  - 이상해서 숫자형 컬럼이 몇 위인지 확인해보니
    - 스케일링 없음: **tenure 37위, MonthlyCharges 44위, TotalCharges 45위** (45개 중 꼴찌권)
    - 스케일링 적용: **tenure 1위(1.4776), TotalCharges 2위(0.7769)**
  - 순위가 완전히 뒤집힘
  - 이유는 컬럼마다 값의 범위가 다르기 때문
    - `tenure` 1~72, `MonthlyCharges` 18.25~118.75, `TotalCharges` 18.8~8684.8
    - One-Hot 컬럼은 전부 0 또는 1
  - 값이 큰 컬럼은 **계수가 작아도** 곱한 결과가 커지므로, 계수 크기만 비교하면 억울하게 밀려남
  - 10/07에 선형 회귀를 배울 때 "표준화의 목적은 성능이 아니라 `coef_`끼리 크기를 비교할 수 있게 만드는 것"이라고 정리했었는데, 그 말의 의미를 오늘 반대 사례로 확인함
  - **가입 기간(tenure)이 이탈의 1순위 요인인데 37위로 보고할 뻔했음**

- **`max_iter=500`을 줘도 수렴 경고가 사라지지 않았다**
  - 노트북 맨 위에서 `warnings.filterwarnings("ignore")`로 경고를 껐기 때문에 화면에는 안 보였음
  - 직접 경고를 켜고 돌려보니 "반복 횟수 한계에 도달했다, 데이터를 스케일링하는 것도 고려하라"는 메시지가 떠 있었음
  - 스케일링을 안 한 상태라 계산이 수렴하지 못한 것
  - **경고를 끄는 것과 문제가 해결되는 것은 다름**

- **고도화를 했는데 성능이 거의 그대로였다**
  - 기본 모델 → 정확도 0.8053, 클래스1 recall 0.54, f1 0.60
  - GridSearchCV best(C=100, max_iter=500) → 정확도 0.80, recall 0.55, f1 0.60
  - C를 기본값 1로 둔 모델 → 정확도 0.81, recall 0.55, f1 0.60
  - `C`를 1에서 100으로 **100배** 키웠는데 결과가 사실상 같음
  - 로지스틱 회귀는 모델 구조가 단순(직선 하나)해서 조절할 수 있는 폭 자체가 좁음
  - 트리 계열에서 `max_depth` 하나로 0.7193 → 0.7946이 바뀌었던 것과 대조됨
  - **모델마다 하이퍼파라미터 탐색으로 얻을 수 있는 이득의 크기가 다르다**

- **SVM이 평가용 1,407명 전원을 0으로 예측했다**
  - 정확도 0.7342가 나왔는데, 이건 베이스라인(전부 "잔류"라고 찍기)과 **소수점까지 똑같은 숫자**
  - 예측값의 고유값을 확인해보니 `[0]` 하나뿐이었고, 개수는 1407
  - 실제 이탈 고객 374명을 **한 명도** 찾지 못함
  - 원인은 이번 노트북에서 SVM에 스케일링을 적용하지 않았기 때문
  - 스케일링 후 다시 돌리니 정확도 0.7974, 이탈로 예측한 고객 263명
  - 어제 교재 5p에서 배운 "암 환자 5% 데이터에서 전부 정상이라고 찍어도 정확도 95%"가 바로 이 상황이었음

## 📅 2026-10-21 | 회귀 모델 성능 고도화 (RMSE 기반 탐색) / 보스턴 집값

> 코드: [`regression_tuning.py`](./regression_tuning.py)

### 개념

**1. 회귀 모델의 `scoring`: `neg_root_mean_squared_error`**
- 분류는 `accuracy`, `f1`처럼 **클수록 좋은** 지표를 씀
- 회귀의 RMSE는 **작을수록 좋은** 오차 값이라 방향이 반대
- sklearn은 모든 `scoring`을 "클수록 좋다"로 통일하기 위해 **오차에 음수를 붙임**
- 그래서 이름 앞에 `neg_`(negative)가 붙고, `best_score_`가 **음수로 출력됨**
- `-3.85`와 `-5.40`을 비교하면 **-3.85가 더 좋은 모델**(오차가 작으므로)

**2. 회귀에서는 `stratify`를 쓸 수 없다**
- 정답(`medv`)이 연속적인 숫자라 범주 비율을 유지하는 분할이 불가능
- 이 데이터는 고유값 229개 중 100개가 단 한 번만 등장해서 더욱 불가능

**3. `range()`로 탐색 범위 지정하기**
- 리스트를 일일이 쓰는 대신 `range(3, 21)`로 3~20까지 18개를 한 번에 지정할 수 있음
- RandomizedSearchCV와 함께 쓰면 범위를 넓게 잡아도 탐색 시간이 늘지 않음

### 왜 이렇게 코딩했는가

- DecisionTree에는 GridSearchCV, RandomForest에는 RandomizedSearchCV를 쓴 이유
  → 조합 수가 다름. DecisionTree는 18 × 4 = **72가지**라 전부 돌 만하지만, RandomForest는 5 × 28 × 4 = **560가지**라 전수 탐색이 무리
- RandomForest의 `n_iter`를 120으로 준 이유
  → 560가지 중 약 21%를 보는 설정. 전부 돌지 않으면서도 넓게 훑기 위함
- `root_mean_squared_error`를 `as rmse`로 줄여 쓰면서 결과는 `rmse_dt`, `rmse_rf`에 담은 이유
  → 10/07에 "별칭을 쓰면 `rmse = rmse(...)`로 함수가 덮어써져 다음 호출이 실패한다"고 정리했던 것을 피하기 위함. 변수명을 함수명과 다르게 지으면 별칭을 써도 안전함
- `warnings.filterwarnings("ignore")`를 맨 위에 둔 이유
  → 탐색 과정에서 같은 경고가 수백 번 반복 출력되어 결과를 가리기 때문

### 이해 포인트

- **`best_score_`가 음수로 나와서 당황했다**
  - DecisionTree `-3.8549`, RandomForest `-3.4897`
  - 처음엔 뭔가 잘못된 줄 알았는데, `neg_`가 붙은 지표라 음수가 정상
  - 실제 RMSE로 읽으려면 **부호만 떼면 됨**(3.85, 3.49)
  - sklearn이 "클수록 좋다"로 방향을 통일하려고 일부러 뒤집어 놓은 것

- **검증 점수와 평가 점수의 차이가 생각보다 크다**
  - DecisionTree: 검증 RMSE 3.85 → 평가 RMSE **5.398**
  - RandomForest: 검증 RMSE 3.49 → 평가 RMSE **4.324**
  - 둘 다 평가 쪽이 나쁨. 특히 DecisionTree는 1.5 가까이 벌어짐
  - 검증 점수는 **학습용 데이터를 5조각으로 나눠서** 잰 점수라, 결국 학습용 데이터 안에서의 성적임
  - 거기에 맞춰 고른 모델이 처음 보는 평가용 데이터에서는 덜 좋을 수 있음
  - 7주차에 AutoGluon의 leaderboard 점수 0.8126과 실제 평가 0.8003이 달랐던 것과 같은 현상
  - **최종 판단은 반드시 평가용 데이터로 해야 한다**

- **RandomForest의 best 모델 출력에 `n_estimators`가 안 보였다**
  - 출력이 `RandomForestRegressor(max_depth=10, min_samples_leaf=2, random_state=0)`
  - `n_estimators`를 [100, 200, 300, 400, 500]으로 탐색했는데 왜 안 보이는지 한참 찾음
  - sklearn은 **기본값과 같은 값은 출력에서 생략**함. `n_estimators`의 기본값이 100이므로, 100이 뽑혔다는 뜻
  - 트리를 500개까지 늘려봤지만 **100개가 가장 좋았다**는 의미이기도 함

- **지금까지의 집값 예측 성능 정리**
  - 선형 회귀 5.4573 / Lasso 5.9573 / Ridge 5.4639
  - 결정 트리(규제 없음) 5.4067 → **고도화 후 5.398**
  - 랜덤 포레스트(기본값) 4.0720 → **고도화 후 4.324**
  - XGBoost 4.2298 / 스태킹 4.1951
  - 랜덤 포레스트는 고도화를 했는데 오히려 나빠졌음(4.0720 → 4.324)
  - 기본값(`max_depth` 제한 없음)이 이 데이터에서는 더 맞았던 것 → **탐색 범위에 "제한 없음"이 빠져 있었기 때문**
