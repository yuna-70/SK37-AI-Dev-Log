# Module 2 - 딥러닝 (개요 / 퍼셉트론)

## 📅 2026-10-22 | 딥러닝 개요와 퍼셉트론 / XOR 난제와 다층 퍼셉트론

> 코드: [`perceptron.py`](./perceptron.py)

### 개념

**1. 딥러닝(Deep Learning)의 정의**
- 인간의 뇌 신경망 구조를 모방한 **인공신경망(Artificial Neural Network)** 을 기반으로, 대량의 데이터에서 **스스로 특징을 학습**하는 머신러닝의 한 분야
- 구조: 입력층(Input layer) → 은닉층(Hidden layer, 여러 개) → 출력층(Output layer)
- 인공지능 ⊃ 머신러닝 ⊃ 딥러닝

**2. 머신러닝과 딥러닝의 차이**
- 특징 추출: 머신러닝은 **사람이 직접 정의**(Feature Engineering) / 딥러닝은 **모델이 스스로 학습**
- 데이터 의존도: 머신러닝은 적은 데이터로도 유의미한 성능 / 딥러닝은 데이터가 많을수록 성능이 극대화됨
- 학습 시간: 머신러닝은 수 초~수 시간 / 딥러닝은 수 일~수 주 이상
- 연산 자원: 머신러닝은 CPU로 가능 / 딥러닝은 **GPU·TPU 등 병렬 연산 장치 필수**
- 대표 알고리즘: 결정 트리·로지스틱 회귀 / CNN·RNN·LSTM·Transformer·BERT

**3. 딥러닝 핵심 알고리즘**
- **CNN**(합성곱 신경망): 이미지의 **공간적 구조**를 유지하며 특징을 추출하는 필터 기반 알고리즘 → 컴퓨터 비전(이미지 분류, 객체 탐지)
- **RNN / LSTM**(순환 신경망): 데이터의 **순서와 시간 흐름**을 기억하기 위해 은닉층의 출력을 다시 입력으로 순환시키는 구조 → 시계열 예측, 초기 자연어 처리
- **Transformer / BERT**: 순환 신경망의 한계를 극복하고 문장 내 단어 간 관계를 **동시에** 파악하는 Self-Attention 기반 → 최신 거대 언어 모델(LLM)

**4. 딥러닝 프레임워크**
- **TensorFlow & Keras**(구글): 직관적인 코드 구조라 입문과 프로토타이핑에 유리
- **PyTorch**(메타): 글로벌 표준

**5. 퍼셉트론(perceptron)**
- 어원: perception(지각) + neuron(신경세포)
- 정의: **다수의 입력 신호를 받아 하나의 신호를 출력하는 인공 뉴런**
- 가중치(weight): 출력 신호를 낼지 말지 결정하기 위해 입력 신호에 곱하는 계수
- 입력 신호의 총합: `z = w₁x₁ + w₂x₂ + w₃x₃ + ... + wₙxₙ + b`

**6. 퍼셉트론의 수학적 정의 — 임계값(θ)에서 편향(b)으로**
- 원래 식: 입력의 가중합이 **임계값 θ** 이상이면 1, 미만이면 0
  - `w₁x₁ + w₂x₂ >= θ` → 1
- θ를 좌변으로 넘기면: `-θ + w₁x₁ + w₂x₂ >= 0` → 1
- `-θ`를 **편향(bias) b**로 바꿔 부름: `b + w₁x₁ + w₂x₂ >= 0` → 1
- 즉 **편향은 임계값의 부호를 바꾼 것**이며, 현대 연산 표준에 맞춰 이렇게 정의함

**7. 퍼셉트론의 정체**
- 결국 0이냐 1이냐를 맞추는 **이진 분류기**
- `w₁x₁ + w₂x₂ + b = 0`이 **결정 경계(Decision Boundary)** 로 작동하는 **선형 분류 모델**

**8. 퍼셉트론의 의의**
- 딥러닝의 **빌딩 블록**: 벽돌 하나하나가 모여 빌딩을 이루듯, 퍼셉트론 수십억 개가 연결된 것이 현대의 심층신경망
- 퍼셉트론 하나의 작동을 모르면 CNN이나 Transformer의 연산 과정을 이해할 수 없음

**9. 논리 게이트(Logic Gate)**
- 컴퓨터의 두뇌(CPU)를 구성하는 가장 작은 단위의 '스위치'
- 입력이 특정 조건을 만족할 때만 신호를 통과시키거나 차단하므로 '논리' 게이트
- '게이트(문)'라고 부르는 이유: 수문처럼 신호를 흐르게 할지(1) 멈추게 할지(0) 결정하기 때문
- 종류
  - **AND**(논리곱): 모든 입력이 1일 때만 1
  - **OR**(논리합): 입력 중 하나라도 1이면 1
  - **NAND**(부정논리곱): AND를 뒤집은 것. 모든 입력이 1일 때만 0
  - **XOR**(배타적논리합): 입력값이 **서로 다를 때만** 1

**10. 퍼셉트론으로 구현한 AND / OR 게이트**
- AND: `0.5x₁ + 0.5x₂ - 0.7 = 0`
- OR: `0.5x₁ + 0.5x₂ - 0.2 = 0`
- 가중치는 같고 **편향만 다름**

**11. 선형 분리 가능과 불가능**
- **선형 분리 가능**: AND, NAND, OR는 네 가지 입력 조합을 평면에 점으로 찍었을 때 **직선 하나**로 0인 영역과 1인 영역을 완벽히 나눌 수 있음
- **선형 분리 불가능**: XOR는 (0,0)과 (1,1)에 0이, (1,0)과 (0,1)에 1이 **대각선으로 엇갈려** 있어 직선 하나로 절대 나눌 수 없음
- 퍼셉트론 식 `w₁x₁ + w₂x₂ + b = 0`이 수학적으로 **직선의 방정식**이므로, 퍼셉트론 하나로는 XOR를 구조적으로 해결할 수 없음

**12. XOR 문제와 제1차 AI 겨울**
- 1969년 마빈 민스키 교수가 저서 《퍼셉트론(Perceptrons)》에서 "단층 퍼셉트론은 XOR조차 풀 수 없으며, 층을 쌓아도 학습시킬 방법은 존재하지 않는다"고 수학적으로 비판
- 이 학술적 사망 선고로 전 세계의 인공지능 연구 지원이 끊기고 **약 20년간 암흑기**에 빠짐
- 훗날 연구자들이 층을 여러 개 쌓는 **다층 퍼셉트론(MLP)** 과 오차를 뒤로 보내며 스스로 매개변수를 고치는 **오차역전파** 알고리즘으로 이 난제를 극복
- XOR 문제는 인공지능을 한 번 죽였다가 현대의 '심층(Deep)' 신경망으로 부활시킨 **터닝 포인트**

**13. 다층 퍼셉트론(MLP)으로 XOR 해결하기**
- 출력층 앞에 **은닉층(Hidden Layer)** 을 도입 → 입력층 → 은닉층 → 출력층의 다층 구조
- 게이트의 유기적 조합
  - 은닉층 노드 1(h₁): 입력에 대해 **NAND** 연산
  - 은닉층 노드 2(h₂): 입력에 대해 **OR** 연산
  - 출력층 노드(y): h₁과 h₂를 입력받아 **AND** 연산
- 흐름: `Input(x₁, x₂) → {NAND → h₁, OR → h₂} → AND(h₁, h₂) → Output(y)`

### 왜 이렇게 코딩했는가

- AND와 OR의 가중치를 둘 다 `0.5, 0.5`로 똑같이 둔 이유
  → 두 입력 `x₁`, `x₂`를 **동등하게 취급**하기 위함. 어느 한쪽이 더 중요한 게 아니라 "둘 다 1인가 / 하나라도 1인가"만 따지는 문제이므로 가중치를 같게 둠
- 편향만 `-0.7`과 `-0.2`로 다르게 준 이유
  → 가중치가 같으면 직선의 기울기가 같고, 편향이 직선의 **위치**를 정함. AND는 `0.5 + 0.5 = 1.0`일 때만 넘는 높은 문턱(0.7)이 필요하고, OR는 `0.5` 하나로도 넘는 낮은 문턱(0.2)이 필요하기 때문
- NAND를 따로 설계하지 않고 AND의 **부호만 뒤집어** 만드는 이유
  → NAND는 AND의 결과를 반대로 뒤집은 것이므로, `w₁=-0.5, w₂=-0.5, b=0.7`처럼 부호만 바꾸면 결정 경계의 **방향이 반대로** 되어 0과 1이 자동으로 뒤바뀜
- XOR을 만들 때 하필 **NAND와 OR**을 은닉층에 둔 이유
  → XOR은 "하나라도 1이면서(OR), 둘 다 1은 아닌(NAND)" 경우에 1임. 이 두 조건을 각각 노드로 만들고 **AND로 묶으면** 정확히 XOR이 됨. 즉 사람이 XOR의 의미를 분해해서 게이트에 나눠 맡긴 것
- 임계값 `θ` 대신 편향 `b`를 쓰도록 식을 고쳐 쓰는 이유
  → `θ`는 부등호 오른쪽에 따로 있어서 가중치들과 다루는 방식이 다름. `-θ`를 `b`로 바꿔 왼쪽으로 옮기면 **모든 항이 한쪽에 모여** `w·x + b` 형태가 되므로, 코드에서 배열 연산 한 번으로 처리할 수 있음

### 막혔던 부분 / 이해 포인트

- **퍼셉트론 식이 다중 선형 회귀 식과 똑같다**
  - 퍼셉트론: `z = w₁x₁ + w₂x₂ + ... + wₙxₙ + b`
  - 10/07에 배운 다중 선형 회귀: `y = w₁x₁ + w₂x₂ + ... + wₚxₚ + b`
  - 글자만 다르고 완전히 같은 식
  - 차이는 **그 다음**에 있음. 선형 회귀는 이 값을 그대로 예측값으로 쓰지만, 퍼셉트론은 **0 이상이냐 아니냐로 0/1을 출력**함
  - 교재 10p가 퍼셉트론을 "결정 경계로 작동하는 선형 분류 모델"이라고 정의한 것도, 10/08에 배운 로지스틱 회귀의 설명과 같음
  - **퍼셉트론 하나 = 지금까지 배운 선형 모델 하나**였고, 딥러닝은 이걸 수십억 개 쌓은 것

- **편향(b)은 "문턱의 높이"다**
  - 가중치는 직선의 **기울기(방향)**, 편향은 직선의 **위치**를 정함
  - 교재의 가중치로 직접 계산해서 확인한 내용
    - AND는 문턱이 0.7이라 `0.5 + 0.5 = 1.0`일 때만 넘음 → 둘 다 1이어야 통과
    - OR는 문턱이 0.2로 낮아서 `0.5` 하나만으로도 넘음 → 하나만 1이어도 통과
  - **편향을 낮추면 뉴런이 쉽게 활성화되고, 높이면 까다로워진다**

- **XOR이 "안 되는" 게 아니라 "구조적으로 불가능"하다**
  - 처음엔 가중치를 잘 고르면 되지 않을까 싶었는데, 교재는 "절대 해결할 수 없다"고 단정함
  - 확인해보려고 `w₁`, `w₂`, `b`를 -2.0부터 2.0까지 0.1 간격으로 바꿔가며 **68,921가지 조합**을 전부 시도해봄
  - XOR 진리표 `[0, 1, 1, 0]`을 만드는 조합은 **0개**
  - 가중치를 못 찾은 게 아니라, 직선 하나로는 애초에 나눌 수 없는 배치라는 뜻
  - 이것이 20년간 연구가 멈춘 이유였음

- **MLP의 진리표를 손으로 따라가 보니 이해됨**
  - 교재의 가중치로 직접 계산해서 확인함
    - `(0,0)` → h₁(NAND)=1, h₂(OR)=0 → AND(1,0)=**0**
    - `(1,0)` → h₁=1, h₂=1 → AND(1,1)=**1**
    - `(0,1)` → h₁=1, h₂=1 → AND(1,1)=**1**
    - `(1,1)` → h₁=0, h₂=1 → AND(0,1)=**0**
  - 결과 `[0, 1, 1, 0]`으로 XOR과 정확히 일치
  - 핵심은 **은닉층이 입력을 새로운 좌표로 바꿔놓는다**는 것. 원래 공간에서는 직선으로 못 나누던 점들이 (h₁, h₂) 공간으로 옮겨지면 직선 하나로 나눠짐
  - "층을 쌓는다"는 말이 단순히 계산을 여러 번 한다는 뜻이 아니라, **데이터를 나눌 수 있는 형태로 바꾼다**는 뜻임을 알게 됨

- **딥러닝에서 GPU가 필수인 이유**
  - 교재 5p에 "GPU/TPU 등 병렬 연산 장치 필수"라고만 적혀 있어서 왜인지 궁금했음
  - 퍼셉트론 하나는 곱셈과 덧셈 몇 번이라 아주 가벼운데, 심층신경망은 이게 **수십억 개**가 동시에 들어감
  - 서로 독립적인 계산이 엄청나게 많으므로, 적은 코어로 빠르게 처리하는 CPU보다 **많은 코어로 동시에 처리하는 GPU**가 유리함

## 📅 2026-10-23 | 퍼셉트론 구현과 논리 게이트 / NumPy 배열 연산

> 코드: [`perceptron.py`](./perceptron.py)

### 개념

**1. 퍼셉트론을 NumPy로 구현하는 방법**
- 입력 신호 `x₁, x₂`를 `np.array([x1, x2])`로 묶음
- 가중치도 `np.array([0.5, 0.5])`로 묶음
- `x * w` → 같은 위치의 원소끼리 곱해진 배열이 나옴
- `np.sum(x * w) + b` → 입력 신호의 총합 `w₁x₁ + w₂x₂ + b`가 한 줄로 계산됨

**2. 게이트별 가중치와 편향**
- AND: `w = [0.5, 0.5]`, `b = -0.7`
- NAND: `w = [-0.5, -0.5]`, `b = 0.7` (AND와 부호가 정반대)
- OR: `w = [0.5, 0.5]`, `b = -0.2` (AND와 가중치는 같고 편향만 다름)

**3. XOR 구현 — 다층 퍼셉트론**
- 은닉층: 입력을 NAND와 OR 두 게이트로 **병렬** 처리 → `s1`, `s2`
- 출력층: 은닉층의 결과를 AND로 조합 → 최종 출력
- 이미 만든 함수 세 개를 불러 쓰는 것만으로 XOR이 완성됨

### 왜 이렇게 코딩했는가

- 입력과 가중치를 파이썬 변수가 아니라 **NumPy 배열**로 만든 이유
  → 입력이 2개일 때는 `w1*x1 + w2*x2`로 써도 되지만, 입력이 784개(손글씨 이미지)가 되면 불가능함. 배열로 묶으면 **개수와 상관없이 같은 코드**가 동작함
- `if output >= 0: return 1` 부분을 각 게이트 함수 안에 넣은 이유
  → 퍼셉트론은 총합을 구하는 것으로 끝나지 않고 **0이냐 1이냐를 출력**해야 완성되기 때문. (이 조건문이 사실은 '계단 함수'라는 걸 활성화 함수를 배우면서 알게 됨)
- NAND를 AND와 **부호만 반대로** 만든 이유
  → NAND는 AND의 결과를 뒤집은 것이므로, 결정 경계의 방향을 반대로 돌리면 0과 1이 자동으로 뒤바뀜
- XOR을 새로 설계하지 않고 **기존 게이트 세 개를 호출**한 이유
  → 다층 퍼셉트론의 핵심이 "새로운 수식을 만드는 것"이 아니라 "**이미 있는 뉴런을 층으로 쌓는 것**"임을 코드로 보여주기 위함
- `inputs = [(0, 0), (1, 0), (0, 1), (1, 1)]`로 네 조합을 미리 만들어 둔 이유
  → 게이트 네 개를 전부 같은 입력으로 검사해야 진리표를 비교할 수 있기 때문

### 막혔던 부분 / 이해 포인트

- **`x * w`와 행렬 곱은 다르다**
  - `np.array([0, 1]) * np.array([0.5, 0.5])` → `[0. , 0.5]`
  - 같은 위치의 원소끼리 곱한 **배열**이 나오지, 하나의 숫자가 나오는 게 아님
  - 그래서 `np.sum()`으로 한 번 더 더해야 입력 신호의 총합이 됨
  - 이 "곱하고 더하기"를 한 번에 하는 것이 교재 31p의 **행렬 내적**

- **처음에 편향을 `b = 0.7`로 썼다가 결과가 전부 뒤집혔다**
  - AND 게이트인데 `(0,0)`에서 1이 나옴
  - 원인은 편향의 부호. 임계값 `θ = 0.7`을 그대로 쓴 것이고, 편향은 `-θ`이므로 `-0.7`이 맞음
  - 어제 정리한 `-θ + w₁x₁ + w₂x₂ >= 0` 유도를 코드에 옮길 때 **부호를 빠뜨린 것**
  - 편향은 임계값과 **부호가 반대**라는 걸 틀려보고 나서 확실히 기억하게 됨

## 📅 2026-10-23 | 활성화 함수 (계단·시그모이드·ReLU·소프트맥스)와 출력층 설계

> 코드: [`activation_functions.py`](./activation_functions.py)

### 개념

**1. 활성화 함수(Activation Function)의 정의**
- 입력 신호의 총합(`w₁x₁ + w₂x₂ + b`)을 받아, **다음 뉴런으로 보낼 출력 신호의 형태로 변환**하고 결정하는 함수
- 어제 퍼셉트론에서 결과를 0 또는 1로 바꿔주던 **조건문이 바로 활성화 함수의 한 종류**(계단 함수)였음

**2. 활성화 함수가 반드시 필요한 이유**
- **'망'의 깊이(Deep)를 의미 있게 만드는 수학적 열쇠**
  - 퍼셉트론의 내부 연산은 본질적으로 공간에 곧은 선을 긋는 **선형 연산**
  - 활성화 함수 없이 층만 깊게 쌓으면, 수백 층을 쌓아도 결국 **하나의 큰 선형 함수**가 됨
  - `y = w(wx + b) + b` → `y = w²x + wb + b` → `y = Wx + B`
  - 퍼셉트론이라는 '직선 자'를 유연하게 **구부리는 도구**가 활성화 함수
- **복잡한 비선형 데이터(이미지, 텍스트)의 처리**
  - 현실 데이터를 숫자 배열로 바꿔 공간에 표현하면 직선으로 나눌 수 없는 꼬인 분포를 가짐
  - 직선 신호를 구부리고 꺾어 '곡면 경계선'을 만들어야 분류가 가능해짐

**3. 계단 함수(Step Function)**
- 입력값이 0을 넘으면 1, 0 이하면 0을 출력하는 가장 기본적인 활성화 함수
- 전통적인 단층 퍼셉트론으로 AND/OR/NAND를 풀 때 쓴 이분법적 방식
- **한계점 — 딥러닝 적용 불가**
  - 불연속성: 출력이 0과 1뿐이라 '모 아니면 도'. 중간의 미세한 오차 변화를 반영할 수 없음
  - **미분 불가능**: 0인 지점에서 뚝 끊겨 미분이 안 되고, 나머지 구간은 평평해서 기울기가 완전히 0
  - 오차 수정 불가능: 현대 딥러닝은 기울기를 구해 가중치를 고치는 **경사하강법**을 쓰는데, 기울기가 0이면 학습할 방법이 없음

**4. 시그모이드 함수(Sigmoid Function)**
- `h(x) = 1 / (1 + e⁻ˣ)`
- 계단 함수의 거친 불연속성을 보완해 출력이 **S자 곡선**으로 부드럽게 변함
- 의의
  - 연속적인 '정답 확률' 표현: 출력이 0~1 사이 실수라 "해당 클래스일 확률"로 해석 가능
  - 모든 구간에서 **매끄러운 미분**이 가능 → 오차역전파의 기틀
- **한계점 — 포화(Saturation)와 기울기 소실(Vanishing Gradient)**
  - 입력값이 너무 크거나 작으면 곡선이 평평해져 기울기가 다시 0에 수렴
  - 층이 깊어지면 역전파 과정에서 기울기가 앞으로 전달되지 못하고 **도중에 사라짐**

**5. ReLU 함수**
- `R(z) = max(0, z)` — 0을 넘으면 그대로 통과, 0 이하면 0으로 차단
- **현대 딥러닝의 사실상 표준인 이유**
  - 경사 소실 해결: 입력이 양수이기만 하면 기울기가 **항상 정확히 1**로 유지됨 → 수백 층을 쌓아도 기울기가 죽지 않고 초기 레이어까지 전달됨
  - 압도적인 연산 속도: 시그모이드처럼 지수 연산을 할 필요 없이 **0보다 큰지만 비교**하면 됨

**6. 다차원 배열의 계산 — 행렬 곱 / 벡터 내적**
- 행렬 곱의 모양 규칙: `(m, k) × (k, n) = (m, n)`
- 앞 행렬의 **열 개수**와 뒤 행렬의 **행 개수**가 같아야 계산이 됨

**7. 신경망 Layer와 행렬 내적**
- 퍼셉트론 하나는 개별 수식으로 계산할 수 있지만, 뉴런이 많아지면 연산이 비효율적
- 입력값과 가중치를 각각 **행렬로 묶으면 단 한 번의 행렬 곱셈으로 층 전체의 계산**이 끝남
- 신경망의 연산 공식: **`Y = X · W + B`**
  - 예: `X(1,2) × W(2,3) + B(3,) = Y(1,3)`

**8. 출력층(Output Layer)의 역할**
- 인공신경망의 마지막 단계로, 은닉층들을 거쳐 흘러온 신호를 종합해 **최종 예측 결과물**을 생성
- 문제 유형에 따라 출력층의 **활성화 함수와 노드 구조가 완전히 달라짐**

**9. 문제 유형에 따른 출력층 매핑 규칙**
- **회귀** → **항등 함수**(Identity Function): `f(x) = x`. 연속적인 수치를 왜곡 없이 그대로 출력
- **이진 분류** → **시그모이드 함수**: 둘 중 하나를 판별해 '정답일 확률'을 도출
- **다중 클래스 분류** → **소프트맥스 함수**: 세 개 이상의 후보군 중 가장 정답 같은 대상을 맞힘

**10. 소프트맥스 함수**
- `yₖ = exp(aₖ) / Σ exp(aᵢ)`
- 각 노드의 지수 함수 값을 전체 노드 지수 함수의 총합으로 나눠 비율을 정규화
- **2대 핵심 특성**
  - 출력값 범위의 정규화: 원본 점수가 아무리 크거나 작아도 항상 **0과 1 사이**
  - **총합의 법칙**: 모든 출력값을 더하면 반드시 **1(100%)**
  - 덕분에 모델의 출력을 하나의 **확률 분포**로 해석할 수 있음

**11. 출력층의 뉴런 수 정하기(Design Rule)**
- 출력층의 뉴런 개수는 **풀고자 하는 문제의 클래스 개수와 일치**시켜야 함
- 이진 분류(스팸 판별): 뉴런 1개 + 시그모이드
- 다중 분류(MNIST 0~9): 뉴런 10개 + 소프트맥스
- 회귀(주택 가격 예측): 뉴런 1개 + 항등 함수(또는 없음)

### 왜 이렇게 코딩했는가

- 인공 뉴런 함수(`perceptron`)와 활성화 함수를 **따로 정의**한 이유
  → 어제 만든 `AND()`는 총합 계산과 0/1 변환이 한 함수 안에 섞여 있었음. 분리해두면 **같은 뉴런에 다른 활성화 함수를 갈아 끼워** 결과를 비교할 수 있음. 실제로 `perceptron` 하나에 계단 함수와 시그모이드를 번갈아 연결해봄
- `np.where(x >= 0, 1, 0)`로 계단 함수를 만든 이유
  → `if`문은 숫자 하나만 처리하지만, `np.where`는 **배열 전체를 한 번에** 처리함. 은닉층 뉴런이 수백 개일 때 반복문 없이 끝남
- ReLU를 `np.maximum(0, x)`로 구현한 이유
  → `max()`는 값 두 개 중 큰 것 하나를 고르지만, `np.maximum()`은 **배열의 각 원소마다** 0과 비교해서 큰 쪽을 남김
- ReLU 입력을 `[-5.0, -2.0, -0.5, 0.0, 0.5, 2.0, 5.0]`처럼 **가상으로** 만든 이유
  → ReLU는 은닉층에서 쓰는 함수인데 아직 은닉층을 만들지 않았으므로, 은닉층 뉴런 7개가 내보낸 값이라고 가정하고 동작만 확인함
- 소프트맥스에서 분자와 분모를 **변수로 나눠** 쓴 이유
  → `np.exp(arr) / np.sum(np.exp(arr))` 한 줄로도 되지만, 분자는 '각 뉴런별 계산', 분모는 '전체의 합'이라는 역할이 다름. 나눠 쓰면 수식과 코드가 1:1로 대응됨

### 이해 포인트

- **출력에 `-0.19999999999999996`이 찍혀서 당황했다**
  - `0.5 + (-0.7)`인데 `-0.2`가 아니라 `-0.19999999999999996`이 나옴
  - 컴퓨터는 0.7을 2진수로 **정확히 표현할 수 없어서** 실제로는 `0.69999999999999995559`로 저장함
  - 확인해보니 파이썬에서 `(0.5 - 0.7) == -0.2`는 **False**
  - 계단 함수가 `>= 0`으로 판정하므로 결과에는 영향이 없었지만, **실수 비교를 `==`로 하면 안 된다**는 걸 알게 됨

- **계단 함수의 경계값 처리가 교재와 내 코드가 다르다**
  - 교재 24p: `h(x) = 0 (x ≤ 0), 1 (x > 0)` → **0일 때 0**
  - 내 코드: `np.where(x >= 0, 1, 0)` → **0일 때 1**
  - 입력 `[-0.5, 0.0, 0.5]`로 확인해보니
    - 교재 방식: `[0, 0, 1]`
    - 내 방식: `[0, 1, 1]`
  - AND 게이트에서는 총합이 정확히 0이 되는 경우가 없어서 결과가 같았지만, **경계에 딱 걸리면 달라짐**
  - 어느 쪽이 틀린 건 아니고 정의하기 나름이지만, 기준을 정했으면 **일관되게** 써야 함

- **활성화 함수 없이 층을 쌓으면 정말 한 층과 같아진다**
  - 교재 23p의 `y = w(wx+b)+b → y = Wx + B` 설명을 직접 확인해봄
  - 2층짜리 신경망을 활성화 함수 없이 통과시킨 결과: `[1.02, 2.29]`
  - 두 층의 가중치를 **하나의 행렬로 미리 합쳐서**(`W1 @ W2`) 한 번에 계산한 결과: `[1.02, 2.29]`
  - 완전히 동일함
  - 즉 활성화 함수가 없으면 **층을 아무리 쌓아도 계산량만 늘고 표현력은 그대로**
  - "Deep"이 의미를 가지려면 층 사이마다 비선형 변환이 꼭 끼어야 한다는 걸 숫자로 확인함

- **시그모이드의 기울기 소실을 숫자로 보니 체감이 달랐다**
  - 시그모이드의 기울기는 `σ(z) × (1 - σ(z))`
    - `z = 0` → 기울기 **0.25**
    - `z = 2` → 0.105
    - `z = 5` → 0.0066
    - `z = 10` → **0.0000454**
  - `z=10`일 때 기울기가 `z=0`의 **약 1/5,500**
  - 층이 깊어지면 역전파에서 이 작은 값들이 계속 곱해지므로 기울기가 사실상 0이 됨
  - ReLU는 양수 구간에서 기울기가 **항상 1**이라 아무리 곱해도 1 → 이게 "경사 소실을 완벽히 해결"한다는 말의 의미

- **소프트맥스는 점수 차이를 확률 차이로 크게 벌린다**
  - 입력 `[0.3, 2.9, 4.0]` → 출력 `[0.0182, 0.2452, 0.7366]`
  - 합계는 정확히 **1.0**
  - 원본 점수 차이는 `4.0 - 0.3 = 3.7`인데, 확률은 `0.7366 / 0.0182 = 약 40배` 차이
  - 지수 함수(`exp`)를 거치기 때문에 작은 점수 차이가 **크게 증폭**됨
  - 그래서 모델이 "이게 정답"이라고 확신 있게 고를 수 있음

- **시그모이드가 두 번 나오는데 쓰임새가 다르다**
  - 교재 26p에서는 **은닉층**의 활성화 함수로 나옴 (계단 함수의 대안)
  - 교재 37p에서는 **출력층**의 활성화 함수로 나옴 (이진 분류의 확률)
  - 같은 함수인데 위치에 따라 역할이 다름
    - 은닉층: 신호를 구부려 다음 층으로 넘김
    - 출력층: 최종 결과를 "확률"로 해석하게 만듦
  - 10/08에 배운 **로지스틱 회귀의 시그모이드**는 이 중 출력층 쪽과 같은 역할이었음

## 📅 2026-10-26 | 손실 함수 (MSE·교차 엔트로피)와 배치 학습

> 코드: [`loss_functions.py`](./loss_functions.py)

### 개념

**1. 손실(Loss)의 본질**
- 모델이 예측한 값(y)과 실제 정답 레이블(t) 사이의 **거리이자 차이의 크기**
- 발생 원인: 신경망 내부의 가중치(W)와 편향(b)이 아직 데이터에 최적화되지 않았기 때문

**2. 손실 함수(Loss Function)의 역할**
- **'나쁨'의 지표**: 모델의 현재 성능이 얼마나 나쁜가를 정량적으로 나타냄. 수많은 오차를 **단 하나의 스칼라(실수) 값**으로 계산해냄
- **딥러닝의 궁극적 목적**: 이 손실 함수의 출력값을 최소화(0에 가깝게) 만드는 최적의 가중치 조합을 찾는 것. 이것이 '학습(Learning)'의 본질

**3. 회귀 문제의 손실 함수 — 평균 제곱 오차(MSE)**
- `E = (1/n) Σ(yᵢ - tᵢ)²`
- 예측값과 정답의 차이를 **제곱하여 모두 더한 뒤 평균**을 냄
- '제곱' 연산이 가지는 의미
  - **부호의 제거**: 오차가 양수든 음수든 모두 양수화해서 순수한 크기만 반영
  - **큰 오차에 대한 강력한 페널티**: 오차가 클수록 손실이 기하급수적으로 커져, 치명적인 에러를 내지 않도록 제어

**4. 분류 문제의 손실 함수 — 교차 엔트로피 오차(CEE)**
- `E = -Σ tₖ log(yₖ)`
- 정답 레이블의 분포와 모델이 예측한 확률 분포 사이의 **수학적 거리**를 계산
- `yₖ`: 소프트맥스를 통과한 예측 확률 (0 < yₖ < 1)
- `tₖ`: 원-핫 인코딩된 정답 레이블 (정답만 1, 오답은 모두 0)

**5. 이진 분류의 교차 엔트로피(BCE)**
- `H(y, p) = -y·log(p) - (1-y)·log(1-p)`
- `y`: 실제 정답(0 또는 1), `p`: 시그모이드를 통과한 예측 확률
- 정답이 1이면 뒷항이 사라져 `-log(p)`만 남고, 정답이 0이면 앞항이 사라져 `-log(1-p)`만 남음

**6. 배치 학습(Batch Learning)**
- 전체 데이터 N개의 손실을 몽땅 구한 뒤 평균 손실로 매개변수를 **딱 1번** 업데이트
- 한계: 데이터가 수백만 개면 메모리가 버티지 못하거나 한 번 업데이트에 시간이 너무 오래 걸림

**7. 미니배치 학습(Mini-batch Learning)**
- 전체 N개 중 임의의 작은 묶음 n개(배치 크기)를 무작위로 추출해 그 평균 손실로 매개변수를 업데이트
- `N/n`번 반복해서 전체 데이터를 한 바퀴 돌면 **1 에포크(epoch)** 완료
- 마지막에 딱 맞아떨어지지 않고 남은 묶음이 있으면 그 개수만큼의 평균 손실로 최종 업데이트

### 왜 이렇게 코딩했는가

- 손실 함수의 인자 순서를 `(t, y)`로 통일한 이유
  → 세 함수(MSE·CEE·BCE)를 모두 **정답 먼저, 예측 나중**으로 맞춰두면 나중에 갈아 끼울 때 헷갈리지 않음. `accuracy_score(y_test, pred)`처럼 sklearn도 정답이 먼저임
- 좋은 예측과 나쁜 예측을 **쌍으로** 만든 이유
  → 손실값은 절대적인 기준이 없어서 숫자 하나만 보면 좋은지 나쁜지 알 수 없음. 두 경우를 나란히 계산해야 "손실이 작을수록 좋은 모델"이라는 게 눈에 보임
- CEE에서 `np.sum`을 쓴 이유
  → 수식 `-Σ tₖ log(yₖ)`가 클래스 전체를 더하는 형태라서. 다만 정답이 원-핫이라 **정답 위치만 1이고 나머지는 0**이므로, 실제로는 정답 위치의 `-log(확률)` 하나만 남음
- 회귀용 정답과 이진 분류용 정답의 변수명을 `target_reg`, `target_binary`로 나눈 이유
  → 둘 다 `target`으로 쓰면 아래 셀이 위 셀의 값을 덮어씀. 노트북은 셀을 순서대로 실행하지 않을 수 있어서 **같은 이름을 재사용하면 위험**함

### 막혔던 부분 / 이해 포인트

- **MSE에 평균이 빠져 있었다**
  - 처음에 `return (t - y)**2`로 작성했는데, 이름은 '평균' 제곱 오차인데 평균을 구하지 않음
  - 예제가 숫자 하나씩이라 결과가 같아서 모르고 넘어갈 뻔함
  - 배열 3개를 넣어 확인해보니
    - 평균 없음: `[0.04, 1.0, 0.25]` ← **배열**이 나옴
    - 평균 있음: `0.4300` ← 실수 하나
  - 교재 41p가 손실 함수를 "단 하나의 스칼라 값으로 계산해낸다"고 정의했는데, 평균이 빠지면 그 정의 자체가 깨짐
  - `np.mean()`을 추가해서 수정함

- **CEE와 BCE 결과가 전부 `-log(확률)`이었다**
  - CEE 모델1 `0.5108` = `-log(0.6)`
  - CEE 모델2 `2.9957` = `-log(0.05)`
  - BCE 모델1 `0.2231` = `-log(0.8)`
  - BCE 모델2 `1.6094` = `-log(0.2)`
  - 수식은 복잡해 보이지만 정답이 원-핫(또는 0/1)이라 **정답 자리의 확률 하나만 남는 구조**
  - 결국 "정답에 몇 %의 확신을 줬는가"만 보는 셈

- **확률이 0에 가까워지면 손실이 폭발한다**
  - 예측 확률 0.5 → 손실 0.69
  - 0.1 → 2.30
  - 0.01 → 4.61
  - 0.0001 → **9.21**
  - `log`는 0에 가까워질수록 음의 무한대로 가므로, 정답에 거의 0을 준 모델은 **엄청나게 큰 벌점**을 받음
  - MSE의 '제곱'이 큰 오차에 페널티를 주는 것과 같은 역할을 `log`가 하고 있음
  - 다만 확률이 정확히 0이면 `log(0)`이 되어 계산이 불가능해지는데, 실무에서는 아주 작은 값을 더해 막는다고 함

## 📅 2026-10-26 | 수치 미분과 경사하강법 / 가중치 업데이트

> 코드: [`numerical_diff.py`](./numerical_diff.py)

### 개념

**1. 미분의 정의**
- 독립변수의 미세한 변화에 대해 함수 값이 **얼마나 민감하게 변하는지**를 나타내는 '순간 변화율'
- 기하학적으로는 함수 그래프 위 한 점에서의 **접선의 기울기**

**2. 딥러닝에서 미분이 필요한 이유**
- 최종 목표는 손실 함수의 값을 0에 가깝게 줄이는 최적의 가중치(W)를 찾는 것
- "특정 가중치를 아주 조금 바꿨을 때 손실이 **늘어나는가 줄어드는가**"를 판별하는 유일한 도구가 미분(기울기)
- 미분값(기울기)이 **양수(+)면 가중치를 (-) 방향**으로 조절
- 미분값(기울기)이 **음수(-)면 가중치를 (+) 방향**으로 조절

**3. 해석적 미분 vs 수치 미분**
- **해석적 미분**: 수학 공식을 사용(`x² → 2x`). 오차가 없지만, 복잡한 딥러닝 수식마다 컴퓨터가 공식을 적용하기엔 한계가 있음
- **수치 미분**: 아주 미세한 차이(h)를 대입해 근사치로 기울기를 구함. 컴퓨터가 단순 반복 연산으로 고속 처리하기에 최적화됨
- 수치 미분 공식(중앙 차분): `f'(x) ≈ (f(x+h) - f(x-h)) / 2h`

**4. 편미분(Partial Derivative)**
- 입력 변수가 여러 개인 함수에서 **관심 있는 하나의 변수만 미분하고, 나머지는 상수로 취급**하는 방식
- 기호는 `d` 대신 `∂`(라운드)를 씀
- 딥러닝에서의 의의
  - 손실 함수는 수천만~수천억 개의 가중치로 얽혀 있음
  - 그중 `w₁` 하나만 미세하게 조정했을 때 오차가 어떻게 변하는지 알기 위해 편미분을 씀
  - 각 가중치별 편미분을 모두 구해 **1차원 배열로 묶은 것이 기울기(Gradient)**

**5. 경사하강법과 가중치 업데이트 공식**
- 종속 변수: 손실 함수 `L` (단 하나의 실수 값)
- 독립 변수: 가중치 행렬 `W`, 편향 `b`
- **`W_new = W_old - η · ∂L/∂W`**
- `∂L/∂W`: 가중치가 손실에 미치는 순간 변화율인 기울기 행렬
- `η`(에타, 학습률): 한 걸음에 얼마나 수정할지 결정하는 **보폭**
- 기울기의 **정반대 방향**으로 수정하므로 공식에 마이너스가 붙음

### 왜 이렇게 코딩했는가

- 미분 함수를 `numerical_diff(f, x)`로 **함수를 인자로 받게** 만든 이유
  → 미분 대상이 바뀔 때마다 새로 짜지 않기 위함. 파이썬은 함수를 다른 함수의 입력으로 넘길 수 있어서, `function` 자리에 어떤 함수를 넣어도 같은 코드가 동작함
- `(f(x+h) - f(x)) / h`가 아니라 **`(f(x+h) - f(x-h)) / 2h`** 를 쓴 이유
  → 앞쪽만 보는 것(전진 차분)보다 **양쪽을 다 보는 것**(중앙 차분)이 참값에 훨씬 가까움. 실제로 확인해보니 오차가 1억 배 이상 차이 남
- `h = 0.0001`로 정한 이유
  → 너무 크면 근사가 부정확하고, 너무 작으면 컴퓨터의 반올림 오차 때문에 오히려 나빠짐. 그 사이의 적절한 값
- 해석적 미분(`2 * target_x`)을 **함께 출력한** 이유
  → 수치 미분은 근사치이므로, 정답을 아는 간단한 함수로 먼저 검증해야 믿고 쓸 수 있음

### 막혔던 부분 / 이해 포인트

- **`h`를 작게 할수록 정확해지는 게 아니었다**
  - "미세한 차이"라길래 작을수록 좋은 줄 알았는데, 직접 바꿔보니 반대였음
    - `h = 0.01` → 오차 `1.28e-13`
    - `h = 0.0001` → 오차 `1.27e-11`
    - `h = 1e-08` → 오차 `3.65e-08`
    - `h = 1e-12` → 오차 `5.33e-04` ← **가장 나쁨**
  - `h`가 너무 작아지면 `f(x+h)`와 `f(x-h)`가 거의 같은 값이 되어 **컴퓨터가 둘의 차이를 제대로 표현하지 못함**
  - 10/23에 본 `0.5 - 0.7 = -0.19999999999999996` 문제와 같은 뿌리
  - 작을수록 좋은 게 아니라 **적당한 크기**가 있다는 걸 알게 됨

- **중앙 차분과 전진 차분의 차이가 생각보다 컸다**
  - `h = 0.0001`에서
    - 중앙 차분 `(f(x+h) - f(x-h)) / 2h` → 오차 `1.27e-11`
    - 전진 차분 `(f(x+h) - f(x)) / h` → 오차 `1.00e-04`
  - 약 **1,000만 배** 차이
  - 양쪽 값을 쓰면 한쪽으로 치우친 오차가 서로 상쇄되기 때문

- **학습률을 바꿔보니 경사하강법의 의미가 보였다**
  - `L(w) = (w-3)²`(최적값 w=3)에서 w=0부터 5번 업데이트해봄
    - 학습률 **0.1**: `0.6 → 1.08 → 1.464 → 1.7712 → 2.017` (느리게 접근, 5번으로는 도착 못 함)
    - 학습률 **0.5**: `3.0 → 3.0 → 3.0 → 3.0 → 3.0` (한 번에 정답)
    - 학습률 **1.1**: `6.6 → -1.32 → 8.184 → -3.2208 → 10.465` ← **점점 멀어짐**
  - 학습률이 너무 작으면 학습이 한없이 느리고, 너무 크면 최솟값을 뛰어넘어 **발산**함
  - 교재가 학습률을 "한 걸음의 보폭"이라고 한 이유가 와닿음. 보폭이 너무 크면 계곡 바닥을 지나쳐 반대편 언덕으로 올라가버림
  - 머신러닝에서 `max_depth`를 조절했던 것처럼, 학습률도 사람이 정해줘야 하는 **하이퍼파라미터**

- **기울기의 부호와 이동 방향이 반대인 이유**
  - 교재 51p의 "기울기가 양수면 가중치를 (-) 방향으로"를 그래프로 생각해보니
    - 기울기가 양수 = 오른쪽으로 갈수록 손실이 **올라감** → 왼쪽으로 가야 함
    - 기울기가 음수 = 오른쪽으로 갈수록 손실이 **내려감** → 오른쪽으로 가야 함
  - 그래서 공식에 `W_old` **빼기** `η · 기울기`가 됨
  - 손실 그래프에서 **언제나 내리막 방향으로 한 걸음** 내딛는 것

## 📅 2026-10-27 | 오차역전파(계산 그래프·연쇄법칙)와 최적화(SGD·모멘텀·AdaGrad·Adam) / 순열 특성 중요도

> 코드: [`permutation_importance.py`](./permutation_importance.py)

### 개념

**1. 계산 그래프(Computational Graph)**
- 복잡한 계산 과정을 **노드(연산 기호)** 와 **에지(데이터가 흐르는 선)** 로 이루어진 네트워크로 시각화한 것
- **순방향 연산(Forward Pass)**: 입력층에서 출력층 방향으로 계산을 진행해 최종 결과(예측값 또는 손실값)를 구하는 과정
- **역방향 연산(Backward Pass)**: 출력층에서 입력층 방향으로 거꾸로 이동하며 기울기를 계산하는 과정

**2. 국소적 계산(Local Computation)**
- "나만 신경 쓴다" — 전체 신경망이 아무리 거대해도 개별 노드는 **자신에게 입력되는 데이터**와 **자신이 출력하는 데이터**라는 좁은 범위의 연산만 처리
- 예: '더하기(+)' 노드는 전체 과정을 알 필요 없이, 자기에게 들어온 4,000과 200만으로 4,200을 내보냄

**3. 합성함수(Composite Function)**
- 여러 함수가 사슬처럼 엮여 한 함수의 출력이 다음 함수의 입력으로 이어지는 구조
- **딥러닝 모델의 실체가 바로 합성함수**: 입력층 → 은닉층 함수 → 출력층 함수 → 손실 함수
- 표기: `u = g(x)`, `y = f(u)` → 최종 `y = f(g(x))`

**4. 연쇄법칙(Chain Rule)**
- 합성함수의 미분은 **구성하는 개별 함수의 미분(국소적 미분)들을 차례대로 모두 곱해서** 구할 수 있다는 법칙
- `∂y/∂x = (∂y/∂u) × (∂u/∂x)`
- 가운데 매개 변수 `u`가 분수처럼 약분되어 사라지면서 원하는 기울기가 도출됨

**5. 오차역전파(Backpropagation)**
- 손실 함수로 나온 오차를 연쇄법칙으로 역방향 연산해서 기울기를 구하는 방식
- 은닉층 가중치 기울기는 **3개의 국소적 미분의 곱**으로 분해됨
  - `∂L/∂w = (∂L/∂a) × (∂a/∂z) × (∂z/∂w)`
  - `∂L/∂a`: 뒤에 있는 출력층들이 이미 계산해서 **거꾸로 넘겨준 오차 신호**
  - `∂a/∂z`: 그 퍼셉트론의 **활성화 함수에 대한 미분**(예: ReLU)
  - `∂z/∂w`: `z = w·x + b`를 w로 미분한 결과 → **입력값 x 그 자체**
- **본질과 의의**: 가중치마다 순방향 계산을 수없이 반복할 필요 없이, 출력층에서 **딱 한 번 뒤로 오차를 보내는 것만으로** 모든 은닉층 가중치의 기울기를 일괄 산출할 수 있음

**6. 최적화(Optimization)**
- 손실 함수의 값(오차)이 최소가 되는 최적의 가중치를 찾는 과정
- 최적화 알고리즘: 최적의 가중치를 찾아가는 구체적인 방법과 수단

**7. 확률적 경사 하강법(SGD)**
- 공식: `W_new = W_old - η·∂L/∂W`
- 작동 방식: 현재 위치에서 기울기가 감소하는 내리막길 방향으로, 설정한 보폭만큼 **정직하게 한 걸음씩** 걸어 내려가는 방식
- **치명적 한계 — 로컬 미니멈 문제**
  - 가짜 최소점인 **지역 극소점(Local Minimum)** 바닥에 도달하면 주변이 모두 오르막이라 기울기가 0이 됨
  - 공식에 의해 보폭이 0이 되므로 **학습이 완전히 멈춤**
  - 진짜 목적지인 **전역 최소점(Global Minimum)** 을 눈앞에 두고 가짜 골짜기에 갇히게 됨

**8. 모멘텀(Momentum)**
- '운동량' 또는 '관성'을 뜻하는 물리학 용어. 가중치가 이동할 때 **과거에 이동했던 방향과 속도를 기억해 가속도를 붙여주는** 알고리즘
- 비유: 경사면에서 굴러 내려오는 **무거운 쇠구슬**. 가짜 골짜기 바닥에 도달해도 관성의 힘으로 앞의 언덕을 넘어감
- 수식 (관성 계수 보통 α = 0.9)
  - `v_new = α·v_old - η·∂L/∂W`
  - `W_new = W_old + v_new`

**9. AdaGrad**
- **업데이트가 많이 진행된 가중치**는 학습률을 강하게 감소시켜 보폭을 촘촘하게 줄이고, **학습이 거의 안 된 가중치**는 초기 학습률을 유지해 빠르게 따라붙게 함
- 수식 (기울기 제곱 누적 행렬 h = '주행거리 계기판')
  - `h_new = h_old + (∂L/∂W) ⊙ (∂L/∂W)`
  - `W_new = W_old - (η / (√h_new + ε))·∂L/∂W`
- **치명적 한계**: 학습이 오래 걸리면 계기판 `h`가 분모에서 무한히 커져, 목적지 근처가 아닌데도 **보폭이 0에 가까워져 학습이 종료됨**

**10. Adam — 현대 딥러닝의 표준**
- **Momentum + AdaGrad의 융합**: "쇠구슬의 묵직한 관성"과 "가중치별 보폭 자율 조정"의 장점만 결합
- **기억 상실 기능** 도입: 과거의 기울기 누적 기록을 일정 비율로 계속 깎아내어 자연스럽게 제거
- 최신 기울기 위주로 반영하므로 누적값이 무한대로 폭발하지 않고, 로컬 미니멈처럼 경사가 완만한 지점에서도 **유효 학습률이 0이 되지 않음**
- 딥러닝에서 가장 널리 사용되며 PyTorch에 내장되어 있음

**11. 특성 중요도의 두 종류**
- **내장 특성 중요도(학습용 데이터 기준)**: 모델 학습 과정에서 각 특성이 **노드 분할에 얼마나 기여했는지**를 평균적인 불순도 감소량으로 측정. 결정 트리 계열의 `feature_importances_`
- **순열 특성 중요도(평가용 데이터 기준)**: 학습을 마친 모델에 평가 데이터를 넣고 예측할 때, **특정 컬럼의 데이터를 무작위로 섞었을 때 성능이 얼마나 하락하는지**를 측정

**12. `permutation_importance` 사용법**
- `estimator`: 학습이 끝난 모델 / `X`, `y`: **평가용** 데이터
- `scoring`: 성능 측정 기준 / `n_repeats`: 무작위로 섞는 횟수
- 결과의 `importances_mean`: `n_repeats`번 측정한 **성능 감소량의 평균**

**13. 과적합 판별을 위한 교차 대조**
- **안정적으로 검증된 모델**: 내장 중요도와 순열 중요도의 상위권 순위가 유사하게 유지됨 → 실전에서도 올바른 근거로 예측
- **과적합된 불량 모델**: 학습 데이터에서 중요도가 높던 특성이 평가 데이터 검증에서 기여도가 폭락하거나 **음수로 떨어짐** → 노이즈까지 암기했다는 증거

### 왜 이렇게 코딩했는가

- 역전파를 **직접 구현하지 않고 개념만 정리한** 이유
  → PyTorch가 `loss.backward()` 한 줄로 처리해줌. 다만 그 한 줄이 무엇을 하는지 모르면 기울기가 폭발하거나 사라질 때 손을 못 댐. 그래서 수식 분해만큼은 손으로 따라가 봄
- 옵티마이저를 **SGD → 모멘텀 → AdaGrad → Adam 순서로** 배우는 이유
  → Adam은 앞선 두 알고리즘의 결합이라, 각각이 어떤 문제를 풀려고 나왔는지 모르면 Adam의 매개변수가 왜 그렇게 생겼는지 알 수 없음
- 순열 중요도에 **평가용 데이터(`X_test`)** 를 넣은 이유
  → 목적이 "**실전 데이터에서** 이 특성이 정말 기여하는가"를 보는 것. 학습용을 넣으면 내장 중요도와 같은 관점이 되어 교차 대조의 의미가 사라짐
- `n_repeats=5`를 준 이유
  → 무작위로 한 번만 섞으면 우연히 성능이 덜 떨어질 수 있음. 여러 번 섞어 평균을 내야 신뢰할 수 있는 값이 나옴
- `scoring="f1"`을 준 이유
  → Telco는 이탈률 26.6%의 불균형 데이터. 정확도로 측정하면 소수 클래스에 중요한 특성이 과소평가됨
- DecisionTree 탐색에 `range(3, 31)`과 `range(2, 21)`을 쓴 이유
  → 28 × 19 = **532가지** 조합이라 전수 탐색이 무리. RandomizedSearchCV로 150가지만 탐색

### 이해 포인트

- **"기울기를 어떻게 구하지?"에 대한 답이 역전파였다**
  - 10/26에 경사하강법 공식 `W_new = W_old - η·∂L/∂W`를 배우면서 `∂L/∂W`를 어떻게 구하는지가 남아 있었음
  - 수치 미분으로 구하면 가중치 하나당 `f(x+h)`와 `f(x-h)` 두 번씩 순방향 계산이 필요 → 가중치가 100만 개면 **200만 번**
  - 역전파는 출력층에서 **한 번만** 뒤로 신호를 보내면서, 각 노드가 이미 계산된 값을 재사용해 모든 기울기를 한꺼번에 구함

- **모멘텀이 로컬 미니멈을 탈출하는 걸 직접 확인했다**
  - 가짜 골짜기(얕음)와 진짜 골짜기(깊음)가 있는 손실 함수를 만들어, 먼 지점에서 출발시켜봄
    - **SGD**: `2.2 → 1.325 → 1.019 → 0.928 → 0.914` → 가짜 골짜기에 **갇힘**(손실 0.5755)
    - **모멘텀**: `2.2 → -0.341 → -0.423 → -1.049 → -1.068` → 언덕을 넘어 **진짜 골짜기 도달**(손실 -0.6210)
  - 다만 조건이 있었음. 가짜 골짜기 **바로 위**에서 출발시키면 모멘텀도 똑같이 갇힘
  - 탈출하려면 **내리막을 달려오며 속도를 붙일 거리**가 필요함. 교재의 '쇠구슬' 비유가 정확했음

- **모멘텀의 속도가 얼마나 누적되는지 계산해봤다**
  - 기울기가 계속 1.0으로 일정할 때 (학습률 0.01, α=0.9)
    - 1스텝 후 속도 `-0.0100` / 10스텝 후 `-0.0651` / 50스텝 후 `-0.0995`
  - 최대 속도는 `-η/(1-α)` = **SGD 보폭의 10배**
  - α를 0.9로 쓰는 이유가 여기 있었음. 0.99면 100배가 되어 너무 빨라짐
  - 같은 방향으로 계속 갈수록 빨라지고, 방향이 바뀌면 누적된 속도가 상쇄되어 자연스럽게 감속됨

- **AdaGrad의 `h`가 왜 문제가 되는지 숫자로 봤다**
  - 기울기가 0.5로 일정할 때 실질 학습률(`η/√h`)의 변화
    - 1스텝 후 `0.200000` / 100스텝 후 `0.020000` / 1,000스텝 후 `0.006325` / 5,000스텝 후 `0.002828`
  - `h`는 **제곱을 더하기만 하므로 절대 줄어들지 않음** → 분모가 단조 증가 → 보폭이 0으로 수렴
  - 목적지에 도착해서 멈추는 게 아니라, **단지 오래 걸었다는 이유로** 멈추는 것

- **10/21에 겪었던 "계수 순위가 무의미한 문제"를 순열 중요도가 해결한다**
  - 10/21에 로지스틱 회귀의 `coef_` 절댓값으로 Top5를 뽑았는데, 스케일링을 하지 않아서 `tenure`가 45개 중 **37위**로 밀려났었음
  - 값의 범위가 큰 컬럼은 계수가 작아도 영향이 크기 때문에, 계수 크기만 비교하면 순위가 왜곡됨
  - **순열 중요도는 계수를 보지 않고 "섞었을 때 성능이 얼마나 떨어지는가"만 측정**하므로 스케일링 여부와 무관함
  - 같은 질문("어떤 특성이 중요한가")에 대해 **더 믿을 수 있는 답**을 주는 방법이었음

- **내장 중요도와 순열 중요도는 기준이 다르다**
  - 내장: "학습할 때 이 특성으로 몇 번이나 갈라졌나" → **학습 과정**의 기록
  - 순열: "이 특성을 망가뜨리면 성능이 얼마나 떨어지나" → **실전 결과**의 측정
  - 그래서 둘이 다르게 나오는 게 이상한 일이 아니라, **다를 때 과적합을 의심**하라는 신호
  - 순열 중요도는 **음수가 나올 수도** 있음. 섞었는데 오히려 성능이 올라갔다면 그 특성이 방해하고 있었다는 뜻이며, 내장 중요도는 0 이상만 나오므로 이런 신호를 줄 수 없음

- **딥러닝 학습의 전체 흐름이 한 줄로 이어졌다**
  - 순방향 연산(예측) → 손실 함수(오차 측정) → 역전파(기울기 계산) → 경사하강법/Adam(가중치 업데이트)
  - 이 네 단계가 한 사이클이고, 미니배치 단위로 반복하다가 전체 데이터를 한 바퀴 돌면 **1 에포크**
  - 지금까지 배운 활성화 함수, 손실 함수, 미분, 최적화가 전부 이 사이클 안의 한 자리씩 차지하고 있었음
