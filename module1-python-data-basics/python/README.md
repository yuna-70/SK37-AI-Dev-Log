# Module 1 - Python 기초 (자료형 / 변수 / 리스트)

## 📅 2026-09-04 | 자료형 / 변수 / 입출력
> 코드: [`input_output.py`](./input_output.py)

### 개념

**1. 자료형(Data Type)**
- 컴퓨터가 처리할 수 있는 데이터의 '종류'와 '형태'를 규정한 것
- 크게 두 가지로 나뉨
  - 기본 자료형: 단일 값 하나를 저장 (숫자, 문자열 등)
  - 묶음 자료형: 여러 값을 하나로 묶어서 저장 (리스트, 튜플 등)

**2. 변수(Variable)**
- 데이터(값)가 저장된 공간의 이름
- 값을 저장할 때마다 메모리 주소가 새로 생기고, 변수는 그 주소를 가리킴
- 같은 변수에 새 값을 넣으면 이전 값이 아니라 최신 값으로 덮어써짐

**3. 데이터 입출력**
- 입력: 키보드 / 출력: 모니터
- 기본 출력 함수: `print(data)`
  - 숫자 출력: `print(2026)`
  - 문자열 출력: `print("Hello python")` 또는 `print('Hello python')`
- f-string: 문자열 안에 변수를 직접 삽입해서 출력하는 방식
  - `print(f'저의 키는 {height}cm 입니다.')`
  - 문자열 조합(`+`)보다 가독성이 좋고, 변수 타입 변환을 신경 쓸 필요가 없음

**4. 변수 네이밍 규칙**
- 사용 가능: 영문 대소문자, 숫자, 언더바(`_`), 한글(권장 X)
- 규칙: 대소문자 구분함 / 숫자로 시작 불가 / 변수명 중간에 공백 불가

### 왜 이렇게 코딩했는가
- `print("저의 키는 180cm 입니다.")`처럼 문자열을 통째로 쓰지 않고 `height = 180` 변수로 분리한 이유
  - 키 값이 바뀔 때 문자열 전체를 다시 쓰지 않고 변수 값만 바꾸면 됨
  - f-string과 함께 쓰면 값과 문장을 분리해서 관리할 수 있음

### 이해 포인트
- `name1 = "홍길동"` 이후 `name1 = "이순신"`으로 재할당했을 때, 마지막 값(`이순신`)만 출력됨
  → 변수는 값이 아니라 "값이 저장된 공간의 이름"이라서, 재할당하면 그 이름이 새 값을 가리키게 됨(이전 값은 사라짐)
- 반면 `name1`, `name2`처럼 서로 다른 변수에 각각 할당하면 둘 다 독립적으로 유지된다는 걸 코드로 직접 확인함

## 📅 2026-09-04 | List (생성 / 인덱싱 / 슬라이싱)
> 코드: [`list_basics.py`](./list_basics.py), [`list_pracctive.py`](./list_pracctive.py)

### 개념

**1. 리스트(List)란**
- Python의 순서형 묶음 자료형: 여러 개의 데이터를 하나로 묶어서 저장하고 사용하는 방법
- 특징
  - 전체 데이터가 하나의 묶음으로 취급됨
  - 원소들은 콤마(`,`)로 구분
  - 원소 간 순서가 있으며, 추가/수정/삭제가 가능함
- 생성 형태: `변수 = [원소1, 원소2, 원소3, ...]`
  - 빈 리스트, 숫자만, 문자열만, 숫자+문자열 혼합, 리스트 안에 리스트(중첩)까지 모두 가능

**2. 인덱싱(Indexing)**
- `리스트[인덱스]` → 해당 위치의 값 하나를 추출
- 인덱스는 0부터 시작, 음수 인덱스는 뒤에서부터 (`-1`이 마지막)
- 중첩 리스트는 인덱스를 이어서 접근 (`list[3][1]` → 4번째 원소 안에서 다시 2번째)

**3. 슬라이싱(Slicing)**
- `리스트[start : stop]` → start 인덱스부터 stop 바로 전까지 추출 (`start <= x < stop`)
- stop을 생략하면 리스트 끝까지

### 왜 이렇게 코딩했는가
- `first_idx = list_data[0]`처럼 인덱싱 결과를 변수로 뺀 이유
  - 변수명 자체가 값의 의미를 설명해줌
  - `list_data[0]`을 코드 여러 곳에서 반복해서 쓰면 나중에 수정할 때 전부 찾아 고쳐야 하는데, 변수로 빼두면 한 곳만 수정하면 됨
- 중첩 리스트에서 `'b'`를 바로 찾지 않고, 1~4번째 원소를 각각 변수로 하나씩 꺼내본 이유
  - `list_data1[3][1]`을 한 번에 이해하기보다, 단계별로 쪼개서 각 인덱스가 무엇을 가리키는지 직접 확인하기 위함

### 이해 포인트
- 슬라이싱에서 `list_data[3:]`처럼 stop을 생략하면 끝까지 포함되고, `[0:3]`은 인덱스 3(네 번째 값)은 포함되지 않는다는 점을 코드로 직접 확인함

## 📅 2026-09-07 | Dictionary
> 코드: [`dict_basics.py`](./dict_basics.py), [`dict_practice.py`](./dict_practice.py)

### 개념

**1. 딕셔너리(Dictionary) - 매핑형 묶음 자료형**
- 매핑(mapping): 데이터 간 1:1 대응
- `dict`는 "사전"이라는 뜻 그대로, key와 value가 1:1로 대응하는 구조 (1쌍 = pair)
- 특징
  - 데이터는 `key : value` 형태의 쌍으로 구성됨
  - key는 중복 불가능, value는 중복 가능
  - 인덱스가 아니라 **key로 데이터에 접근**함 (리스트와의 가장 큰 차이)
  - value로 리스트 등 다른 자료형도 담을 수 있음 (`{'name': ['박보검', '이찬원']}`)

**2. 값 가져오기 / 추가 / 삭제 / 수정**
- 값 가져오기: `딕셔너리변수[key]`
- 데이터 추가: `딕셔너리변수[새key] = 값` → 없는 key에 값을 대입하면 자동 추가됨
- 데이터 삭제: `del 딕셔너리변수[key]` → key와 value가 함께 삭제됨
- 데이터 수정: `딕셔너리변수[기존key] = 새값` → 추가와 문법은 같지만, 이미 있는 key면 값이 덮어써짐(수정)

### 왜 이렇게 코딩했는가
- 리스트는 `list_data[4] = 50`처럼 존재하지 않는 인덱스에 값을 대입하면 에러가 나지만, 딕셔너리는 `dict[새key] = 값`으로 새 key를 바로 추가할 수 있음
  → 이 차이를 직접 비교하려고 리스트에 없는 인덱스를 대입하는 코드를 주석 처리해서 함께 남겨둠 (에러가 나는 상황을 보여주기 위한 의도적 비교)

### 이해 포인트
- 딕셔너리의 "추가"와 "수정"이 문법상 완전히 똑같다는 점(`변수[key] = 값`)
  → key가 이미 있으면 수정, 없으면 추가로 동작이 자동으로 나뉜다는 걸 코드로 확인함
- `del 변수[key]`는 값만 지우는 게 아니라 key까지 함께 삭제한다는 점을 확인함

## 📅 2026-09-07 | Tuple
> 코드: [`tuple_basics.py`](./tuple_basics.py)

### 개념

**튜플(Tuple) - 순서형 묶음 자료형**
- 생성: `()` 사용 (예: `t = (1, 2, 3)`)
- 리스트와의 공통점: 순서형 묶음 자료형 → 인덱싱 가능
- 리스트와의 차이점: **값 수정이 불가능** (리스트는 `list[0] = 값`으로 수정 가능하지만, 튜플은 에러 발생)

### 왜 이렇게 코딩했는가
- 리스트와 튜플을 각각 만들어서 같은 방식으로 인덱싱해본 이유
  → 두 자료형이 "순서형 묶음"이라는 공통점을 공유한다는 걸 직접 비교하기 위함
- 리스트는 실제로 수정하고, 튜플은 수정 코드를 주석 처리만 해둔 이유
  → 튜플 수정 시 에러가 난다는 걸 알고 있으므로, 실행하지 않고 "이건 안 된다"는 걸 코드 흔적으로 남기기 위함

### 이해 포인트
- 리스트와 튜플이 겉보기엔 비슷해 보였는데, `tuple_data[0] = "mango"`를 시도하면 에러가 난다는 걸 확인하며 "값 변경 가능 여부"가 핵심 차이라는 걸 체감함

## 📅 2026-09-07 | 숫자형 자료형
> 코드: [`number_basics.py`](./number_basics.py)

### 개념

**1. 종류와 생성**
- 정수형(`int`): 소수점 없는 수 / 실수형(`float`): 소수점 있는 수
- 변수에 숫자를 직접 대입하여 생성 (`num1 = 123`, `num2 = 1.2`)

**2. 연산자**
- 사칙연산: `+`, `-`, `*`, `/`
- 제곱(`**`): 예) `3 ** 4` → 3의 4제곱
- 나머지(`%`): 나눗셈 후 나머지만 추출
- 몫(`//`): 나눗셈 후 소수점 버리고 정수 몫만 추출

**3. `%`를 활용한 조건 판별**
- 짝수/홀수: `n % 2 == 0` → 짝수, `n % 2 == 1` → 홀수
- K의 배수: `n % K == 0`

### 왜 이렇게 코딩했는가
- `print(2 % 2)`처럼 나머지 값을 먼저 찍어보고, `print(2 % 2 == 0)`으로 비교 결과(True/False)를 이어서 찍은 이유
  → 조건식이 왜 True/False가 되는지, 중간 계산값을 먼저 눈으로 확인한 뒤 조건 결과를 보기 위함

### 이해 포인트
- `%`(나머지)와 `//`(몫)의 차이를 `7 % 3`(나머지 1)과 `7 // 3`(몫 2)을 직접 실행해보며 구분함

## 📅 2026-09-07 | 문자열(str) 자료형
> 코드: [`str_basics.py`](./str_basics.py)

### 개념

**1. 문자열이란**
- Python의 문자 순서형 자료형: 연속된 문자로 구성된 데이터를 저장하고 사용하는 방법을 정의

**2. 생성**
- `'문자열'` 또는 `"문자열"`
- `"""문자열"""` → 여러 줄에 걸친 문자열 생성 시 사용

**3. 인덱싱과 슬라이싱**
- 문자열도 순서형 자료형이라 리스트와 동일한 방식으로 인덱싱/슬라이싱 가능
- `문자열[인덱스]`, `문자열[start:stop]` (stop 인덱스는 미포함)

**4. 문자열 연산**
- `+` : 문자열끼리 연결
- `*` : 문자열을 정수만큼 반복 (예: `"-" * 80` → 구분선 만들기에 자주 사용)

### 왜 이렇게 코딩했는가
- 문자열 인덱싱/슬라이싱 결과를 출력할 때마다 `print("-" * 80)`으로 구분선을 넣은 이유
  → 여러 출력 결과가 섞이지 않고 한눈에 구분되도록 하기 위함
- `"-" * 80`처럼 문자열에 곱셈 연산자를 쓴 이유
  → 반복문 없이 짧은 코드로 긴 구분선을 만들 수 있어서

## 📅 2026-09-08 | 함수(Function)
> 코드: [`function_basics.py`](./function_basics.py), [`list_functions.py`](./list_functions.py), [`dict_functions.py`](./dict_functions.py), [`str_functions.py`](./str_functions.py)

### 개념

**1. 함수(Function)란**
- 입력받은 데이터를 가지고 사전에 정의된 기능을 수행하고, 결과값을 전달하는 코드의 집합

**2. 함수 구조**
- `def 함수이름(매개변수):` 형태로 정의 (콜론 필수, 다음 줄부터 들여쓰기)
- 함수 실행(호출): 함수 이름 뒤 소괄호 안에 필요한 인수(argument)를 입력
```python
  def add(x, y):
      sum = x + y
      return sum

  result = add(3, 5)
```

**3. 함수의 종류**
- 사용자 정의 함수: 사용자가 직접 정의하고 호출해서 사용
- 내장 함수: 파이썬에 이미 정의되어 있어 호출만 하면 사용 가능
  - 자료형 상관없이 쓸 수 있는 함수: `print()`, `type()`, `len()`
  - 특정 자료형 전용 함수: 리스트 전용, 딕셔너리 전용, 문자열 전용 함수로 나뉨

**4. 리스트 전용 함수**
- `리스트.append(값)`: 리스트 맨 뒤에 값 하나 추가 (순차적으로만 추가 가능)
- `리스트.extend(다른리스트)`: 리스트끼리 연결해서 하나의 긴 리스트로 만듦
- `+` 연산자: extend와 마찬가지로 리스트끼리 연결 가능
- `len(리스트)`: 원소 개수 확인 (모든 자료형에 사용 가능한 범용 함수)

**5. 딕셔너리 전용 함수**
- `딕셔너리.keys()`: key만 모아서 가져오기
- `딕셔너리.values()`: value만 모아서 가져오기
- `딕셔너리.items()`: key, value를 쌍으로 가져오기
- `딕셔너리.get('key')`: key로 value 가져오기 (`딕셔너리[key]`와 유사하지만 없는 key 조회 시 에러 대신 None 반환)

**6. 문자열 전용 함수**
- `capitalize()`: 첫 번째 문자만 대문자로 변환
- `upper()` / `lower()`: 전체를 대문자 / 소문자로 변환
- `title()`: 각 단어의 첫 문자를 대문자로 변환
- `split()`: 특정 문자를 기준으로 문자열을 분리해 리스트로 반환
- `join()`: 리스트 형태의 문자열들을 특정 문자로 연결
- `replace()`: 특정 문자(열)를 다른 문자(열)로 치환
- `strip()`: 문자열 시작·끝의 공백/줄바꿈 기호 제거

### 왜 이렇게 코딩했는가
- `add(x, y)`를 호출할 때 `add(3, 5)`(위치 인수)와 `add(x=3, y=5)`(키워드 인수) 두 방식을 모두 실행해본 이유
  → 같은 결과를 내는 두 가지 호출 방식이 있다는 걸 직접 비교하기 위함
- 리스트에 값 3개를 추가할 때 `append()`를 3번 쓰는 방법, `extend()` 한 번 쓰는 방법, `+` 연산자 쓰는 방법을 모두 실행해본 이유
  → 여러 원소를 추가하는 여러 방법의 차이(순차 추가 vs 한 번에 연결)를 직접 비교하기 위함
- `dict_data.keys()`의 결과를 `type()`으로 확인해본 이유
  → 결과가 리스트가 아니라 `dict_keys`라는 별도 자료형이라는 걸 확인하기 위함
- `dict_data["birth"]`(존재하지 않는 key)는 에러 확인용으로 주석 처리만 하고, `dict_data.get("birth")`는 실제로 실행해본 이유
  → 인덱싱 방식(`[key]`)은 없는 key 조회 시 에러가 나지만, `get()`은 에러 없이 `None`을 반환한다는 차이를 직접 비교하기 위함

### 이해 포인트
- `dict_keys` 자료형이 순서대로 값을 보관하지만, 리스트처럼 인덱싱(`keys_data[0]`)은 안 된다는 걸 확인함 (코드에 주석으로 남겨둠)
- `append()`는 값을 딱 하나씩만 순차적으로 추가할 수 있고, 여러 개를 한 번에 합치려면 `extend()`나 `+`를 써야 한다는 차이를 실습으로 구분함
- `변수[key]`와 `변수.get(key)`가 있는 key를 가져올 땐 결과가 같지만, 없는 key를 조회할 때 동작이 다르다는 걸 이해함
  (`[key]` → KeyError 발생 / `get(key)` → None 반환, 에러 없음)

## 📅 2026-09-09 | 반복문 (for / while)
> 코드: [`loop_basics.py`](./loop_basics.py)

### 개념

**1. 반복문이란**
- 특정 명령을 반복하여 실행하도록 제어하는 명령문
- 종류: `for`, `while`

**2. for 반복문**
- 정해진 횟수만큼(또는 자료구조의 길이만큼) 반복 실행
- 리스트, 튜플, 문자열, 딕셔너리처럼 데이터를 하나씩 꺼낼 수 있는 자료구조에서, 각 요소를 하나씩 꺼내와 코드 블록을 실행
- 기본 구조: `for 변수 in 자료구조:` (콜론 필수, 다음 줄부터 들여쓰기)
- `range(start, stop)`: start부터 stop-1까지의 정수를 순서대로 만들어냄 → for문과 함께 "지정한 횟수만큼 반복"할 때 자주 사용

**3. while 반복문**
- 조건식이 참(True)인 동안 코드 블록을 반복 실행
- 반복 횟수가 미리 정해지지 않았을 때 주로 사용
- 동작 순서: 조건식 평가 → 참이면 코드 실행 → 다시 조건 평가 (선 조건 평가, 후 코드 실행)
- `break`: 반복문을 즉시 종료시키는 예약어. 주로 `while True:`(무한 루프)와 함께 써서, 특정 조건이 되면 `break`로 빠져나오는 패턴으로 사용

### 왜 이렇게 코딩했는가
- for 반복문 실습(1)에서 `print(food)` 대신 `print("Hi")`를 주석 처리 없이 바꿔서 실행해본 이유
  → for문이 "각 원소 값 자체"가 아니라 "정해진 횟수만큼 반복 실행"한다는 것도 확인하기 위해, 변수를 안 쓰고 고정 문자열만 출력해봄
- `while True:` + `input()` + `break`를 조합한 이유
  → 사용자가 언제 그만둘지 미리 알 수 없는 상황(사용자 입력을 계속 받다가 "exit"/"quit" 입력 시 종료)에서는
    반복 횟수를 미리 정할 수 없으므로, for문이 아니라 while 무한 루프 + break 조합이 적합하다고 판단함

### 이해 포인트
- `range(0, 100)`을 그냥 `print()`하면 숫자 목록이 아니라 `range(0, 100)`이라는 range 객체 자체가 출력된다는 걸 확인함
  → 실제 숫자들을 보려면 `for`문으로 하나씩 꺼내거나 `list(range(0,100))`으로 변환해야 함
- `while` 반복문은 `count += 1`처럼 조건을 거짓으로 만들 변화를 직접 코드 안에 넣어야 한다는 걸 확인함 (안 넣으면 무한 루프)

> 코드: [`conditional_basics.py`](./conditional_basics.py)

### 개념

**1. 조건문이란**
- 상황에 따라 실행 흐름을 다르게 하는 문법

  - 두 번째가 참이면 실행문장2 실행
  - 두 번째도 거짓이면 else의 실행문장3 실행
- 즉 위에서부터 순서대로 조건을 검사하다가, 처음으로 참이 되는 조건의 코드만 실행되고 나머지는 건너뜀

  → 조건값에 따라 실제로 어떤 분기가 실행되는지 직접 눈으로 확인하기 위함

  → elif는 위에서부터 순서대로 검사하므로, 만약 60점부터 먼저 검사하면 90점도 "60 이상"에 걸려 처음 조건에서 멈춰버림

## 📅 2026-09-10 | 예외 처리 (Exception Handling)
> 코드: [`exception_basics.py`](./exception_basics.py)

### 개념

**1. 예외(Exception)란**
- 코드(프로그램) 실행 중에 발생하는 에러
- 예외가 발생하면 프로그램이 비정상 종료됨 (예: 10을 0으로 나누면 에러 발생)

**2. 예외 처리란**
- 예외가 발생해도 프로그램이 중단되지 않고 계속 실행되도록 코드를 작성하는 것
- 기본 문법: `try-except`문

**3. 명시적 예외 처리**
- `except 예외이름:`처럼 처리할 예외 종류를 직접 지정
- 지정한 종류의 예외만 처리됨 (다른 종류의 예외는 그대로 프로그램이 중단됨)
- 여러 개의 예외를 각각 다르게 처리하고 싶으면 `except`를 여러 번 이어서 작성 가능

**4. 포괄적 예외 처리**
- `except Exception as e:`처럼 발생할 수 있는 모든 종류의 오류를 한 번에 처리
- 어떤 종류의 예외인지 구분하지 않고 전부 잡아내고 싶을 때 사용

### 왜 이렇게 코딩했는가
- 명시적 예외 처리(3)에서 실제로는 `NameError`가 발생하는 상황인데 일부러 `except ZeroDivisionError`를 먼저 써본 이유
  → 지정하지 않은 종류의 예외는 명시적 처리로 못 잡는다는 걸 확인하고, `except NameError`를 추가로 이어붙여
    여러 종류의 예외를 각각 대응할 수 있다는 걸 실습하기 위함
- 포괄적 예외 처리(2)에서 `NameError`(정의 안 된 변수 `naem`)와 `ZeroDivisionError`(0으로 나누기)를
  한 코드 블록 안에 동시에 넣어본 이유
  → 명시적 처리는 지정한 예외 하나만 잡지만, `except Exception`은 종류에 상관없이 발생한 첫 예외를
    바로 잡아준다는 차이를 직접 비교하기 위함

### 이해 포인트
- 명시적 예외 처리는 지정한 예외 종류와 실제 발생한 예외가 다르면 처리가 안 되고 프로그램이 그대로 중단된다는 걸 확인함
  (그래서 명시적 처리를 쓸 땐 어떤 예외가 발생할지 미리 예상하고 있어야 함)
- 포괄적 예외 처리(`except Exception`)는 한 코드 블록 안에 오류가 여러 개 있어도, **먼저 발생한 오류 하나만** 잡고
  그 아래 코드는 실행되지 않는다는 걸 확인함 (2번째 오류인 `10/number`는 실행조차 안 됨, `naem` 오류에서 이미 멈췄기 때문)

**3. 파일 쓰기 (`mode="w"`)**
- 같은 이름의 파일이 이미 있으면 기존 내용을 무시하고 새로 씀 (덮어쓰기)
- `f.write(내용)`: 파일에 문자열을 입력

### 왜 이렇게 코딩했는가
- 파일 경로를 쓸 때 `\`(백슬래시) 대신 `/`(슬래시)로 바꿔서 쓴 이유
  → 윈도우 경로는 원래 `\`를 쓰지만, 파이썬 문자열에서 `\`는 이스케이프 문자로 해석될 수 있어서
    `\U`, `\n` 같은 조합이 의도치 않게 특수 문자로 인식되는 걸 피하려고 `/`로 통일함
- 같은 파일을 `read()`와 `readlines()` 둘 다로 읽어본 이유
  → 전체를 문자열 하나로 받는 것과, 줄 단위 리스트로 받는 것의 결과 형태 차이를 직접 비교하기 위함

### 이해 포인트
- `read()`는 문자열 하나를 반환하고 `len()`을 하면 "전체 글자 수"가 나오는 반면,
  `readlines()`는 리스트를 반환하고 `len()`을 하면 "줄 수"가 나온다는 차이를 확인함
- `mode="w"`로 파일을 열면 기존 파일이 있어도 덮어써진다는 걸 확인함 (기존 내용이 남지 않음)
