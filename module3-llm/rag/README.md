### 개념

**1. RAG가 무엇인지**

- RAG(Retrieval-Augmented Generation)는 **검색**으로 근거를 먼저 찾고, 그 근거를 프롬프트에 넣어 LLM이 **생성**하게 하는 방식임
- LLM은 학습 시점 이후의 일이나 우리 회사 내부 문서를 모름. 모르는 걸 물으면 그럴듯하게 지어내는 환각이 생김
- 모델을 다시 학습시키는 대신, 질문할 때마다 답의 근거를 찾아서 같이 넣어주는 쪽을 택한 것임
- 흐름은 **문서 로드 → 분할 → 임베딩 → 저장 → 검색 → 생성** 순서임

**2. Document 자료형과 로더**

- `Document`는 LangChain이 텍스트를 다루는 기본 자료형임. `metadata`(파일 경로, 페이지 번호 등)와 `page_content`(텍스트 내용)로 구성됨
- `TextLoader`는 `.txt` 파일 1개를 Document 1개로 만듦
- `PyMuPDFLoader`는 PDF를 **페이지당 Document 1개**로 만듦. 헌법 PDF는 14개가 나왔고, 각 Document의 `metadata`에 `page` 번호가 들어 있었음
- 로더가 달라도 결과물이 똑같이 `[Document]` 리스트라서, 그다음 단계부터는 코드가 동일함

**3. 분할(chunking)과 chunk_size**

- 임베딩 모델이 한 번에 처리할 수 있는 길이에 제한(8,192 토큰)이 있고, 너무 긴 덩어리는 유사도 계산도 뭉개짐. 그래서 작은 조각으로 나눔
- `RecursiveCharacterTextSplitter`는 큰 단위부터 순서대로 쪼갬. `"\n\n"`(단락) → `"\n"`(문장) → `" "`(공백) → `""`(글자)
- 조각이 `chunk_size`보다 크면 다음 구분자로 다시 쪼개고, 짧으면 병합함
- `chunk_overlap`은 인접한 조각 사이에 겹치는 글자 수임. QA나 법률 문서는 조각이 그 자체로 완결되므로 0, 일반 소설처럼 문맥이 이어지는 글은 `chunk_size`의 10% 정도를 씀

**4. 임베딩과 벡터 저장소**

- `OpenAIEmbeddings(model="text-embedding-3-small")`로 각 조각을 벡터로 바꿈. 수요일에 `SentenceTransformer`로 문장을 벡터로 만든 것과 같은 일을 API로 하는 것임
- 벡터 저장소는 그 벡터들을 모아두고, 질문 벡터와 가장 가까운 것을 찾아주는 저장소임
- `FAISS`는 메모리에 저장함. `index`에 벡터 배열, `docstore`에 원문과 메타데이터가 들어감. 프로그램을 끄면 사라지므로 다음 실행 때 임베딩을 다시 해야 함
- `Chroma`는 `persist_directory`를 주면 폴더에 파일로 저장함. 폴더를 열어보니 `chroma.sqlite3`와 벡터 인덱스 폴더가 만들어져 있었음

**5. 검색 도구(retriever)**

- `vectorstore.as_retriever(search_kwargs={'k': n})`로 만들고 `retriever.invoke(질문)`으로 호출함
- 질문도 같은 임베딩 모델로 벡터화한 뒤, 저장된 벡터들과 거리를 비교해 가까운 `n`개를 Document 리스트로 돌려줌
- 그래서 저장할 때 쓴 모델과 검색할 때 쓴 모델이 같아야 함. `Chroma`를 다시 불러올 때 `embedding_function=model`을 넣는 이유가 이것임
- `k`는 문서의 성격에 따라 정함. QA 매뉴얼은 한 쌍이 곧 완결된 답이라 `k=1`, 헌법은 조문 하나로 답이 안 되는 경우가 많아 `k=2`로 올렸음

**6. 검색 결과를 프롬프트에 넣기**

- `k=1`이면 `retrieved_docs[0].page_content` 하나로 끝남
- `k=2`이면 두 Document의 텍스트를 꺼내 리스트에 모으고 `"\n\n".join(contents)`로 하나의 문자열로 병합함
- 체인은 `rag_chain = prompt | llm | output_parser`로 금요일과 똑같고, 검색은 체인 **밖에서** 따로 한 뒤 `invoke({'context': ..., 'question': ...})`로 넣어줌

### 왜 이렇게 코딩했는가

- `chunk_size`를 감으로 정하지 않고, 파일을 문단으로 쪼개서 글자수를 전부 재본 뒤 가장 긴 QA 쌍(157자)보다 조금 큰 160으로 잡았음. 이렇게 하면 **질문-답변 한 쌍이 중간에 끊기지 않고** 한 조각에 들어감
- 헌법 PDF에서 `separators=["\n\n", "\n", " ", ""]`를 명시한 이유는 기본값과 같지만 **조문 단위로 끊기길 바란다는 의도를 코드에 남기기 위함**임. `chunk_size`도 조문이 QA보다 훨씬 길어서 500으로 올렸음
- 세 실습 모두 프롬프트에 "컨텍스트에 정보가 없으면 모른다고 답하라"는 규칙을 넣었음. 검색 도구는 **관련이 없어도 가장 가까운 걸 반드시 돌려주기 때문**에, 이 규칙이 없으면 엉뚱한 근거로 답을 만들어버림
- 헌법 프롬프트에 "조항 번호를 언급하라"를 넣은 이유는 답변의 출처를 눈으로 확인하기 위함임. 실제로 "국회의원의 임기는 4년으로 정해져 있습니다. (제42조)"처럼 조항이 함께 나왔음
- Chroma에서 `if os.path.exists(chroma_path) and os.listdir(chroma_path):`로 두 가지를 함께 확인한 이유는, 폴더만 있고 안이 빈 경우에는 새로 만들어야 하기 때문임. `exists`만 보면 빈 폴더를 저장소로 착각함
- 헌법 저장소 폴더를 `chroma_db_constitution`으로 따로 둔 이유는, `manual.txt`와 같은 폴더를 쓰면 **서로 다른 문서의 벡터가 한 저장소에 섞여** 검색 결과가 뒤죽박죽이 되기 때문임
- 검색 결과를 매번 `print`로 찍어두는 이유는, 답이 이상할 때 **검색이 틀렸는지 생성이 틀렸는지**를 나눠서 볼 수 있기 때문임

### 막혔던 부분 · 이해 포인트

- **검색은 성공했는데 챗봇이 "아는 바가 없습니다"라고 답했음**
  - 세 번째 질문에서 retriever가 "모바일 앱" 관련 문서를 가져왔는데, 챗봇은 `죄송하지만 문의하신 내용에 대해서는 아는 바가 없습니다.`라고 답했음
  - 처음엔 검색이 실패한 줄 알았는데, 검색은 가장 가까운 문서를 정상적으로 돌려준 것이었고 그게 질문과 관련이 없었던 것임
  - **벡터 검색에는 "결과 없음"이 없음.** 유사도가 낮아도 가장 가까운 걸 반드시 하나 돌려줌
  - 그래서 프롬프트의 3번 규칙이 장식이 아니라 **실제로 작동하는 안전장치**였음. LLM이 근거를 읽고 질문과 무관하다고 판단해 모른다고 답한 것임
- **FAISS와 Chroma의 차이가 코드가 아니라 실행 후에 보였음**
  - FAISS는 `from_documents(docs, model)` 한 줄이고, 끄면 사라짐
  - Chroma는 `persist_directory='chroma_db'`를 줬더니 폴더가 생기고 `os.listdir`에 `['ceb347b3-...', 'chroma.sqlite3']`가 찍혔음
  - 두 번째 실행부터는 `if`문이 기존 저장소를 불러와서 임베딩 API를 다시 호출하지 않음. **임베딩은 돈이 드는 작업이라 한 번 하고 저장해두는 게 중요**하다는 걸 알게 됐음
- **같은 코드가 PDF에서는 다른 수의 조각을 만들었음**
  - `manual.txt`: Document 1개 → `chunk_size=160` → 10개 조각
  - 헌법 PDF: Document 14개(페이지당 1개) → `chunk_size=500` → 52개 조각
  - 로더가 Document를 몇 개로 만드는지, 그걸 다시 몇 글자로 쪼개는지가 **문서의 성격에 따라 매번 달라지는 설계 선택**이라는 게 보였음
- **수요일에 했던 유사도 챗봇과 구조가 같으면서 달랐음**
  - 수요일 유사도 챗봇은 11,823개 질문을 전부 임베딩해두고, 가장 비슷한 질문의 **준비된 답을 그대로** 돌려줬음
  - RAG는 가장 비슷한 문서를 찾은 뒤, 그걸 근거로 **LLM이 답을 새로 씀**. 그래서 질문 표현이 달라도 문장을 다듬어 답할 수 있음
  - 검색까지는 같고, 그 뒤에 생성이 붙은 것이 차이였음
- **`langchain_community` DeprecationWarning이 떴음**
  - `TextLoader`를 임포트할 때 `langchain_community`가 더 이상 권장되지 않는다는 경고가 나왔음
  - 실행은 정상적으로 됐고, Chroma는 이미 `langchain_chroma`라는 별도 패키지로 분리되어 있었음
  - LangChain이 기능별로 패키지를 쪼개는 중이라서 임포트 경로가 옮겨 다니는 것으로 보임. 교재 코드가 돌아가지 않으면 임포트 경로부터 확인해야 할 것 같음
