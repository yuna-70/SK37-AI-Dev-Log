# Module 3 - 서울시 상권 분석 에이전트 (Text-to-SQL / 데이터 분석)

## 📅 2026-11-27 | 서울시 상권 데이터 적재와 분석 에이전트 설계

> 코드: [`load_seoul_data.py`](./load_seoul_data.py)

### 개념

**1. 무엇을 만드는가**

- 지금까지의 RAG 챗봇은 **문서**에서 답을 찾았음. 이번 에이전트는 **데이터베이스**에서 답을 찾음
- 사용자가 한국어로 질문하면 LLM이 SQL을 만들고, 그 SQL을 실행한 결과로 분석 보고서를 작성하는 구조임
- 흐름은 `질문 재구성` → `SQL 생성` → `SQL 실행` → `보고서 생성` 이고, 데이터 조회가 필요 없는 질문은 일반 답변으로 빠짐
- 교재의 실습 프로젝트이고, 지금까지 배운 것(조건부 분기, 비동기, 체크포인터, 구조화된 출력)이 전부 들어감

**2. 데이터 적재 — CSV에서 MySQL로**

- 서울 열린데이터광장의 상권별 매출 데이터임. **128,053행 × 55컬럼**
- `pd.read_csv(file_path, encoding="cp949")` — 공공데이터는 보통 cp949로 저장되어 있어 utf-8로 읽으면 깨짐
- `df.rename(columns=column_mapping)`으로 한글 컬럼명을 전부 영문으로 바꿈
- `df1.to_sql(name=..., con=engine, if_exists="replace", index=False, chunksize=1000)`로 MySQL에 적재함

**3. SQLAlchemy의 `URL.create()`**

- 접속 주소를 문자열로 직접 조립하지 않고 `URL.create(drivername=..., username=..., password=..., ...)`로 만듦
- 비밀번호에 `@`나 `:` 같은 특수문자가 있어도 알아서 처리해줌. 11월 25일에 `quote_plus`로 직접 처리했던 일을 대신해주는 것임
- `print`할 때 비밀번호를 `***`로 가려서 출력함
- `query={"charset": "utf8mb4"}`를 넣어야 한글 상권명이 제대로 저장됨

**4. 구조화된 출력을 여러 에이전트에 쓰기**

- 에이전트마다 출력 형식 클래스를 따로 만듦. `RephraseResult`, `SQLResult`, `ReportResult`
- `RephraseResult`는 `rephrased_query`(문자열)와 `is_data_query`(불리언)를 **한 번에** 돌려줌. 지금까지는 재구성과 분류를 다른 노드에서 따로 했는데, 구조화된 출력을 쓰면 LLM 한 번 호출로 둘 다 받을 수 있음
- `SQLResult`의 `explanation: str | None`은 설명이 없어도 되는 선택 항목이라는 뜻임
- 상태에도 `final_report: ReportResult | None`처럼 **커스텀 자료형 자체**를 담을 수 있음

**5. DB 조회 도구 함수**

- `SHOW CREATE TABLE`로 테이블 구조를 뽑아 LLM에게 알려줌. 컬럼 이름과 자료형을 모르면 SQL을 만들 수 없기 때문임
- `aiomysql.DictCursor`를 지정하면 조회 결과가 튜플이 아니라 딕셔너리로 나옴. 그대로 LLM 프롬프트에 넣기 좋음
- MySQL의 `SUM()` 같은 집계 함수는 `Decimal` 자료형을 돌려주는데, 이건 JSON으로 바로 못 바꿔서 `int`나 `float`로 변환해줘야 함
- 노드 함수 작성은 다음 시간에 이어서 함

### 왜 이렇게 코딩했는가

- 한글 컬럼명을 영문으로 바꾼 이유는 두 가지임. MySQL에서 한글 컬럼은 SQL을 쓸 때마다 백틱으로 감싸야 하고, 나중에 **LLM에게 SQL을 생성시킬 때** 영문 컬럼명 쪽이 훨씬 안정적이기 때문임
- `chunksize=1000`을 준 이유는 12만 행을 한 번에 보내면 메모리와 패킷 크기에서 문제가 생기기 때문임. 1,000행씩 나눠 보냄
- `if_exists="replace"`로 둔 이유는 적재 코드를 여러 번 실행해도 데이터가 중복으로 쌓이지 않게 하기 위함임. 운영이라면 `append`를 쓰겠지만 지금은 반복 실험 중이라 덮어쓰기가 맞음
- 매핑한 뒤 눈으로 확인하지 않고 `for`문으로 남은 한글 컬럼이 있는지 검증한 이유는, 55개를 하나씩 보는 것보다 정확하고 빠르기 때문임
- 접속 정보를 `.env`로 뺀 이유는 수업 자료에 `password="1234"`가 코드에 그대로 있었기 때문임. 11월 25일 MySQL 체크포인터 때와 같은 처리임

### 막혔던 부분 · 이해 포인트

- **Workbench에서 `Error Code: 1046. No database selected`가 났음**
  - 노트북에서는 `128053건 저장 성공`이 찍혔는데, MySQL Workbench에서 `select * from seoul_commercial`을 돌리니 1046 에러가 났음
  - Output 창을 보니 실행된 기록이 전부 `select ...`뿐이고, 위에 적어둔 `use langgraph_db;`는 **한 번도 실행되지 않았음**
  - Workbench에서 번개 버튼이나 `Ctrl+Enter`는 **커서가 놓인 문장 하나만** 실행하기 때문임. 커서가 2번 줄에 있어서 SELECT만 세 번 돌린 것이었음
  - MySQL은 "어느 데이터베이스에서 찾을지"를 먼저 정해줘야 테이블 이름만으로 조회할 수 있음
  - 해결 방법이 세 가지였음. 전체 실행(`Ctrl+Shift+Enter`), Navigator에서 DB를 더블클릭해 기본 스키마로 지정, 또는 `langgraph_db.seoul_commercial`처럼 DB 이름을 같이 쓰기
  - 에러 메시지가 아니라 **실행 기록**을 보고 원인을 찾은 경우였음
- **같은 데이터인데 문서가 아니라 테이블이라는 점**
  - 11월 18일 CSV 실습에서는 CSVLoader로 행마다 Document를 만들어 벡터 저장소에 넣었음
  - 이번에는 같은 CSV를 **MySQL 테이블**로 넣었음. 128,053행을 전부 임베딩하면 비용도 크고, "강남에서 매출이 가장 높은 업종"처럼 **집계가 필요한 질문**에는 벡터 검색이 답을 못 함
  - 숫자를 더하고 정렬하는 질문은 SQL이 할 일이고, 의미가 비슷한 문장을 찾는 질문은 벡터 검색이 할 일이라는 구분이 생겼음
- **상태에 커스텀 자료형을 담을 수 있다는 것**
  - `final_report: ReportResult | None = None`처럼, 상태의 한 칸에 또 다른 BaseModel을 통째로 담을 수 있었음
  - 지금까지는 상태에 문자열·불리언·리스트만 넣었는데, 구조화된 출력을 쓰면 **결과 묶음 자체**를 상태에 보관할 수 있음
  - `| None`과 기본값 `None`을 함께 쓴 이유는 보고서가 아직 만들어지기 전 상태를 표현하기 위함임
