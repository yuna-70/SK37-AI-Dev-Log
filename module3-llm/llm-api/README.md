### 개념

- API(Application Programming Interface)는 잘 만들어진 타사의 기능을 가져다 내 애플리케이션에 붙이는 통로임. LLM을 직접 만들지 않고 OpenAI가 만든 것을 호출해서 씀
- API 사용량과 요금의 핵심 단위는 **토큰(Token)**이고, 토큰 1개는 서브워드 1개임
  - 자주 쓰이는 단어는 그 자체로 1토큰, 드문 단어나 신조어는 여러 서브워드로 쪼개짐 (Chatbot → Chat + bot, 먹었다 → 먹 + 었 + 다)
  - 11월 4일에 BPE와 WordPiece로 배웠던 그 서브워드 토큰화가 그대로 요금 단위가 됨
- API 키는 `.env` 파일에 저장해 코드와 분리함
  - `load_dotenv()`가 `.env`의 내용을 환경 변수로 올려줌. 반환값 `True`는 파일을 찾았다는 뜻
  - `OpenAI()`를 인자 없이 호출해도 되는 이유는 환경 변수 `OPENAI_API_KEY`를 자동으로 읽기 때문임
- 호출 방식 두 가지
  - **Chat Completions API**: 채팅(질의응답) 기능. `messages=[{role, content}]`로 전달하고 `response.choices[0].message.content`로 답변을 꺼냄
  - **Responses API**: 웹 검색 같은 도구(tool)를 붙일 수 있음. 시스템 프롬프트는 `instructions=`, 사용자 프롬프트는 `input=`으로 전달하고 `response.output_text`로 바로 꺼냄
- 프롬프트는 역할에 따라 둘로 나뉨
  - **시스템 프롬프트**: AI에게 역할을 부여함 ("너는 경력 10년 이상의 감성 분석 전문가야")
  - **사용자 프롬프트**: 실제 요청 내용
- 효과적인 프롬프트 작성 방법 다섯 가지
  - **구체적인 지시**: "소설을 써줘"가 아니라 "등장인물 3명, 갈등 구조를 가진 로맨스 소설 1000자 내외로 써줘"
  - **역할 부여**: 분야를 구체적으로 지정할수록 답변의 전문성이 올라감
  - **맥락 제시**: 판단에 필요한 배경 정보를 함께 제공
  - **예시 활용**: 원하는 결과물의 형태를 직접 보여줌
  - **반복 및 개선**: 결과를 보고 프롬프트를 고쳐나감
- **스트리밍**은 답변이 다 만들어질 때까지 기다리지 않고 토큰이 생성되는 즉시 받아 처리하는 방식임. 체감 응답 속도가 빨라짐
- API가 돌려주는 JSON은 **문자열**이지 파이썬 dict가 아님. `json.loads()`로 변환해야 키로 값을 꺼낼 수 있음
  - JSON은 큰따옴표만 허용함. 작은따옴표를 쓰면 `JSONDecodeError`가 발생함

### 왜 이렇게 코딩했는가

- `.env` 경로를 변수로 빼고 `load_dotenv()`의 반환값을 출력한 것은, 키를 못 읽었을 때 어디서 틀렸는지 바로 알기 위함임. `False`가 나오면 파일 경로 문제이고, `True`인데 인증 오류가 나면 키 값 자체의 문제임
- `get_completion()`처럼 API 호출을 함수로 감싼 이유는 모델명·시스템 프롬프트·응답 형식이 매번 같기 때문임. 바뀌는 것은 사용자 프롬프트 하나뿐이므로 그것만 매개변수로 받음
- `response_format={"type": "json_object"}`를 지정하면 응답이 JSON 문자열로 고정됨. 프로그램이 이어서 처리해야 하는 결과에는 이 설정이 필요함
- 프롬프트에서 사용할 키 이름을 직접 지정한 이유는 받는 쪽에서 파싱하기 쉽게 하기 위함임. 키 이름을 맡겨두면 호출할 때마다 달라질 수 있음
- 리뷰 텍스트를 triple backticks로 감싼 것은 지시문과 데이터를 구분하기 위함임. 리뷰 안에 "분석해줘" 같은 문장이 들어 있어도 지시로 읽히지 않음
- 스트리밍에서 `if content is not None` 검사가 필요한 이유는 첫 조각에는 역할 정보만, 마지막 조각에는 종료 정보만 담겨 있어 `content`가 비어 있기 때문임
- 스트리밍은 `message`가 아니라 `delta`에서 꺼냄. 완성된 메시지가 아니라 방금 추가된 조각이기 때문임

### 막혔던 부분 · 이해 포인트

- **눈에 보이지 않는 토큰에 요금이 나가고 있었음**
  - `response.usage`를 열어보니 `prompt_tokens=43`, `completion_tokens=1775`, `total_tokens=1818`이었음
  - 그런데 `completion_tokens_details`를 보니 그중 `reasoning_tokens=1536`이었음
  - 실제 답변 텍스트는 1775 - 1536 = **239 토큰**뿐이고, 나머지 **86.5%는 화면에 보이지 않는 추론 과정**임
  - `gpt-5-nano`는 답하기 전에 속으로 생각하는 추론 모델이고, 그 생각도 전부 과금 대상임
  - 보낸 프롬프트는 43토큰인데 과금되는 출력은 1775토큰으로 41배였음. 요금을 추정할 때 입력 길이만 보면 안 됨
- **프롬프트로 "최대 200 토큰"이라고 써도 지켜지지 않았음**
  - 보이는 답변만 세도 239토큰으로 요청을 넘김
  - 프롬프트의 길이 지시는 권유일 뿐 강제력이 없음. 실제로 막으려면 `max_completion_tokens` 매개변수를 써야 함
  - 비용을 통제해야 하는 상황에서 프롬프트에만 의존하면 안 된다는 걸 알게 됨
- **JSON 예시를 보여주려다 파이썬 표현이 나갔음**
  - 감성 분석 (1)에서 `example = {"감성 분석 결과": "긍정"}`처럼 파이썬 dict를 만들어 f-string에 넣었음
  - 출력된 프롬프트를 확인하니 `{'감성 분석 결과': '긍정'}`로 작은따옴표가 됐음. 파이썬이 dict를 문자열로 바꿀 때의 표현이기 때문임
  - JSON은 큰따옴표만 허용하므로, 모델에게 "JSON 예시"라며 JSON이 아닌 것을 보여준 셈임
  - 이번에는 모델이 알아서 큰따옴표로 답했지만, `json.dumps(example, ensure_ascii=False)`로 넘기거나 감성 분석 (2)처럼 문자열로 직접 쓰는 게 정확함
- **같은 리뷰인데 프롬프트에 따라 결과의 깊이가 완전히 달랐음**
  - (1) 간단한 프롬프트 → `{"감성 분석 결과": "긍정"}` 한 줄
  - (2) 출력 형식을 자세히 지정 → 긍정 키워드 3개, 부정 키워드 5개, 최종 판단의 이유까지
  - 긍정과 부정이 섞인 리뷰인데도 (2)는 "편안한 착용감과 만족감이 강하게 나타나 긍정으로 판단"이라고 근거를 설명했음
  - 11월 10일에 HuggingFace 모델로 같은 작업을 했을 때는 `{'label': 'LABEL_1', 'score': 0.99}`가 전부였고, 왜 그렇게 판단했는지는 알 수 없었음
  - 모델을 미세 조정하지 않고 프롬프트만 바꿔서 설명까지 얻을 수 있다는 점이 가장 크게 달라진 부분임
- Responses API에 웹 검색 도구를 붙이니 오늘 날짜의 뉴스를 출처 링크와 함께 가져왔음
  - 학습 데이터에 없는 정보를 답하게 만드는 방법이 이것임
  - 다음 장에서 배울 Agent가 도구를 쓰는 것과 같은 구조로 보임
- `client = OpenAI()`에 아무 인자도 안 넘기는데 동작하는 이유를 처음에는 몰랐음
  - `load_dotenv()`가 `.env`를 읽어 환경 변수로 올려두고, `OpenAI()`가 그 환경 변수를 찾아 쓰는 구조임
  - 코드 어디에도 키가 적혀 있지 않은데 동작하는 것이 핵심이고, 그래서 키가 저장소에 올라가지 않음
